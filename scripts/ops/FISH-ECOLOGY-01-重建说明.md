# FISH-ECOLOGY-01 · 测试鱼群重建

正常服务器启动只进行增量字段迁移，不会清塘。已确认目标测试库并停止服务后，使用下面的显式操作；旧`reset-pond-ecology.ts`已转到同一安全入口，不能再使用默认库直接清塘。

## 检查与执行

先构建并导出本版配置，确认40个正式塘、每塘100条、20个钓位。结算待领取鱼、停止钓鱼会话，等待尚有剩余份数的窝料到期，然后停止该库对应服务。

```bash
npx tsx scripts/ops/rebuild-fish-ecology.ts --db /绝对路径/测试库.sqlite --environment test --dry-run
npx tsx scripts/ops/rebuild-fish-ecology.ts --db /绝对路径/测试库.sqlite --environment test --backup-dir /绝对路径/备份目录 --batch entry-v1-20261104 --apply
```

`--db`和`--backup-dir`必须使用绝对路径。没有`--environment test`和明确执行模式时，工具退出；不会采用`DB_PATH`或项目默认库作为兜底。

工具要求macOS或Linux可运行`lsof`，发现其他进程持有SQLite主文件或WAL/SHM文件时拒绝执行。维护期间创建数据库旁的`.ecology-maintenance.lock`，正常服务启动也会检查该锁。发现待领取鱼、未过期上钩锁、进行中的钓鱼会话或有效窝料时，先由服务完成相应结算，再停服重试；不要手工删除锁定记录绕过检查。

## 保存了什么

在修改表结构和鱼群之前，先生成完整SQLite备份，再复制出可独立打开的恢复校验库。检查`integrity_check`、外键及所有原始表内容摘要，验证复制恢复后的内容与源库一致。备份与恢复校验副本均保留，manifest记录目标路径、批次、规则版本及各表原始列、条数、内容摘要。

单个事务内将旧在塘鱼原始行存入`fish_entity_archive`，原鱼塘状态和钓位权重存入`fish_ecology_state_archive`；再重建活跃鱼群。当前库的玩家资产、背包、相册、帖子、图鉴和其他历史内容都保留，并以原始列内容摘要检查。发生播种失败或历史内容变化时，整个事务回滚，已验证的备份仍保留。

重建结果应为**4000条正式塘鱼，另加新手塘独立配置的1条鱼**。所有新鱼使用新ID和新规则：幼鱼基准3.4～4.6厘米、品质上限独立±15%、入塘日期位于开服前14～0天；不会伪造摄食和脱钩事件。新规则的旧`born_at`列仅用0占位，`birth_size_m`为NULL，真正的时间和尺寸保存于明确的入塘字段。

同一批次成功后再次执行只返回原完成结果，不会再次清塘或重复播种。恢复测试必须对输出的`restoredCopyPath`或其副本进行，不能为了检查备份而覆盖仍在使用的数据库。
