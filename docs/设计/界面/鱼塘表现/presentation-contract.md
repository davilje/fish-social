# H / I 共用表现事件与验收基线

H/I方案 v2，2026-10-24。以下字段是拟接入契约；现有 snapshot `sequence` 仅表示传输顺序，不能充当鱼获或动作身份。

## 1. 已知基线与所有权

- Unity `OwnFishingPresenter` 管自己预测与权威阶段协调；WPF `OverlayPetActor` 管真实显示帧，`OverlayFishingLayers` 已有源帧与补帧映射。不能用扩展后帧序号作为稳定触发点。
- 音频继续由 Unity `DesktopAudioService` 独占播放；WPF 发送自己的语义标记，不另开音频设备。Unity 兜底鱼塘视图与原生 Overlay 二选一为当前表现发起者，避免双播。
- `catchId`、失败 `resultId` 已出现在当前服务端／Unity DTO；开发前核验 ACK、结算、自动回鱼、IPC 是否传递同一值。缺链补链，不能并行制造第二套结果 ID。
- 当前工作区有钓鱼睡眠等并行改动。H/I 只消费已发布事件；睡眠导致真实逃脱仅由I按原动作接触决定音效，H不生成脱钩特效，不能仅看 `fishingAsleep` 自己合成咬钩或结果。

## 2. 事件信封（设计）

| 字段 | 来源／用途 |
|---|---|
| presentationSessionId | Unity 每次进入新的鱼塘会话生成；断线重连建立新播放 epoch 并重新设静默基线；旧会话消息丢弃 |
| actorId / pondId / spotId | 权威角色和鱼塘身份；spot 用于校验，不把坐标当身份 |
| actionId | 抛竿／打窝等一次动作身份；本地 commandId 必须带进程／会话前缀，权威追认映射为同一动作 |
| eventId | I的结果声音复用 catchId/resultId，H不订阅收获确认／脱钩／收线事件；咬钩优先用权威阶段修订 ID。缺少稳定 ID 时先补协议，不以时间窗口、鱼尺寸或阶段字符串代替 |
| marker / occurrence | 共用float.contact、bite.onset、groundbait.contact；H的fish.surface/fish.slap限hooked/effort；cast.release、retrieve.start、result.presented供I独立消费，不据此增加H特效；循环occurrence单调递增 |
| waterSizeTier / variant | H/I共用S/M/L/XL，来源与未知降级见H；同一事件稳定选样，不因快照重抽；浮漂／窝料用自己的物体规格 |
| source | prediction / authoritative / snapshot；快照默认仅恢复状态，不发一次性特效或声音 |
| ownerEpoch / actorGeneration | 当前表现端与角色实例版本；皮肤替换、取消、重建后的迟到完成回调失效 |
| elapsedMs / validityMs | 同一进程内单调时钟的延迟预算；跨 IPC 不直接比较两个进程的 Stopwatch 值 |

去重键为 `(presentationSessionId, actorId, actionId或eventId, marker, occurrence)`。视觉和声音分别记消费位，同一派发事件不会被视觉先消费而吞掉声音。每会话保留最多 512 个已消费键；权威结果另保留本会话有界结果集合，切换 epoch 以静默基线防止旧结果补播。若超过上限，淘汰过期动作，不能淘汰仍可能重发的当前轮次；需要重播日志的消息携带 snapshot 标识。

预测只有挥竿／按下等可撤销表现；咬钩、鱼获、逃脱必须是权威事件。追认复用动作键。预测失败停止未触发标记，已发出的短声不逆放；不补成功声音；H没有成功确认特效。

## 3. 标记派发与延迟

1. 动画定义按**源片段＋源时间**标记；H/I 不各自写一套 `delay(600)`。浮漂入水／发力破水以水面求解器的接触关系和对应源标记双重校验。
2. WPF 当对应九层图片完整发布时派发当前可见标记；发力和打窝的插值帧跨过标记也只触发一次。
3. 冷加载等待真实发布，0／150／400ms 三档必须对齐。某帧跳过时不补播历史挥竿／水花；咬钩仍有效时，在首次可见 hooked 帧做一次起始反馈，再按真实剩余期限显示读条。
4. WPF 发给 Unity 的音频标记由 Unity 收到后立即仲裁；目标实机画声差 ≤80ms，>120ms 记诊断。该数值为设计验收目标；未量测前不承诺已达成。已过阶段／超过 250ms 待执行队列的普通 cue 丢弃。
5. 离席、停钓、换塘、断连和退出清理对应动作；音效 40–80ms 淡出，特效最多 100ms 淡出，读条仍由原逻辑立即清理。取消状态比迟到 marker 优先。
6. 隐藏或移出视口暂停视觉、不积压粒子。恢复只重建当前等待／挣扎低频持续效果，不回放过期一次性效果。有效新咬钩可走 I 的后台提示策略：完全隐藏时 Unity 可用同一事件键发一次提示，不等可见帧；恢复可见时仅恢复视觉，不再发同一声音。

## 4. 性能与测量口径

参数为新增表现的预算，不能把未实测目标写成现有指标：

| 项目 | 目标与验证 |
|---|---|
| 活跃对象 | H同屏最多24实例／8组，自己关键动作预留2组／12实例；四档形态共享池，详情见H |
| 新增资源 | H 解码后 ≤4MiB；新增短音解码后 ≤4MiB；地图 GPU 预算单独见 J |
| 调度 | 共用现有时钟；无效果时零活跃订阅；禁止逐粒子 DispatcherTimer、每帧创建控件或磁盘读写 |
| CPU | 20 人同塘 A/B，新增 H/I 主线程耗时 p95 ≤1ms／帧、p99 ≤2ms；记录硬件、窗口、DPI、构建版本 |
| 长稳 | 预热后 30 次进出塘＋10 分钟循环，池内对象、订阅、待发事件返回基线；不能用单次 GC 后内存推断无泄漏 |
| 画声 | 用实机 60fps 录屏＋系统回环音频测边界，报告采样数量、p50／p95／最大差值，至少 30 次各关键动作 |

效果质量可降为「简化」；优先移除其他玩家波纹和装饰，保留自己的咬钩水面提示与鱼大小区别；结果沿用角色原动作，H不加结果特效。视觉仍提供非颜色标识，声音不能是唯一提示。

## 5. 共用回归矩阵

| 场景 | 期望 |
|---|---|
| 首次快照即 waiting / hooked / catch | 恢复当前姿势／读条；不补旧挥竿、咬钩音或庆祝 |
| 预测＋追认、重复包、ACK＋结算 | 相同事件各发一次；两个不同真实鱼获的I声音各一次；H的收获／脱钩／收线特效始终为零 |
| 打窝 0.2s／3s／30s，结束前后重复快照 | 撒饵持续但限频，真实结束后无补发 |
| 冷解码、后台、切塘、退出、快速重入 | 旧 epoch／旧 actor 的迟到标记失效，无残留声／光 |
| S/M/L/XL和未知尺寸 | H/I档位一致，形态／水声不只缩放变调；未知尺寸不取未来入包结果重播 |
| 1／8／20 人同时咬钩 | 他人自动声音为零，视觉总量不超限，自己的关键反馈保留 |
| 开关简化／关闭、音量归零、重复调滑杆 | 当前效果及时收敛；静音不改变事件去重；调回音量不补历史音 |
| 失去水面锚点／缺素材／IPC 旧版本 | 不凭空定位、不崩溃；低成本原地提示或静默降级，并记录一次诊断 |

诊断采用开发日志／测试计数器，不新增生产埋点或修改 `fishing_metrics`；如后续决定做业务埋点，另走埋点目录同步。
