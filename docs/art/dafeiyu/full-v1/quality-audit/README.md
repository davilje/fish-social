# 大肥鱼尺寸跳变与清晰度排查

2026-10-20。检查了 44 张独立姿势、63 个源帧映射、原始生成图、导入和对齐脚本，以及网页和 Unity 的显示链路。本次新增诊断资料，生产素材未替换。

[图像对照页](index.html) · [逐稿数据](measurements.json) · [浏览器尺寸实测](browser-measurements.json)

## 结论

尺寸变化已烘焙进最终 PNG。主要原因是原稿比例缺少统一约束，又以每帧手与脚底的距离反算整个人物缩放；六张旧关键姿势和 38 张新增稿使用不同的对齐规则。清晰度问题来自有限的角色有效像素、多次重采样以及高像素密度显示时的放大。

## 尺寸的证据

`../build.mjs:44` 对新增持物姿势采用：

```text
整图缩放 = (450 − 猫咪模板双手平均高度) / (人物最下方像素 − 人物双手平均高度)
```

这会把手臂升降和手臂/躯干比例差异转成全身缩放。当前参数最小为 `reset_catch-02` 的 0.6708，最大为 `reset_empty-01` 的 1.0574，系数之比 1.5763；这个比值是处理参数之比，并不表示两帧实际身高必然相差 57.6%。

站坐前三帧另用 `87 / 脸部肤色区域宽度` 校准。六张复用关键姿势则直接保留 `scale = 1`，三套规则混在同一动作序列中。站坐的 87px 基准也与准备旧稿约 82px 的肤色区域宽度不一致。

原稿也不统一：导入稿的脸部肤色连通区域宽度为 82～118px，最终稿为 69～107px。该检测区域受表情、转头、刘海及连通性影响，只能用于发现异常；不能当作精确的头骨尺寸或直接作为统一缩放的依据。

在同画布、同脚底线的图像对照中，可以看到头饰、脸和裙身一起明显放大/缩小。因此这些变化不只是表情或姿势造成的投影差异。原猫咪模板应约束动作时序与握点，而人形角色需要自己的固定体型和肢体长度。

握点处理也未完全解决接触：`catch-01` 最终前后手与模板中心的误差约为 18.8/19.4px。整身相似变换无法同时消除头身比例、双手间距与脚底位置的不同。

## 显示端排除与清晰度链路

浏览器实测采用 1440×1080、DPR=2。六个代表帧的图层始终是 `680×544 CSS px`，原图均为 `640×512`，`transform: none`。固定视口下没有逐帧改变 CSS 宽高；每源像素对应 2.125 个设备像素，放大显示会暴露素材分辨率不足。

新增 19 组双帧原图及其返修稿实际均为 **1983×793**，并非提示中要求的 2560×1024。导入脚本第19～23行先放大整张到 2560×1024，再逐格降到 640×512；对齐脚本又执行一次逐稿缩放。人物只占画布一部分，最终脸部有效宽度约 69～107px，细发丝、眼睛高光、女仆头饰和裙边装饰容易丢失。

网页直接读取 640×512 分层图；**320×256 条带用于另一条客户端输出链路，并非当前网页模糊的直接来源**。Unity 的 `FishingLayerArt.LoadSprite` 读取 640×512 PNG 后还调用 `Scale`，用 `GetPixelBilinear` 生成显示大小的纹理，再设为 Bilinear。该路径可能继续软化细线，但此次没有量化 Unity 实际窗口的额外清晰度损失。

拆层代码逐像素拷贝，已验证分区合回与角色图一致；PNG 为无损格式。拆层与 PNG 编码不是本次重采样模糊的主要来源。分层遮挡边界是否自然属于另一个需要目视验收的问题。

## 修复顺序

1. 建立大肥鱼独立比例基准：头颅、肩宽、躯干长度、骨盆/落座点及脚底，不用头发、鲸尾、举手后的包围盒推算体型。所有六张旧关键姿势也纳入同一标准。
2. 先重做准备、展示收获和复位这组高风险姿势，固定头身尺度后调整/重绘手臂，让握点对上现有鱼竿与鱼。随后逐动作修正其余帧，保持自然的转身、后仰和蹲坐变化。直接统一 `scale=1` 仍会留下原稿差异及接触错位。
3. 保留单帧高分辨率主稿；至少准备 2×逻辑尺寸的有效细节，避免以空画布尺寸充当人物分辨率。原图裁切、校准和最终输出合并为一次重采样，不经过“先放大、再缩小、再次缩放”的链路。放大当前低分辨率 PNG 不能恢复细节。
4. 逻辑坐标仍可为 640×512，纹理支持独立的 2×分辨率。Unity 当前会拒绝非640×512图片，需要同时调整加载验证与纹理/逻辑尺寸映射，不能只换大图。移动条带按目标显示尺寸另导出，避免影响已有猫咪素材契约。
5. 加入相邻帧视觉检查：同尺度叠影、稳定头颅/躯干标记、手与道具接触、完整动作循环和动作衔接。按实际显示分辨率检查眼睛、描边和头饰，不以资源数量或分层像素一致代替美术一致性。

此前的通过记录验证的是资源完整、层级拷贝和加载/播放流程，未验证体型连续性及原稿有效分辨率。这是原验证范围遗漏，不能作为动画视觉质量通过的依据。
