## 1. 背景

1.3 已做到：玩家一览、表格化、入口精简。页签仍偏碎：

| 痛点 | 表现 |
|------|------|
| Timeline 与 Live 重复 | Live 已有「最近关键事件」，与 Timeline 历史高度重叠，要切两个页签 |
| Fishing Debug 孤立 | 看塘内钓位概率 / 鱼状态却不在「鱼塘」语境里 |
| 玩家列表缺位置 | 看不到人所在塘、钓位，排障要再点进详情 |
| ID 英文 | `pond-calm` / `calm-spot-2` 对策划不友好 |
| 业务健康 | 日表适合明细，**跨天趋势更适合折线** |
| 服务探活重复 | 「今日运维」已有服务摘要，下方仍叠一套 health/ready 明细 + 原始 JSON |

**北极星**：Admin 页签收敛为 **玩家 · 玩家详情（史+实时）· 鱼塘（含 Debug）· 业务健康（折线）**；位置信息一律中文名；运营入口去掉重复探活区，服务摘要收进今日运维且字段精简。

---

## 2. 目标信息架构

```text
Admin（连接后）
├── 玩家          ← 一览表（默认）；含塘/钓位中文名
├── 玩家详情      ← 原 Timeline + Live 合并（按 playerId）
├── 鱼塘          ← 原鱼塘概览 + Fishing Debug 合并
└── 业务健康      ← 汇总卡 + 折线图（+ 可选日表明细折叠）
```

| 旧 tab | 新归宿 |
|--------|--------|
| `players` | 保留，增强列 |
| `timeline` + `live` | 合并为 **`player`（玩家详情）**；旧 query `tab=timeline` / `tab=live` **兼容重定向**到新 tab |
| `ponds` + `debug` | 合并为 **`ponds`（鱼塘）**；`tab=debug` 兼容打开鱼塘并聚焦 Debug 区 |
| `health` | 保留，图表化 |

深链兼容（必须）：

| 旧 URL | 行为 |
|--------|------|
| `?tab=timeline&playerId=` | → `?tab=player&playerId=`（可默认停在「历史」子区） |
| `?tab=live&playerId=` | → `?tab=player&playerId=`（可默认停在「实时」或同页自动连 SSE） |
| `?tab=debug&pondId=` | → `?tab=ponds&pondId=`（展开/滚到钓位概率区） |

## 3. 功能需求

### 3.1 A — 合并「玩家 Timeline」+「Live Inspector」→「玩家详情」

#### 布局（单页）

```text
玩家详情
├── 顶栏：playerId 输入 · 查询 · （从玩家表点入时预填）
├── §实时状态（原 Live）
│   ├── 相位 / 本局时长 / fishingStartedAt / 塘·钓位（中文）
│   ├── 连接 SSE「开始盯梢 / 停止」
│   └── 塘内真人/机器人计数（若有）
├── §近窗摘要卡（原 Timeline summary 表格化，已有则复用）
└── §事件流（统一一张表）
    ├── 模式：实时最近 N 条（SSE 推） | 历史查询（hours，默认 24）
    └── 列：时间 · 事件（中文）· 塘（中文）· 摘要；禁 JSON 墙
```

#### 规则

1. **一个 playerId 一条工作流**：查人 → 上看实时 → 下看事件；不必切页。  
2. 进入页时若带 `playerId`：拉 live-state + 可选自动 SSE；并拉 timeline。  
3. 事件表：历史与实时可同表（实时插入顶部）或 Tab「历史 | 实时」——实现二选一，**推荐同表 + 来源标记**（live / history）。  
4. 删除独立顶栏入口「玩家 Timeline」「Live Inspector」；玩家一览操作列改为「详情」一键。

#### 验收 A

- [ ] Admin 顶栏不再同时出现 Timeline 与 Live 两个页签  
- [ ] 玩家详情同时具备实时卡片与事件表  
- [ ] 旧 `tab=timeline|live` 深链仍可用（重定向）  
- [ ] 无大块 JSON 主展示  

---

### 3.2 B — 合并「Fishing Debug」→「鱼塘」概览

#### 布局

```text
鱼塘
├── 塘列表/选择（中文名：静心湖 / 云雾塘 / 夕阳湾 / 竹林池）
├── §概览卡：鱼数 · 上限 · 真人 · 机器人 · 人口率
├── §钓位概率（原 Debug 钓位表）
│   └── 钓位中文名 · 鱼数 · 关键展示概率/权重（见下）
├── §鱼列表（塘内各鱼状态）
│   └── 品质 · 体长 · 钓点（中文）· 咬钩相关只读字段
└── §在钓玩家（原 activeFishers，可折叠）
```

#### 概率展示说明（产品约束）

当前 Debug 每次刷新会重抽「代表鱼」导致数字跳（见既有实现）。本需求要求：

- **默认展示**：钓位汇总指标（如 spot 权重、鱼数量、期望/区间）或**缓存快照**，避免无意义的每次重抽跳动；或明确标注「单次抽样，仅供参考」。  
- 推荐：主列用稳定量（`spotMultiplier`、鱼数、品质结构）；`pBite` 抽样列标「抽样」且提供「再抽样」按钮，**禁止**每次打开页都强制 `refresh=1` 无说明。

#### 验收 B

- [ ] 无独立 Fishing Debug 页签  
- [ ] 鱼塘页可选塘后看到钓位表 + 鱼状态  
- [ ] 塘名、钓位名为中文  
- [ ] `tab=debug` 深链仍落到鱼塘 Debug 区

### 3.3 C — 玩家一览增加塘 / 钓位（中文）

在 **玩家** 表增加列（1.3 已有时长/钓获/断线等则保留）：

| 列 | 内容 |
|----|------|
| 鱼塘 | 中文名，如「静心湖」；无则 — |
| 钓位 | 中文名，如「静心湖·2 号位」或配置名；无则 — |

数据来源：内存态优先（在塘用户的 `pondId`/`spotId`）；仅历史活跃不在塘则塘/位可空或「最近：xxx」（若 API 易得；否则 MVP 仅在塘显示）。

`GET /api/admin/players/overview` 响应增加：

- `pondId` / `spotId`（机器 ID，可选留给调试）  
- `pondName` / `spotName`（**中文展示用，必填当有 ID 时**）

中文名解析：复用 `shared/ponds.ts` 的 `name`（静心湖等）；钓位若配置无独立中文名，则规范为 **`{塘短名}·{序号}号位`**（由 spotId 解析序号），全站 Admin 统一。

#### 验收 C

- [ ] 玩家表可见中文塘、钓位  
- [ ] 不展示裸 `pond-calm` 作为主文案（可 title 悬停显示 ID）

### 3.4 D — 业务健康改为折线图

#### 展示

1. **汇总卡**（总数/均值，沿用 1.3 表格化 totals）。  
2. **主图**：折线图，X = 日期，Y = 可选指标（多选或多轴）：  
   - 默认：日钓获、断线率（断线率可用右轴或独立图）  
   - 可选叠加：分塘人口均值等（若序列已有）  
3. **天数**：保持 1–30（或现有上限），切换天数重拉并重绘。  
4. **明细表**：可保留在折线下方，**默认折叠**。

技术：admin-web 可用轻量 Chart.js / 现有依赖；勿引入过重 BI 框架。

#### 验收 D

- [ ] 改天数后折线随之变化  
- [ ] 主视觉是折线而非仅表格  
- [ ] 无 JSON 墙  

---

### 3.5 E — 运营平台：删除「服务探活」区；服务摘要收进「今日运维」并精简

现状：`运营平台.html` 在 Admin 内嵌下方有折叠区 **「服务探活（原始字段）」**，重复展示 `/health`（状态/已运行/版本）与 `/ready`（状态/DB/队列/RSS/真人/机器人）及「打开原始 JSON」。

#### 删除（仅删重复探活区）

- 整块「服务探活（原始字段）」`<details>`（含 health/ready 明细卡与原始 JSON 链接）  
- 页面上不再主推 `/health`、`/ready` 原始 JSON 入口（工程师仍可直接 curl；不必在入口页保留）

#### 「今日运维」整体：原有能力全部保留

以下 **不得删除 / 不得挪出今日运维**：

- KPI：日钓获 · 活跃玩家 · 断线次数  
- 告警（T-1）  
- 日批任务状态  
- 昨日运营日报 CTA、「刷新状态」  
- （若有）报告缺失提示等现有降级文案  

本条 **只改「服务」这一块的展示内容**，不是把今日运维改成只剩服务字段。

#### 「服务」块：从探活明细收进来的字段（精简后）

| 展示 | 口径 | 数据来源 |
|------|------|----------|
| 状态 | **运行中** / 异常·停机·无响应（推荐「运行中」= health+ready 正常） | `/health` + `/ready` |
| 内存 RSS | 如 `69 MB` | `/ready` → `memoryMb.rss` |
| 当前真人 | 在塘人数 | `/ready` → `humanInPond` |
| 当前机器人 | 在塘人数 | `/ready` → `botInPondCount` |

相对现状今日条里的服务摘要：可去掉入口页上的 **uptime 秒数、版本号、DB、埋点队列**（这些只存在于探活明细时也不再展示）；改为明确露出 **RSS + 机器人**（真人若已有则保留）。

布局建议：今日条 meta 区在 **告警 / 日批** 旁保留服务相关格：**状态 · 内存 RSS · 真人 · 机器人**。

#### 验收 E

- [ ] 入口页无「服务探活」折叠区、无 health/ready 原始 JSON 主链  
- [ ] 今日运维仍有 KPI / 告警 / 日批 / 昨日日报 CTA  
- [ ] 今日运维服务块可见：运行状态、内存 RSS、真人在塘、机器人在塘  
- [ ] `verify:ops-portal-links` 同步：不再要求「服务探活」明细；断言今日运维关键结构仍在，并覆盖 RSS/真人/机器人
