## 1. 背景与目标

### 1.1 背景

「热更」常被混用。项目已有 **C1 数值配置热更**（Admin 批准 → `game_config` → 运行时生效），但缺少书面约定：何时不停服、何时短停服、客户端 OTA 何时做。

### 1.2 目标

- 书面拆分三类更新，并给出决策矩阵  
- 产出单机阶段 **不停服** / **停服** runbook（可给运营执行）  
- 明确客户端 OTA、多机滚动发布的**触发条件**（打包前 / 千人阶段），本迭代不实现  

### 1.3 非目标

- 接入 Expo Updates / CodePush / Unity 热更 CDN  
- 多机负载均衡滚动发布（归 BE-OPT-E / S4）  
- 改咬钩公式或扩 FEAT-05 全量玩法  
- 替代 C1：不重做 Admin 双人批准，只对齐边界与文档入口  

---

## 2. 三类更新（权威分类）

| 类型 | 含义 | 现状 | 本需求动作 |
|------|------|------|------------|
| **A. 配置热更** | 改 `game_config` 等，进程不换包 | C1 已有能力 | 文档写清适用范围、审批、回滚；运营入口链到 Admin |
| **B. 服务端发版** | 换 Node 代码 / DB 迁移 | 单机 SQLite | 写不停服边界 + **短停服**标准流程 |
| **C. 客户端热更（OTA）** | 不经商店更新 JS/资源 | 未做 | **原则预留**；商店打包前再单独立项实现 |

---

## 3. 决策矩阵

| 变更类型 | 推荐通道 | 说明 |
|----------|----------|------|
| 咬钩/生态数值、开关类 KV | **A 不停服** | C1；双人批准；可回滚上一版 |
| 兼容性 API/Socket 小改（旧客户端仍可用） | **B 尽量短窗或热替换** | 单机可接受分钟级重启；先发后兼容 |
| 破坏性协议 / 必改事件名或主 DTO | **B 停服** + 升 `protocolVersion` | 对齐 UNITY-P0 纪律 |
| SQLite 破坏性迁移、清库、不可逆数据手术 | **B 停服** | 备份 → 迁移 → 冒烟 |
| 纯客户端 UI/场景（协议不变） | 内测整包重装；上架后走 **C**（另立） | 本需求不实现 C |
| 多机无感滚动 | 千人阶段 | BE-OPT-E；本需求只点名依赖 |

**单机阶段务实目标**：配置真正不停服；进程发版接受**短停服（分钟级）**；不承诺多机零停机。

## 4. 功能范围（本迭代交付）

### 4.1 必交付文档

写入 `docs/planning/architecture/发版与热更-单机Runbook.md`（或同级路径，spec 变更记录附最终链接）：

1. **分类与矩阵**（可复用本 spec §2–§3）  
2. **不停服（配置）步骤**：Admin 提交 → 批准 → refresh → 核对 A2/生效值 → 异常回滚  
3. **停服发版步骤**：公告/踢人（若有）→ 停服 → DB 备份 → 部署/迁移 → `verify:server-boot` 或等价冒烟 → 开门 → 观察 `/health` 与关键日志  
4. **回滚**：配置回滚 vs 二进制/镜像回滚各自入口  
5. **OTA 触发条件**：正式客户端形态确定且接近商店打包时，另开 `OPS-RELEASE-OTA`（名称可调）  

### 4.2 可选（不阻塞验收）

- 运营平台「发版/热更」说明区链到上述文档  
- 检查清单 Markdown 可打印一页纸  

### 4.3 与现系统对齐

| 能力 | 路径提示 |
|------|----------|
| 配置热更 | Admin 参数面板 · `/api/admin/config/*` · `gameConfig.ts` |
| 健康检查 | `/health` |
| 协议版本 | UNITY-P0 / 契约清单中的 `protocolVersion` 约定 |
