## 1. 背景与目标

### 1.1 现状问题

FISH-BOT-1 之后：启动 `tickSpawn` **while 补满**（默认每塘 20）+ `scheduleRuntimeInterval` **立刻**跑一轮开钓 → 重启瞬间满塘、很快「全员在钓」，与早期「陆陆续续进、陆陆续续走」不符。

### 1.2 目标

1. **启动**：每塘仅 **3～6** 名 bot（可配），不要一次坐满  
2. **初始已钓时长随机**：这些人看起来「已经钓了一会儿」，不是全员从 0 秒齐刷  
3. **后续**：按随机节奏 **一次最多补 1 人**，可一直补到 **满塘**（`MAX_BOTS_PER_POND`），并保持随机离塘后再慢慢补  

### 1.3 非目标

- 不改 100 账号池 / 昵称池  
- 不改真人踢 bot、咬钩公式  
- 不强制改运营看板口径  
- **不做**「日常永久锁软上限、永远不满塘」——满塘是允许的终态

## 2. 参数建议（可用 `game_config` / 常量，名称可微调）

| 键 | 建议默认 | 说明 |
|----|----------|------|
| `BOT_BOOT_MIN` | `3` | 启动每塘最少 bot |
| `BOT_BOOT_MAX` | `6` | 启动每塘最多 bot（含） |
| `MAX_BOTS_PER_POND` | 保持 `20`（= 塘容量） | **补人硬上限**；后续随机补人可达到此值（满塘） |
| `BOT_SPAWN_CHECK_MS` | `45000`～`90000` | 补人检查间隔 |
| `BOT_SPAWN_CHANCE` | `0.35` | 每次检查、每个未满塘：尝试补 **1** 人的概率 |
| `BOT_BOOT_FISHING_RATIO` | `0.75` | 启动进塘者中，直接进入钓鱼态的比例 |
| `BOT_BOOT_ELAPSED_MIN_MS` | `5 * 60 * 1000` | 已钓时长下限（5 分钟） |
| `BOT_BOOT_ELAPSED_MAX_MS` | `75 * 60 * 1000` | 已钓时长上限（75 分钟） |
| `BOT_JOIN_FISHING_CHANCE` | `0.4` | **后续**新进塘 bot：进塘后立刻开钓的概率（其余 idle，沿用原 `BOT_START_FISHING_CHANCE` 慢慢开钓） |
| `BOT_MIN/MAX_STAY_MS` | 维持 1～3h 或略缩到 40min～2h | 离塘仍随机；略缩短则进出更明显 |

> 已取消 `BOT_SOFT_CAP`。稀疏感只靠 **启动 3～6 + 每次只 +1 + 概率**；终态允许满员。

## 3. 启动算法（Boot）

对每个 `pond ∈ PONDS`：

```text
N = uniform_int(BOT_BOOT_MIN, BOT_BOOT_MAX)   // 例：3~6
N = min(N, 空位, 池空闲数, MAX_BOTS_PER_POND)

重复 N 次:
  bot = enterPondFromPool(pondId)   // 已有：抽空闲池号 + leaveAt 随机
  若失败则 break

  若 random() < BOT_BOOT_FISHING_RATIO:
      占钓点 + waiting（复用 startBotFishing / initBotFishingPhase）
      elapsed = uniform(BOT_BOOT_ELAPSED_MIN_MS, BOT_BOOT_ELAPSED_MAX_MS)
      // 关键：让 session / 今日展示「已经钓了 elapsed」
      fishingStartedAt = now - elapsed
      （可选）todayFishingMs 底数 += uniform(0, elapsed) 的一部分，或仅靠 backdate startedAt
  否则:
      保持 idle，时长为 0；之后靠 tickBots 慢慢开钓
```

### 3.1 「已钓鱼时长」实现要点

| 字段 | 做法 |
|------|------|
| `sessionFishingMs` | 钓鱼中 = `now - fishingStartedAt` → **把 `fishingStartedAt` 往回拨**即可 |
| `todayFishingMs` | 展示用：`enrich` 会算 `todayFishingMs + (now - fishingStartedAt)`；backdate 后侧栏今日也会变大。若担心写库虚高，**仅 backdate 内存 `fishingStartedAt`，不要 `addTodayFishingMs` 一次性灌库**，停钓再按真实墙钟结算 |
| 相位 | 仍 `waiting` + 正常 bite tick；**不要**伪造 hook 中途态（避免状态机半截） |

**禁止**：启动 while 补到 `MAX_BOTS_PER_POND`。

**禁止依赖**：启动后立刻那一轮 `tickBots` 用 28% 骰子「假装大家已经钓很久」——时长必须显式 backdate。

### 3.2 启动后第一轮 `tickBots`

- 已 fishing 的 bot：走 bite / 停钓逻辑，**不要**再当 idle 开钓  
- 可选：Boot 后 **延迟 30～60s** 再开始 `tickBots`，或 Boot 本周期跳过「idle→开钓」，减少「刚进又齐刷抛竿」

## 4. 后续随机补人算法（Steady）

每 `BOT_SPAWN_CHECK_MS` 对每个塘：

```text
bots = 当前塘 bot 数
humans = 当前塘真人数
if bots + humans >= MAX_POND_USERS: skip          // 物理满员
if bots >= MAX_BOTS_PER_POND: skip                // bot 硬上限（可与塘容量相同 → 允许满塘）

if random() >= BOT_SPAWN_CHANCE: skip             // 本周期本塘不来人

bot = enterPondFromPool(pondId)                   // 仅 1 个，禁止 while 一次补满
emit pond_user_joined

if random() < BOT_JOIN_FISHING_CHANCE:
    start fishing + 可选短 backdate（如 0～10min，避免新人时长过大）
else:
    idle，等待 tickBots 的 BOT_START_FISHING_CHANCE
```

**要点**：允许最终 `bots → MAX_BOTS_PER_POND`（满塘）；禁止的是「一次 tick 内 while 补满」，不是「永远不满」。

### 4.1 与离塘的配合

- 到期 `leaveAt` → 离塘回池（已有）  
- 真人进塘踢 bot（已有）  
- 满塘后：有人离开 → 下一轮再按概率 +1，重新爬向满塘 → **慢进快满、到期再空一档**  

### 4.2 期望观感（默认参数粗算）

| 时刻 | 观感 |
|------|------|
| T=0 重启 | 每塘约 3～6 人；大半已在钓，时长各不相同（5～75 分） |
| 随后 1～数小时 | 偶尔 +1，人数缓慢爬升，**可以爬到满塘（~20）** |
| 满塘后 | 到期离开腾位，再随机补回 → 在满塘附近起伏 |

## 6. 验收

- [x] 冷启动后抽查：每塘 bot 数 ∈ **[3,6]**（池枯竭/配置另论）  
- [x] 启动瞬间 **不会** 出现每塘 ≈20 bot  
- [x] 启动时已在钓的 bot：`sessionFishingMs`（或侧栏时长）**彼此不同**，且大致落在配置的 min～max  
- [x] 之后短时间内：补人是「偶发 +1」，不是整塘一次刷满  
- [x] 长时间运行（或压测加速 tick）：无真人干扰时 bot **可以**补到 `MAX_BOTS_PER_POND`（满塘）  
- [x] 真人进塘仍可踢 bot；池仍 100、不新建 UUID  
- [x] `verify:fish-bot-pool` 调整或新增 `verify:fish-bot-spawn-pace`

## 7. 风险

| 风险 | 缓解 |
|------|------|
| backdate 导致今日时长写库虚高 | 停钓结算用真实 elapsed；Boot 不预写 `daily_fishing` |
| 补满过慢 / 过快 | 调 `BOT_SPAWN_CHANCE`、`BOT_SPAWN_CHECK_MS` |
| 与 FISH-BOT-1「可填满」 | **一致**：仍可满塘；差别只在「慢补」vs「启动瞬间满」 |
