## 1. 背景与目标

`FEAT-SPOT-02` 已为 activity 线索预留 **`activitySignal`** 六档，但 v1 坐席抽选**忽略**该字段，仅在 tag 交集内随机。

本票：当钓位鱼群数量、近期咬钩/受惊、迁徙状态变化时，**动态**倾向展示与当前状况一致的 activity 文案（仍不暴露 bite 率、条数等精确数值）。

### 非目标

- 正式 UI 展示「本点 N 条鱼」
- 标签影响咬钩/出鱼（仍仅影响线索）
- 重写 `FEAT-SPOT-01` 气泡样式

---

## 2. 输入信号（服务端权威）

| 信号 | 来源 | 说明 |
|------|------|------|
| `spotFishCount` | `pond_fish` where `spot_id` | 当前钓位未锁定鱼实体数 |
| `spotFishRatio` | count / 塘 `maxPopulation` 或分位 | 相对密度 |
| `recentBiteMs` | 该点最近一次咬钩/中鱼时间 | 活性 |
| `recentDisturbMs` | 受惊、多人落座、巡警等 | disturbed |
| `migrationPhase` | 生态 tick 迁徙窗口 | 可选：刚迁入/迁出 |

具体阈值入 **`fishing_formula_constants`** 或新 sheet `spot_clue_tier_rules`（实现时定）。

---

## 3. `computedTier` 算法（定稿方向）

输出与 `activitySignal` 对齐（activity 行）：  
`active_high` | `active_mid` | `active_low` | `inactive` | `disturbed`

示意（实现可调参）：

```
if recentDisturb within T_dist → disturbed
else if spotFishCount == 0 → inactive
else if spotFishRatio >= R_high OR recentBite within T_bite → active_high
else if spotFishRatio >= R_mid → active_mid
else if spotFishCount > 0 → active_low
else → inactive
```

**habitat** 线索：仍 50% 与 activity 混合；**不参与** tier 匹配。

**降级**：当前 tier 无可用文案时 → 相邻档（high→mid→low→inactive）→ 最后才全 activity 池。

## 4. 运行时改造

| 层 | 改动 |
|----|------|
| **server** | 进塘/坐席/定时推送 `spotClueTier`（或随 fishing state 广播） |
| **shared** | `filterSpotCluePool(..., activityTier)` 已预留；补 tier 计算纯函数 + 单测 |
| **Unity** | `SpotObservationController` 读 tier 再抽 activity；habitat 逻辑不变 |
| **verify** | 扩展 `verify-feat-spot-01` 或新增 `verify-feat-spot-05` |

坐席时若仅有 IPC 单向：Unity 本地可先用服务端下发的 tier；离线/新手关仍随机（与 SPOT-01 一致）。

## 5. 验收标准

- [ ] 鱼量为 0 的钓位，activity 线索 **倾向** `inactive`（抽选权重或硬过滤可配置）
- [ ] 刚咬钩/高密度点 **倾向** `active_high` / `active_mid`
- [ ] 受惊后短时 **倾向** `disturbed`
- [ ] habitat 文案仍随机，且不泄露数值
- [ ] 不破坏 `verify:feat-spot-01` 静态表校验
- [ ] 埋点（可选）：`spot_clue_shown` 带 `clueId`、`activitySignal`、`computedTier`
