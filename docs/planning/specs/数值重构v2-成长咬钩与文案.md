## 1. 背景与目标

### 1.1 变更动机

| 现状（A0） | 问题 |
|------------|------|
| 高品质鱼出生偏小 | 塘内缺少「一眼大鱼」的惊喜 |
| 成长未对齐 14 日满尺寸 | 与挂机节奏不符 |
| 咬钩：指数模型 + 钓点**加法** | 与产品「钓点乘法系数 0~5」不符 |
| 检测间隔 5s | 过于频繁 |
| 渔具脱钩：**减法** | 改为**乘法**减免，上限 30% |
| 满尺寸鱼咬钩 2~12s | 大鱼应有 2 小时收杆窗口 |
| 数值文案偏工程化 | 玩家难理解；Debug 同 |

### 1.2 目标

1. **14 天内**成长至该品质尺寸上限。
2. 初始尺寸覆盖 **[最小, 上限]** 全区间，允许至尊等 **30m+** 初始出现。
3. 满尺寸鱼：**0.6% 存量占比**、**3% 基础咬钩率**、**98.4% 脱钩率**、咬钩时长 **2 小时**。
4. 咬钩率 = **钓点系数 × (鱼咬钩率 + 鱼饵加成)**；钓点系数 **0~5**。
5. 检测间隔 **30s**；渔具脱钩减免 **×(1−减免率)**，最高 **30%**。
6. 全站 + Debug **玩家可读文案**；鱼塘明细 **方格化**；`generation` 改中文说明。

### 1.3 非目标

- 不改 C6 状态机阶段枚举
- 不改鱼种数量与品质档位数量
- 不做玩家可见的精确概率计算器（仅 Debug/Admin）

## 2. 术语（统一对外文案）

| 内部字段 | 玩家/Debug 展示名 | 说明 |
|----------|-------------------|------|
| `sizeM` | 体长 X.XX 米 | 保留两位小数 |
| `quality` | 普通/优良/…/至尊 | 不用 gray/gold |
| `generation` | 初始鱼 / 第 N 代 | **0 = 初始鱼**（系统投放或枯竭补种）；**≥1 = 繁殖产出**（第几代指父母代际较大值 +1） |

## 3. 成长曲线（14 日满尺寸）

### 3.1 尺寸上限

沿用 A0 `QUALITY_SIZE_CAP`（gold **40m** 等），不变。

### 3.2 初始尺寸（全区间均匀）

**废弃** A0 `rollInitialSize` 偏小偏态公式。

```
maxSize = min(QUALITY_SIZE_CAP[quality], species.typicalMaxM * 3.2, MAX_FISH_SIZE_M)
floor   = max(MIN_FISH_SIZE_M, species.typicalMinM * 0.5)
sizeM   = floor + (maxSize - floor) * Math.random()   // 均匀分布，允许接近 maxSize
```

**满尺寸鱼投放占比（塘内结构目标）**：

- 每次 `createFish` / 补种时，以 **0.6%** 概率强制 `sizeM = maxSize * (0.975 + random*0.025)`（即 **97.5%~100%** 上限区间）
- 其余 99.4% 走均匀分布

**验收**：Monte Carlo 1 万次，`sizeM >= maxSize*0.975` 占比 **0.55%~0.65%**；gold 品质样本中 **存在 ≥30m**。

### 3.3 成长（出生起 14 日达上限）

以 `bornAt` 为起点，**品质不变**，只增 `sizeM`：

```
maxSize = …同上
ageDays = (now - bornAt) / 86400000
progress = clamp01(ageDays / 14)
// 平滑：先快后慢，14 天必达 maxSize（若出生已接近 max 则几乎不动）
targetSize = birthSize + (maxSize - birthSize) * (1 - Math.pow(1 - progress, 1.8))
sizeM = min(maxSize, max(currentSizeM, targetSize))  // 单调不减
```

- 生态 tick 仍按 `hoursElapsed` 调用，但**以 bornAt 推导 target**，不再仅用 `typicalMinM * 0.012` 增量（可废弃 `POND_GROWTH_RATE_PER_HOUR` 主导逻辑或保留为微调项）。
- **已存 DB 鱼**：迁移时用 `bornAt` 重算一次 `sizeM`（不超过 maxSize）。

**验收**：
- [ ] 出生 0.1m 的普通鱼 14 天后 ≈ 0.3m 上限
- [ ] 出生 35m 的至尊鱼 14 天内不超过 40m，且初始即显示为大鱼

## 4. 咬钩 / 脱钩（乘法模型）

### 4.1 检测间隔

```ts
FISH_BITE_CHECK_MS = 30_000   // 30 秒，替代 5000
```

**废弃**：`BITE_LAMBDA`、指数模型 `P = 1 - exp(-W×λ)`。

### 4.2 钓点系数（乘法，0~5）

`spot_bite_weights` 表语义改为 **`spot_multiplier`**（建议列名迁移或复用 weight 字段存 multiplier）：

- 刷新策略：每 5 分钟
- 取值：**均匀随机 `[0, 5]`**，保留 2 位小数
- **0**：该点位 `(鱼+饵)` 再乘 0 → **永不上钩**（空军位）
- **5**：最佳位，5 倍咬钩

玩家文案示例：**「此钓点当前运气：×3.2（每 30 秒判定一次）」**

### 4.3 单鱼有效咬钩率（每 30s 一次）

对玩家 `waiting`、钓点 `spotId`、装备饵 `baitBonus`（B1 公式）：

```
baseBite = fish.biteRate ?? species.biteRatePerTick   // 见 §4.4
effectiveBite_i = clamp01( spotMultiplier * (baseBite + baitBonus) )
```

**本 tick 是否咬钩**（单玩家）：

```
total = Σ effectiveBite_i   （未锁定、未枯竭鱼）
if total <= 0 → 不咬钩
if random() < min(1, total) → 按 effectiveBite_i 加权随机选一条鱼 target
else → 不咬钩
```

> 注：多条鱼时 `total` 可 >1，需 `min(1, total)` 封顶。

### 4.4 鱼种咬钩率 / 脱钩率

**普通鱼**（非满尺寸）：由策划表配置 `biteRatePerTick`（每 30s，建议 0.005~0.05），`baseEscapeRate` 沿用 A0 量级（0.08~0.25 + 品质加成）。

**满尺寸鱼** `isNearMaxSize(fish)`：

| 参数 | 值 | 说明 |
|------|-----|------|
| 基础咬钩率 | **3%** (`0.03`) | 再 × 钓点 × 含饵加成 |
| 脱钩率 | **98.4%** (`0.984`) | 再 × 渔具减免 |
| 存量占比目标 | **0.6%** | 见 §3.2 出生/补种 |

**上钩后脱钩判定**（咬钩瞬间）：

```
escapeRate = baseEscapeForFish   // 满尺寸 0.984，否则 species+quality
escapeRate *= (1 - tackleEscapeReduction)   // §4.5
escaped = random() < clamp01(escapeRate)
```

### 4.5 渔具脱钩减免（乘法，上限 30%）

**废弃**：`escapeRate - tackleEscapeReduction`（减法）。

```
reduction = min(0.30, tackleEscapeReduction(tackleId))   // 最高 30%
escapeRateFinal = clamp01(escapeRate * (1 - reduction))
```

**渔具表调整建议**（B0 配置）：

| 渔具 | 抗脱钩（玩家文案） | reduction |
|------|-------------------|-----------|
| 竹竿 | 无 | 0 |
| 碳素竿 | 脱钩率 ×90% | 0.10 |
| 专业路亚 | 脱钩率 ×80% | 0.20 |
| 大师套装 | 脱钩率 ×70% | 0.30 |

玩家文案：**「脱钩率降低 10%」= 最终脱钩率乘以 (1−10%)**，不是减去 10 个百分点。

### 4.6 咬钩时长 `hookDurationMs`

```
if isNearMaxSize(fish):
  hookDurationMs = 2 * 60 * 60 * 1000   // 2 小时 = 7_200_000 ms
else:
  hookDurationMs = clamp(2000, 1800 + qualityIndex*700 + sizeM*400, 600_000)  // 非满尺寸最长 10 分钟
```

**客户端**：展示「预计收杆时间：X 小时 X 分」；`hookEndsAt` 同步。

**状态机**：C6 `hooked` 阶段须支持 2h 计时；断线 60s 规则仍适用，重连后按剩余时间续接。

**验收**：
- [ ] 满尺寸鱼咬钩后 `hookDurationMs === 7200000`
- [ ] 非满尺寸仍 ≤10 分钟

## 5. 鱼饵加成（B1 兼容）

加法仍在乘钓点**之前**：

```
baitBonus = baitBiteBonus(baitId, speciesId)   // 现有 B1
effectiveBite = spotMultiplier * (fishBite + baitBonus)
```

商店/Debug 文案：**「每 30 秒额外 +X% 咬钩」**（X = baitBonus×100）。

## 6. 文案规范（全站 + Debug）

### 6.1 原则

- **禁止**对玩家展示：`BITE_LAMBDA`、`biteWeight`、`effectiveWeight`、`shareOfTotal`、`gen0` 等内部键名。
- 概率统一：**「每 30 秒 XX% 机会咬钩」**、**「上钩后 XX% 可能脱钩」**。
- 钓点：**「运气系数 ×N（0~5）」**；N=0 时 **「枯位：当前几乎钓不到鱼」**。

### 6.2 涉及页面

| 位置 | 调整 |
|------|------|
| 商店 `ShopModal` | 加成改「每 30 秒 +X% 咬钩」「脱钩率 ×Y」 |
| 图鉴 `CodexModal` | 咬钩/脱钩改可读句；推荐饵保留 |
| 鱼塘生态一行字 | 可选展示本塘钓点运气范围 |
| Admin `AdminFishingDebugPanel` | 全文案对照 §6.1 |
| Admin `AdminConfigPanel` | 配置项中文标签 + 说明 |

### 6.3 Debug：鱼塘 + 钓点 **统一方格面板**（合并原「鱼塘明细」与「钓鱼概率」）

**原则**：一个面板、一组 **小页签** 切换；**不再**上下分两块（`PondFishGrid` + `AdminFishingDebugPanel` 折叠列表）。

#### 6.3.1 面板结构

```
┌─ 鱼塘调试 · [静水塘] ─────────────────────────────┐
│ [模拟鱼饵: 蚯蚓 | 玉米 | …]  [强制刷新]            │
│ 摘要：总鱼数 · 品质分布 · 判定间隔 30 秒          │
├──────────────────────────────────────────────────┤
│ 页签： [鱼塘] [钓位1] [钓位2] … [钓位N]           │  ← 横向 ScrollView 小页签
├──────────────────────────────────────────────────┤
│ ┌200×200┐ ┌200×200┐ ┌200×200┐ …                  │
│ │ 鱼格 1 │ │ 鱼格 2 │ │ 鱼格 3 │                  │  ← 响应式换行，格固定 200×200
│ └────────┘ └────────┘ └────────┘                  │
└──────────────────────────────────────────────────┘
```

- **页签「鱼塘」**：展示塘内**全部**鱼（与钓点无关的静态生态数据）。
- **页签「钓位 k」**：仅展示在该钓位下 **`本点有效咬钩率 > 0`** 的鱼（见 §6.3.3）；**不展示**有效咬钩率为 0 的鱼（含枯位 ×0、基础咬钩为 0 且饵加成不足等情况）。
- 钓位页签标题：**钓位 1**、**钓位 2**…（按 `spots` 数组序号，**禁止** raw `spot-uuid` 作主标题）；副标题可显示 `运气 ×N`。

#### 6.3.2 鱼格尺寸与字号（解决「字太小」）

| 属性 | 定稿 |
|------|------|
| 格子外框 | **200 × 200 px**（`width`/`height`/`minWidth`/`minHeight` 均锁定，Web 用 px） |
| 鱼种 icon | **48px** |
| 体长 | **16px** 加粗 |
| 品质名 | **14px**，品质色 |
| 鱼 ID | **11px** 等宽，显示前 8 位 + `…`；**点击/长按**复制完整 UUID |
| 辅助行（来源/角标） | **12px** |
| 概率行（仅钓位页签） | **13px**，行距 1.4 |

**布局**：格内 `padding: 10`；内容垂直居中偏上；概率多行时格内 **ScrollView**（不超过 200 高）。

#### 6.3.3 页签字段分工（重要）

| 字段 | **鱼塘** 页签 | **钓位 k** 页签 |
|------|:-------------:|:---------------:|
| 鱼种 icon + 名称 | ✅ | ✅（缩略） |
| 体长 | ✅ | ✅ |
| 品质（中文） | ✅ | ✅ |
| 唯一 ID 短码 | ✅ | ✅ |
| 来源：初始鱼 / 第 n 代 | ✅ | ❌ |
| 角标「体型上限」见 §6.3.4 | ✅ | ✅（可选小角标） |
| 角标「繁殖」 | ✅ | ❌ |
| **基础咬钩率**（每 30s） | ❌ **不显示** | ✅ |
| **鱼饵加成**（当前模拟饵） | ❌ | ✅ |
| **钓点运气 ×N**（点位加成） | ❌ | ✅（页签级摘要 + 格内重复一次） |
| **本点有效咬钩率** | ❌ | ✅ |
| **上钩后脱钩率** | ❌ | ✅ |
| **被选中占比** | ❌ | ✅（可选，小字） |

**钓位页签过滤规则**：

```
effectiveBite = spotMultiplier × (baseBite + baitBonus)   // 见 §4.3
仅当 effectiveBite > 0 时，该鱼出现在「钓位 k」页签方格中
```

- 枯位（运气 ×0）：钓位页签**空状态**——「此钓位当前无有效目标鱼（运气 ×0）」。
- 切换模拟鱼饵时，钓位页签鱼数量可变化（饵加成改变 → 过滤结果改变）。
- 鱼塘页签始终展示**全塘鱼**，不受上述过滤影响。

**摘要区**（页签上方）：钓位页签额外一行 **「本钓位约 XX% / 30 秒有鱼咬钩 · 运气 ×N · 可钓 X 条」**（X = 过滤后鱼数）；鱼塘页签无咬钩率摘要。

#### 6.3.4 角标「满」→ 改为「体型上限」

**问题**：单字 **「满」** 语义不清。

**定稿**：
- 条件不变：`isNearMaxSize`（体长 ≥ 该鱼品质尺寸上限 × 97.5%）。
- 角标文案：**「体型上限」** 三字（或窄格用 **「上限」** 两字，**禁止**单独「满」）。
- **Tooltip / 长按说明**：「此鱼体长已接近该品质允许的最大值，咬钩 3%、脱钩 98.4%、收杆 2 小时（见 A0-v2 §4.4）」。
- Debug 图例（面板底部一行）：**「上限 = 已达该品质最大体长」**。

#### 6.3.5 组件与 API

- **合并** `PondFishGrid` + `AdminFishingDebugPanel` → 新组件 `AdminPondFishDebugGrid.tsx`（名称可调整）。
- `admin.tsx`：选中鱼塘后**只渲染一个**合并面板；删除独立 `PondFishGrid` + 折叠「钓鱼概率」双区块。

## 9. 验收标准

### 数值

- [ ] 14 日成长模拟：出生小鱼 14 天达上限误差 <2%
- [ ] 满尺寸鱼占比 0.55%~0.65%；gold ≥30m 可出现
- [ ] 满尺寸：bite 3%、escape 98.4%、hook 2h
- [ ] 钓点 ×0 永不咬钩；×5 同鱼咬钩率为 ×1 的 5 倍
- [ ] 检测间隔 30s（日志/单测）
- [ ] 大师竿：脱钩率 ×0.7，且不超过 30% 减免上限

### 文案与 Debug

- [x] 玩家界面无 `gen0`/`BITE_LAMBDA`/biteWeight 英文字样
- [x] Debug 统一页签面板：鱼塘 + 钓位 1…N（§6.3）
- [x] 鱼格 200×200，字号 ≥ §6.3.2
- [x] 鱼塘页签无概率字段；钓位页签每条鱼有咬钩/脱钩/饵/点位加成
- [x] 角标「体型上限」+ 图例，无单字「满」
- [x] generation 显示「初始鱼/第 n 代」

## 10. 风险

| 风险 | 缓解 |
|------|------|
| 2h 收杆占用钓位 | 满尺寸极稀有；允许 stop 视为脱钩 |
| 钓点 ×0 玩家挫败 | 客户端提示换钓位；5 分钟刷新 |
| 30s 检测体感变慢 | 符合挂机；文案说明 |
| 与 A0 验收冲突 | 本 spec 优先，A0 相关条目 superseded |
