## 1. 背景与目标

### 1.1 产品定位

Fish Social 定位为 **2D 多人社交桌面宠物产品**，以桌面宠物为第一入口，在桌面宠物的基础上扩充联机鱼塘和轻量社交能力。玩家不仅能看到自己的猫咪钓鱼，还能看到同一个鱼塘内其他玩家的宠物形象、钓鱼状态和鱼塘环境。

- 桌面上的 2D 猫咪宠物陪伴和钓鱼状态
- 同一鱼塘内多个玩家宠物的可视化和轻量互动
- 可随时进入、随时离开的挂机钓鱼
- 不打断工作流的低干扰桌面陪伴
- 与 Steam 好友聊天、邀请和共同进入鱼塘
- 有长期积累的鱼获、图鉴、装备和鱼塘生态

### 1.2 第一阶段目标

第一阶段验证“桌面宠物陪伴 + 多人鱼塘场景 + 快速功能访问”的完整主循环：

```text
启动桌面宠物
→ Steam 身份确认
→ 进入桌面主界面
→ 选择或恢复当前鱼塘
→ 显示自己的猫咪、同塘玩家宠物和鱼塘环境
→ 选择钓点并开始钓鱼
→ 缩小窗口/隐藏到托盘继续陪伴
→ 鱼咬钩提醒
→ 恢复窗口并收取鱼获
→ 通过右键菜单打开好友、背包、图鉴等弹窗
→ 与同塘玩家聊天或邀请好友
→ 关闭窗口隐藏到托盘，或从托盘退出
```

### 1.3 非目标

- 不把移动端页面逐个平移到 Unity。
- Steam 版建立新档，不迁移旧移动端数据。
- 鱼塘权威与 web/RN 相同（现有 Node + Socket.IO）；桌面差异只在窗口、Overlay 和宠物表现（含 Overlay 本地序列帧）。
- 不在本阶段实现复杂竞技、战斗或大规模开放世界。
- 不把 Steam Cloud 作为金币、库存、鱼获和每日额度的唯一存储。
- 不为每个鱼塘启动一台常驻服务器。
- 不以 Steam Networking/Relay 替换现有 Node Socket.IO 作为本阶段前置。
- 不在 RN 和 Unity 中同时开发新的完整功能。

### 1.4 已确认决策（2026-08-11）

| 主题 | 决策 |
|------|------|
| 窗口关闭 | 关闭窗口隐藏到托盘并继续挂机 |
| 通知 | 默认通知鱼咬钩和好友邀请 |
| 启动入口 | 先进入桌面主界面，再选择鱼塘 |
| 收鱼 | 限定时间内自动收鱼 |
| 离线生态 | 补算迁移、成长、数量和下次看到的具体位置 |
| 社交 | Steam 好友邀请 + 公共聊天 + 私聊 |
| 平台 | 第一阶段只支持 Windows；包含窗口化、全屏/无边框、托盘和通知 |
| 账号 | Steam 版建立新档，不迁移旧移动端数据 |
| 收鱼规则 | 沿用现有服务端咬钩/超时规则，Unity 只展示结果 |
| 钓点 | 保留手动选择钓点 |
| 邀请 | 直接进入邀请者当前鱼塘 |

| 同塘同步 | 沿用 `pond_snapshot` / `pond_user_*`；Overlay 不连 Socket |

## 2. 目标用户与核心场景

| 场景 | 用户行为 | 产品应提供 |
|------|----------|------------|
| 工作间隙 | 快速查看鱼塘和好友状态 | 低信息密度主界面、快速进入 |
| 工作期间 | 最小化后挂机 | 后台保持会话、低 CPU、低打扰 |
| 鱼咬钩 | 收到提醒后短暂操作 | 桌面通知、点击恢复、收鱼 |
| 好友在线 | 邀请或进入同一鱼塘 | Steam 好友/Lobby/邀请入口 |
| 长时间离线 | 下次回来查看变化 | 鱼群迁移、成长和生态离线补算 |
| 下班后 | 查看鱼获、图鉴和社交内容 | 可展开的背包、图鉴、聊天和个人状态 |

## 3. 第一阶段功能需求

### 3.1 客户端启动与登录

- 使用 Steam 客户端启动或检测 Steam 是否运行。
- 获取 Steam Ticket，由 Node 服务端验证。
- 服务端将可信 `SteamID64` 映射到内部 `playerId`。
- 登录成功后建立游戏 JWT 会话。
- 登录失败时显示可理解的原因和重试入口。

### 3.2 桌面窗口

默认支持：

- 窗口化运行
- 最小化与恢复
- 关闭窗口隐藏到托盘并继续运行
- 窗口大小和位置保存
- 后台运行状态
- 全屏/无边框模式
- 托盘入口
- 基础设置入口

置顶窗口、极简/静默模式和开机启动暂不作为第一阶段承诺。

#### 3.2.1 桌面宠物形态

- 宠物是桌面端的常驻主视觉，不是普通游戏大厅中的头像。
- 第一阶段使用普通桌面窗口承载宠物和鱼塘内容；不承诺透明穿透桌面、自由拖拽宠物或系统级置顶。
- 窗口隐藏到托盘后，钓鱼会话和服务端状态按既有规则继续运行。
- 恢复窗口时优先展示服务端最新快照，不使用本地倒计时作为权威。

#### 3.2.2 右键菜单

右键菜单只作用于 Fish Social 自己的窗口和桌面宠物区域，不拦截 Windows 桌面其他区域的系统右键菜单。

| 菜单项 | 行为 | 优先级 |
|--------|------|--------|
| 当前鱼塘 | 展开/恢复鱼塘主场景 | P0 |
| 好友与聊天 | 打开社交弹窗 | P0 |
| 鱼获/背包 | 打开背包弹窗 | P0 |
| 图鉴 | 打开图鉴弹窗 | P1 |
| 设置 | 打开窗口、通知设置弹窗 | P0 |
| 返回桌面宠物 | 收起鱼塘内容，保留宠物主视图 | P1 |
| 隐藏到托盘 | 隐藏窗口并继续后台运行 | P0 |
| 退出 | 结束客户端进程并清理托盘资源 | P0 |

菜单打开后，点击具体功能使用弹窗或面板承载，不跳转到移动端式多级页面。

### 3.3 鱼塘主界面

必须能看到：

- 当前鱼塘名称和主题
- 2D 鱼塘环境、池塘水面和钓位
- 自己的猫咪宠物形象、位置和钓鱼状态
- 同塘其他玩家的宠物形象、昵称和基础钓鱼状态
- 玩家自己的钓鱼状态
- 当前钓点和剩余每日额度
- 在线好友或鱼塘内玩家
- 聊天入口
- 鱼咬钩/收鱼入口
- 背包或鱼获入口

主界面优先保障挂机状态和社交信息，不优先堆叠移动端全部按钮。

#### 3.3.1 主界面分层

```text
Fish Social 桌面主窗口
├── 宠物/鱼塘场景层
│   ├── 池塘环境与钓位
│   ├── 自己的猫咪宠物
│   └── 同塘其他玩家宠物
├── 状态层
│   ├── 鱼塘名称与在线人数
│   ├── 自己的钓鱼状态与剩余额度
│   └── 鱼咬钩、断线、重连提示
├── 轻交互层
│   ├── 鱼塘聊天入口
│   ├── 好友/邀请入口
│   └── 开始/收竿/收鱼操作
└── 弹窗层
    ├── 好友与聊天
    ├── 鱼获/背包
    ├── 图鉴
    └── 设置
```

宠物和鱼塘场景是主视觉；弹窗不能覆盖并重置鱼塘会话，关闭弹窗后返回原场景状态。

### 3.4 挂机与通知

- 最小化后继续保持合法钓鱼会话。
- 空鱼塘停止高频生态 Tick，但鱼群成长和迁移通过时间差补算。
- 鱼咬钩和好友邀请默认触发桌面通知。
- 其他系统事件默认不通知；免打扰开关和通知细节待确认。
- 客户端恢复时必须重新以服务端快照为准，不信任本地倒计时作为权威。

### 3.5 好友与社交

第一阶段建议支持：

- Steam 好友列表中的在线状态读取
- Steam 好友邀请
- Lobby 与 `pondId` 映射
- 好友进入同一鱼塘
- 鱼塘内文字聊天
- 好友私聊

好友墙和复杂社交关系管理可后置到第二阶段；私聊沿用现有服务端能力，先做最小可用版本。

### 3.6 数据与安全

- 客户端不提交 SteamID 作为可信身份。
- 客户端不直接修改库存、金币、鱼获或每日额度。
- 所有资产变更由 Node 服务端校验、写入和审计。
- `SteamID64 ↔ playerId` 绑定必须可查询、可撤销、避免重复绑定。
- Token、Steam API Key、数据库文件和备份不得进入客户端包或日志。

### 4.1 用户主流程

```text
Steam 启动 Fish Social
→ 检查 Steam 与安全会话
→ 首次登录：完成 Steam 绑定；已有账号：恢复 playerId
→ 显示桌面宠物主视图
→ 用户选择鱼塘，或恢复上次进入的鱼塘
→ Node 返回 pond 快照和在线玩家
→ 渲染池塘环境、自己的猫咪和同塘玩家宠物
→ 选择钓点并开始钓鱼
→ 用户可隐藏窗口/打开右键菜单/打开弹窗
→ 鱼咬钩时通知用户
→ 恢复鱼塘窗口并收鱼
→ 继续聊天、邀请好友或查看背包
→ 隐藏到托盘继续运行，或明确退出客户端
```

### 4.2 异常与恢复主流程

```text
Steam 未启动
→ 保留客户端窗口
→ 显示“请先启动 Steam”及重试入口

服务端不可用
→ 显示连接失败原因
→ 不伪造多人鱼塘状态
→ 提供重试和退出入口

Socket 断线
→ 显示重连状态
→ 恢复后以 pond_snapshot 为准
→ 保留弹窗和鱼塘会话上下文

打开弹窗
→ 不执行 leave_pond
→ 关闭弹窗后回到原鱼塘和宠物状态
```

## 5. 交互原则

- 进入游戏后尽快看到鱼塘，不强制经过复杂大厅。
- 主要挂机状态在窗口最小化后仍可理解。
- 通知必须可关闭、可配置频率。
- 断线、Steam 未启动、服务器维护和账号绑定失败要用普通用户能理解的文字解释。
- 所有关键结果以服务端快照为准，客户端只做表现和本地插值。
- 新功能优先考虑“能否在几秒内查看并退出”，而不是增加操作层级。

## 10. 定稿补充：桌面宠物 UI 与 Unity 开发拆分

### 10.1 一页产品定位

**产品**：Fish Social Steam Windows 桌面宠物。  
**核心体验**：玩家在桌面窗口中看到自己的猫咪，随时进入持久化鱼塘，与同塘玩家宠物共同挂机钓鱼。  
**目标用户**：希望在工作、学习或休息间隙快速查看状态、低打扰挂机，并与 Steam 好友保持轻社交联系的玩家。  
**核心价值**：

1. 几秒内启动、登录、查看宠物和鱼塘状态。
2. 缩小、隐藏到托盘后仍保持合法会话和通知能力。
3. 鱼塘是持久化世界，不因 Lobby 或房主离开而关闭。
4. 所有鱼获、库存、额度、生态和权限由 Node/DB 权威保存。

**第一阶段成功标准**：玩家能完成“启动 → 登录 → 宠物主视图 → 进入鱼塘 → 选择钓点 → 挂机 → 收鱼 → 聊天/邀请 → 托盘运行”的闭环；断线、弹窗和 Lobby 失效不破坏鱼塘状态。

### 10.2 桌面宠物 UI 规格

#### 宠物主视图（P0）

| 区域 | 内容 | 交互 |
|------|------|------|
| 宠物展示区 | 自己的猫咪、当前动作、当前钓鱼状态 | 左键打开鱼塘；右键打开产品菜单 |
| 状态胶囊 | Steam 登录、鱼塘名称、在线/重连状态 | 点击进入对应状态面板 |
| 最近事件 | 咬钩、好友邀请、断线和收鱼结果 | 点击恢复主窗口并打开相关弹窗 |
| 快捷入口 | 当前鱼塘、好友/聊天、鱼获/背包 | 打开弹窗或鱼塘主窗口 |

#### 右键菜单（P0）

菜单只挂载在 Fish Social 自己的窗口和宠物区域：

```text
当前鱼塘
好友 / 聊天
鱼获 / 背包
图鉴（P1）
设置
返回桌面宠物
隐藏到托盘
退出
```

右键菜单不改变服务端状态；打开或关闭菜单、弹窗都不得触发 `leave_pond`。

#### 鱼塘主窗口（P0）

```text
顶部栏：鱼塘名称 / 在线人数 / Socket 状态 / 最小化
主场景：池塘环境 / 钓位 / 自己的猫咪 / 同塘玩家宠物
底部状态：当前钓位 / fishingPhase / 每日剩余额度
操作栏：选钓位 / 开始 / 收杆 / 收鱼 / 聊天 / 好友邀请
浮层：咬钩、断线、重连、服务端错误
```

P0 必须控件：

- 鱼塘名称和主题
- 在线人数
- 自己宠物和当前 `fishingPhase`
- 同塘玩家宠物、昵称和基础状态
- 当前钓位、选择钓位入口
- 开始钓鱼、收杆、领取鱼获
- 每日剩余额度
- 聊天入口
- 好友邀请入口
- 连接/重连状态和错误提示

P1 控件：

- 宠物动作和情绪表现
- 钓鱼倒计时表现
- 图鉴快捷入口
- 同塘玩家快捷菜单
- Rich Presence 状态详情

### 10.3 鱼塘主流程

```text
Steam 启动
→ 检测 Steam
→ Ticket 登录 / 恢复 playerId
→ 宠物主视图
→ 选择或恢复 pondId
→ Node 执行生态唤醒补算
→ pond_snapshot
→ 显示池塘与同塘玩家宠物
→ 选择钓位
→ 开始钓鱼
→ 最小化 / 托盘挂机
→ fish_bite 通知
→ 恢复窗口
→ 领取鱼获
→ inventory_updated
→ 聊天 / 邀请 / 查看背包
→ 继续挂机或明确退出
```

关键边界：

- 打开弹窗不离开鱼塘。
- 隐藏到托盘不停止合法钓鱼会话。
- Lobby 关闭不删除 `pondId`。
- 最后一个真人离开后，鱼塘进入休眠并按离线时间补算。
- 恢复窗口时以服务端快照为准，不使用本地倒计时覆盖权威状态。

### 10.4 异常恢复流程

| 异常 | UI 状态 | 恢复动作 |
|------|---------|----------|
| Steam 未启动 | 登录失败 | 启动 Steam / 重试 |
| Ticket 或账号绑定失败 | 登录失败 | 显示原因 / 重试 / 退出 |
| Socket 断线 | 重连中 | 自动重连；成功后重新 `join_pond` |
| 服务端不可用 | 服务不可用 | 不伪造在线人数和鱼塘状态；重试或退出 |
| Lobby 缓存失效 | Lobby 已失效 | 允许重新创建 Lobby；原 `pondId` 仍可从其他入口进入 |
| 咬钩通知点击过期 | 鱼获状态待同步 | 请求服务端快照和待领取状态 |
| 弹窗关闭 | 返回原场景 | 不执行 `leave_pond`，保留宠物和鱼塘状态 |

### 10.5 Unity 开发拆分

| 任务 | Unity 产出 | 依赖 | 优先级 |
|------|------------|------|--------|
| U01 宠物主视图 | `PetHomePanel`、宠物状态 ViewModel、最近事件区 | STEAM-DESKTOP-02 / UNITY-P2 | P0 |
| U02 鱼塘场景壳 | `PondPanel`、场景层、钓位标记、玩家宠物锚点 | UNITY-P2 | P0 |
| U03 鱼塘状态栏 | phase、额度、在线人数、Socket 状态 | SocialPondSessionController | P0 |
| U04 钓鱼操作栏 | 选位、开始、收杆、收鱼按钮状态机 | U03 | P0 |
| U05 宠物与玩家表现 | 自己宠物/同塘玩家宠物的状态驱动表现 | pond_snapshot / pond_user_updated | P0 |
| U06 Friends/Lobby 弹窗 | 好友列表、邀请、Lobby 状态、错误恢复 | STEAM-DESKTOP-03 | P0 |
| U07 鱼获弹窗 | 背包、鱼获结果、领取状态 | inventory_updated / REST | P0 |
| U08 Chat 弹窗 | 公共聊天、私聊入口、消息列表 | 现有 Node 社交接口 | P1 |
| U09 右键产品菜单 | 窗口内右键菜单和弹窗路由 | U01 / U02 | P0 |
| U10 托盘与通知层 | 隐藏/恢复、咬钩通知、好友邀请通知 | STEAM-DESKTOP-04 | P0 |
| U11 设置弹窗 | 窗口模式、通知开关、免打扰 | STEAM-DESKTOP-04 | P0 |
| U12 异常恢复 | Steam/Socket/Lobby/服务器错误状态和重试 | U03 / U06 | P0 |

架构边界：

```text
Steam / Socket Adapter
        ↓
Controller / Session
        ↓
ViewModel / State Events
        ↓
PetHomePanel / PondPanel / FriendsPanel / LobbyPanel / Modal
```

UI 不直接调用 Steam API、Node 权限接口或鱼塘业务服务；正式美术只替换 Panel 和 View，不重写 Controller、协议和服务端权威逻辑。

### 10.6 必须阻塞开发的问题

以下决策已采用推荐默认值，若变更会影响 P0：

| 问题 | 选项 | 推荐默认值 | 影响 |
|------|------|------------|------|
| 桌面宠物是否透明穿透桌面 | 普通窗口 / 透明置顶宠物 | 普通窗口 | 影响 Win32 窗口、输入和托盘实现 |
| 宠物与鱼塘关系 | 独立宠物 / 鱼塘作为宠物背景 | 鱼塘作为可展开主场景 | 影响 U01/U02 路由和状态保持 |
| 关闭窗口行为 | 退出 / 隐藏托盘 | 隐藏托盘 | 影响挂机、通知和生命周期 |
| 鱼塘入口 | 强制 Lobby / 世界地图或好友等多入口 | 多入口，Lobby 仅社交入口 | 影响后端权限与空塘恢复 |
| 收鱼方式 | 自动 / 手动 / 混合 | 沿用服务端规则，Unity 展示结果 | 影响通知、待领取状态和 UI |
| 主窗口信息密度 | 移动端全量 / 低密度陪伴 | 低密度 P0 + 弹窗承载详情 | 影响布局和开发范围 |

### 10.7 可后置决定的问题

- 正式宠物美术、动作数量和情绪系统。
- 透明窗口、置顶、自由拖拽和桌面穿透。
- 图鉴、Rich Presence 细节、成就和时长统计。
- 聊天历史、消息搜索和复杂社交关系管理。
- 多显示器、DPI 适配、音量和画质设置。
- 开机启动、自动登录和多账号切换。

以上后置项不得改变 P0 主循环、鱼塘持久化、Node 权威和托盘挂机边界。
