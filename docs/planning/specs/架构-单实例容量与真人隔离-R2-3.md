## 1. 背景与目标

### 1.1 背景

当前架构为 **单进程 + 内存实时态 + SQLite**。v0.5 一～三期正确性/可维护/性能项已落地，但：

- 「一台机能撑多少真人」没有可执行的运维口径
- Bot 与真人混在同一 Socket/钓位池时，容量观感与公平性易被 Bot 挤占
- 多机扩容（阶段 4）前置条件散落在路线图，缺少独立可引用文档

### 1.2 目标

1. **单实例容量基线**：给出推荐上限、监控项、超限处置策略（先软后硬）
2. **真人隔离口径**：连接数、在塘人数、钓位占用均按 human / bot 分计；限额默认只约束真人
3. **多实例前置清单**：明确「未满足则禁止宣称可水平扩展」的检查表（文档交付，本编号不写多机代码）

### 1.3 非目标

- Redis Adapter / 多副本 Socket / 业务库全面迁 PG（阶段 4 另立项）
- 正式千人压测报告（可引用本基线做小规模压测，但不作为本编号验收）
- 改 Bot 行为 AI、改钓鱼公式
- 替换 R2-5 已有的 `MAX_BOTS_PER_POND` / 驱逐策略（本规格引用并互补）

## 3. 功能范围

### 3.1 文档交付（必须，本编号主体）

| ID | 交付 | 说明 |
|----|------|------|
| D1 | 单实例容量基线表 | 见 §3.3 |
| D2 | 真人/Bot 分账口径 | 连接、在塘、钓位、metrics 标签约定 |
| D3 | 多实例前置检查表 | 见 §3.4 |
| D4 | 监控与告警项 | 见 §5；对齐 Admin /health 可读字段 |

### 3.2 轻量实现（建议同迭代，可标 P2）

| ID | 功能点 | 说明 |
|----|--------|------|
| I1 | 配置项 | `MAX_HUMAN_SOCKETS`（默认 200）、`MAX_HUMANS_PER_POND`（可选，默认不限制或与钓位数一致） |
| I2 | 软拒绝 | 真人 `join_pond` / 新 Socket 鉴权成功后，若超 `MAX_HUMAN_SOCKETS` → 返回明确错误码（Bot 豁免） |
| I3 | 指标暴露 | `/ready` 或 Admin summary：`humanSocketCount` / `botSocketCount` / `humanInPond` / `capacityLimit` |
| I4 | 日志 | 超限时 `capacity_reject` structured log（含 playerId、current、limit） |

**不做硬杀已在线真人**（避免误伤）；仅拒绝新进入。

### 3.3 单实例容量基线（D1）

| 指标 | 推荐上限（初值） | 备注 |
|------|------------------|------|
| 活跃真人 Socket | **&lt; 200** | 以压测为准可调；含短暂断线宽限期内的会话 |
| 单塘真人同时在座 | ≤ 钓位数 | 已有占座逻辑；Bot 用 R2-5 配额 |
| 全服 Bot 连接 | 受 `MAX_BOTS_PER_POND` × 塘数约束 | 不占用真人 Socket 限额 |
| SQLite 写 | 维持现有 metrics 批量 | 超限优先减采样，不先加机器 |

调整流程：压测 → 改 env → 更新本表「推荐上限」与 CHANGELOG 一行，无需新开编号。

### 3.4 多实例前置检查表（D3）

在宣称「可水平扩展 / 千人」前，须全部满足（**本编号只要求文档列出；实现属阶段 4**）：

- [ ] 在线态 checkpoint 可跨进程恢复（R0-2 已有单机表；多机需共享存储）
- [ ] Socket.IO Redis Adapter（或等价）跨机广播
- [ ] 占座 / pending 锁鱼等关键路径有分布式锁或单写者
- [ ] 业务库或会话态不再绑定「单机内存为唯一权威」而无共享回退
- [ ] 负载均衡粘性或无状态握手方案已定
- [ ] 正式压测报告（目标并发 ≥ 声明容量）

## 4. 技术影响

### 4.1 配置

```bash
# .env.example
MAX_HUMAN_SOCKETS=200
# MAX_HUMANS_PER_POND=   # 可选；空=不额外限制
```

### 4.2 API / 事件

| 类型 | 名称 | 说明 |
|------|------|------|
| Socket/HTTP | join 失败码 | 如 `capacity_full` / `human_socket_limit` |
| Admin/ready | capacity 摘要 | human/bot counts + limit |
| Metric/log | `capacity_reject` | 超限拒绝 |

### 4.3 涉及文件（若做 I1–I4）

- `server/src/`：连接计数（sessionRegistry / socketLifecycle）、join_pond 守卫
- `shared/`：错误码常量（若已有错误字典则追加）
- `.env.example`、运维说明（可附本 spec）

## 6. 风险与依赖

| 风险 | 缓解 |
|------|------|
| 200 过于保守/激进 | 初值保守；用压测改 env，不改代码常量硬编码 |
| 断线宽限导致「幽灵占用」 | 计数以「已鉴权且未完成 disconnect_timeout 清场」的真人会话为准；与 R0-2 checkpoint 对齐 |
| 与 R2-5 重叠 | Bot 塘内配额仍归 R2-5；本规格只管**全服真人 Socket 顶** |
