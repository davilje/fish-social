## 1. 设计原则

1. **服务端权威**：所有状态转移由服务端驱动，客户端仅根据服务端广播渲染。
2. **可观察性**：状态、剩余时间、上下文（鱼种、饵、竿）必须能被同塘所有玩家观察到，用于阶段动画与飘字。
3. **可恢复性**：玩家断线重连、服务端热重启后，能从持久化 / 快照恢复当前状态与剩余计时。
4. **可扩展性**：新阶段可插入而不破坏客户端渲染契约（客户端未知的阶段回退为静态展示）。
5. **与经济系统对齐**：饵消耗时机、鱼锁定时机、金币扣减时机必须绑定到明确的状态转移点。

## 2. §4.11 决策落地一览

| 决策项 | 结论 | 落地位置 |
|---|---|---|
| 1. `resolving(escape)` 是否广播全塘 | **方案 B：广播全塘**，提升鱼塘氛围 | §4.4.7 `resolving`；A1 已提前实现 |
| 2. `hooked` 阶段 `stop_fishing` 的定性 | **视为脱钩**（鱼回塘、饵不退，走 escape 分支） | §4.4.6 `hooked` |
| 3. `baiting` 与 `rebaiting` 是否合并 | **合并为单一 `baiting`**，用 `context.isRebait` 区分 | §4.2 状态枚举；§4.4.3 |
| 4. `disconnected` 超时时长 | **60s**（放宽以适配移动端弱网） | §4.4.10 `disconnected` |
| 5. 付费饵扣款是否延迟到 `waiting` | **不延迟**，保持在 `baiting` 起点 | §4.7 经济绑定表 |

## 3. 状态枚举 `FishingPhase`（完整）

| 阶段 | 服务端权威 | 典型时长 | 他人可见 | 说明 |
|---|---|---|---|---|
| `idle` | 是 | 无 | 是（不在钓位或空闲） | 玩家未占据钓位或已离开 |
| `seated` | 是 | 无（玩家动作驱动） | 是 | 已占座未开始钓鱼；可「开始钓鱼」「离席」 |
| `baiting` | 是 | 800ms | 是 | 装饵；付费饵在此阶段起点扣 1 个；`context.isRebait` 区分首次/循环装饵 |
| `casting` | 是 | 600ms | 是 | 抛竿动作；循环钓时可跳过 |
| `waiting` | 是 | 不定（直到咬钩） | 是 | 垂钓中；纳入 5s 咬钩检测；可 `stop_fishing` 中止 |
| `hooked` | 是 | `hookDurationMs`（2000~12000ms） | 是（含飘字） | 鱼已咬钩，脱钩结果已在起点确定但对玩家保密 |
| `resolving` | 是 | 600~800ms | 是 | 结果播放阶段，带 `outcome: 'catch' \| 'escape'` |
| `result` | 客户端本地 | 直到玩家操作 | 否 | 弹窗展示中；服务端 phase 已回落到 `seated` 或 `baiting`(isRebait) |
| `stopping` | 是 | ≤ 200ms | 是 | 主动停止钓鱼的短暂收竿过渡；结束回 `seated` 或 `idle` |
| `disconnected` | 是 | ≤ 60s | 否（他人看角色变灰） | 玩家断线，状态冻结；60s 超时释放钓位与锁定鱼 |

**决策 3 落地说明**：原设计的 `rebaiting` 已合并进 `baiting`。服务端通过 `phaseContext.isRebait: boolean` 区分：
- `isRebait = false`：首次装饵（`seated → baiting`）
- `isRebait = true`：循环装饵（`resolving → baiting`），后续可跳过 `casting`

## 5. 阶段详细需求

### 5.1 `idle`

- **进入**：初始态、`disconnected` 超时、`stopping` 结束且已离席。
- **允许操作**：`take_spot`。
- **不允许**：`start_fishing`、`stop_fishing`。

### 5.2 `seated`

- **进入**：`take_spot` 成功、`stopping` 结束、任一弹窗关闭后无自动续钓。
- **允许操作**：`start_fishing`、`leave_spot`。
- **可见性**：他人可见玩家坐姿、当前装备的竿与饵图标（可选展示）。

### 5.3 `baiting`（含合并后的 rebaiting）

- **进入**：
  - `start_fishing` → 上下文 `isRebait = false`
  - `resolving` 结束（且玩家未离席、饵充足）→ 上下文 `isRebait = true`
- **入场副作用**：
  - 检查背包饵数量：`basic` 跳过；其他饵不足则**回到 `seated`** 并前端提示「饵已用完，请补充」
  - **扣除 1 个当前装备付费饵**（basic 不扣）—— §4.11 决策 5：不延迟到 waiting
- **时长**：800ms 定时器；客户端播装饵动画
- **可跳过**：管理员开关 / 玩家「快速钓鱼」偏好可将时长压至 0（保留服务端 200ms 最小值以保状态一致性）
- **结束后**：
  - `isRebait = false` → `casting`
  - `isRebait = true` 且服务端配置 `skipCastingOnRebait = true` → 直接 `waiting`
  - `isRebait = true` 且未开启跳过 → `casting`

### 5.4 `casting`

- **进入**：`baiting` 结束（未开启循环跳过时）
- **时长**：600ms
- **允许操作**：`stop_fishing`
- **结束后**：`waiting`

### 5.5 `waiting`

- **进入**：`casting` 结束、`baiting` 结束（循环跳过 casting 时）
- **服务端行为**：加入本 tick 咬钩检测名单，每 `TICK_MS = 5000` 参与一次判定
- **允许操作**：`stop_fishing`、`leave_spot`（等价先 stop_fishing 再离席）
- **超时策略**：可选「长时间无咬钩提示」（本 spec 不做，列为 P2）

### 5.6 `hooked`

- **进入**：咬钩检测中被选中
- **入场副作用**（原子操作）：
  1. `target` 鱼服务端标记为 `hookedFishId`，从本塘咬钩池排除
  2. 计算并存储 `escaped: boolean`、`hookDurationMs`、`hookEndsAt = now + hookDurationMs`
  3. 广播 `fishing_float_text { kind: 'hook', speciesId, quality }` 给同塘全体（A1 已实现）
  4. 若使用付费饵：饵已在 `baiting` 阶段扣除，此处不再扣
- **不允许操作**：`start_fishing`
- **允许操作**（§4.11 决策 2：视为脱钩）：
  - `stop_fishing`：**视为脱钩**，鱼回塘、饵不退；立即跳到 `resolving` 走 escape 分支
  - `leave_spot`：同上，且 `resolving` 结束后 `stopping → idle`
- **计时器结束**：进入 `resolving`，`outcome` 由入场时的 `escaped` 决定

### 5.7 `resolving`

- **合并**原 spec 的 `reeling`（未脱钩）与 `escaped`（脱钩）两阶段
- **携带字段**：`outcome: 'catch' | 'escape'`
- **时长**：`catch` 800ms，`escape` 600ms
- **服务端行为**：
  - `catch`：向玩家发送 `fish_bite { pondFishId, speciesId, quality, sizeM, hookDurationMs }`；鱼实体标记 `pending`
  - `escape`（§4.11 决策 1：方案 B）：
    - 广播 `fishing_float_text { kind: 'escape', ... }` 给**同塘全体**
    - 广播 `fish_miss { reason: 'escaped', speciesId, userId }` 给同塘全体
    - 提升鱼塘氛围与真实感
- **他人可见**：客户端根据 `outcome` 播放收竿或竿尖弹起的差异化动画
- **结束后**：
  - 玩家未离席、饵充足 → `baiting`(isRebait=true)
  - 玩家未离席、饵不足 → `seated` + 提示
  - 玩家已请求 leave → `stopping → idle`

### 5.8 `result`（客户端本地）

- **服务端 phase**：`resolving` 结束时服务端已切换到 `baiting`(isRebait=true) 或 `seated`
- **客户端**：`result` 仅本地 UI 态，展示 `CatchFishModal` 或空军弹窗
- **超时**：5 分钟未领取 → 服务端自动 `dismiss_catch`，鱼回塘并广播 `fish_miss { reason: 'timeout' }`

### 5.9 `stopping`

- **进入**：`stop_fishing` 事件（非 hooked 阶段）或 `leave_spot`
- **时长**：≤ 200ms（收竿短动画）
- **服务端行为**：
  - 来自 `hooked` 的 stop：**不走 stopping，直接走 resolving.escape**（决策 2）
  - 来自 `baiting/casting`：已扣的付费饵**不退**
  - 来自 `waiting`：无副作用
- **结束后**：`seated`（未离席）或 `idle`（离席）

### 5.10 `disconnected`

- **进入**：服务端 socket 断开或心跳超时
- **服务端行为**：
  - 冻结当前 phase 与所有计时器；`hookEndsAt` 保留
  - **60s 计时开始**（§4.11 决策 4：从 30s 放宽到 60s，适配移动端弱网）
  - 广播 `pond_user_updated { status: 'disconnected' }`，他人 UI 显示角色变灰
- **重连**：
  - 60s 内重连成功：恢复原 phase；若 `hookEndsAt` 已过期，立即进 `resolving`
  - 60s 超时：释放 `hookedFishId`（若有）、释放钓位、清 pending 领取、切 `idle`
- **饵/竿状态**：不因断线额外扣减；已扣的不退

---

## 6. 计时与调度

- **统一 tick 心跳**：服务端使用 100ms 全局 tick 检查所有玩家的 `phaseEndsAt`（`baiting/casting/hooked/resolving/stopping/disconnected`），触发状态转移
- **不使用零散 `setTimeout`**：便于热重启后从内存快照恢复
- **`FISH_BITE_CHECK_MS = 5000`**：仅对 `waiting` 玩家在 5s tick 边界检测咬钩，避免每 100ms 全遍历

## 8. 与经济 / 库存的绑定点

| 转移 | 副作用 |
|---|---|
| `seated → baiting(isRebait=false)` | **扣当前装备付费饵 1 个**；basic 不扣（决策 5） |
| `resolving → baiting(isRebait=true)` | **扣当前装备付费饵 1 个**；basic 不扣（决策 5） |
| `waiting → hooked` | 锁定鱼实体；不扣饵 |
| `hooked → resolving(catch)` | 鱼实体标记 pending |
| `resolving(catch) → baiting/seated` | `accept_catch` 时鱼从塘中移除，玩家背包 +1 |
| `resolving(escape) → baiting` | 鱼回塘可再被钓；饵已在 baiting 扣，不再扣 |
| 5 分钟未 `accept_catch` | 鱼自动回塘，广播 `fish_miss { reason: 'timeout' }` |
| `hooked → resolving(escape)`（`stop_fishing` 触发） | 视为脱钩：鱼回塘、饵不退、无 catch 计数（决策 2） |
| `disconnected` 60s 超时 | 释放 hookedFishId、清 pending；已扣饵不退（决策 4） |

## 9. 与飘字（A1 已交付部分）的对齐

- **飘字触发点**：
  - `waiting → hooked` 转移瞬间：广播 `hook` 类飘字（全塘）
  - `hooked → resolving(escape)` 时：广播 `escape` 类飘字（**全塘**，决策 1）
- **本节状态机上线后**：飘字触发函数无需改动，仅调用位置从「A0 咬钩判定成功那一刻」迁移到「`hooked` 阶段入场钩子」，函数签名保持不变
- **兼容性**：A1 已实现的客户端 `FishingFloatText.tsx` 组件无需修改

---

## 10. 与 Bot 的对齐

- Bot 走同一状态机，但可省略 `baiting/casting/stopping` 的动画时长（服务端配置 `botSkipAnimationPhases = true`），直接 `seated → waiting` 或 `waiting → seated`
- Bot 不会进入 `disconnected`
- Bot 咬钩后同样触发飘字广播，保持鱼塘热度感

## 11. 客户端渲染契约

| 阶段 | 期望视觉表现 |
|---|---|
| `idle` | 玩家站立行走 idle |
| `seated` | 坐在钓点，手持竿 idle |
| `baiting` | 低头装饵（`isRebait=true` 可选缩短动画） |
| `casting` | 甩竿向前 |
| `waiting` | 竿尖微动，水纹 |
| `hooked` | 竿身弯曲抖动 + 头顶飘字（A1 已交付飘字部分） |
| `resolving(catch)` | 后仰拉杆 |
| `resolving(escape)` | 竿尖弹起 + 全塘 escape 飘字 |
| `stopping` | 收竿短动画 |
| `disconnected` | 角色变灰 idle |

**契约保证**：客户端渲染代码遇到未识别的 `fishingPhase` 时**必须回退到 `seated` 视觉**，保证前后端可独立发版。
