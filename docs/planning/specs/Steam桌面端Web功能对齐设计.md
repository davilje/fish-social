## 1. 目标与原则

Steam 版复刻 Web 端的功能和数据语义，但不逐个平移移动端页面。

- Web 端是功能、字段、权限和服务端交互的基准。
- Steam 版采用 `1280×720` 主窗口 + **底部横向页签**。好友/聊天、背包、图鉴、设置是主窗口内容页，**不再使用盖在主窗口上的功能弹窗**。
- 鱼塘场景、自己的猫和同塘玩家仍由 Overlay（07B/07C/07G）承载。
- Overlay 右键菜单只负责唤起主窗口并切到对应页签，不在 Overlay 内画功能页。
- 不新增第二套业务规则、库存计算、好友权限或聊天协议。
- 打开、关闭、切换页签不得触发 `leave_pond`，不得重建鱼塘会话或 Overlay。

## 3. 页签功能规格

### 3.1 好友与聊天

#### 鱼塘社交

- 显示在线钓友数量、昵称、头像和基础钓鱼状态。
- 点击用户可打开资料摘要，不离开当前鱼塘。
- 显示鱼塘公共聊天消息和系统公告。
- 支持输入、发送和发送中状态；鱼塘聊天文本上限为 200 字。
- 空消息、发送失败、断线和重新连接必须有明确提示。

#### 好友与邀请

- 显示好友列表和在线状态。
- 显示待处理好友请求，支持接受、拒绝和移除好友。
- 支持邀请好友进入当前鱼塘。
- 好友权限继续由服务端判断，客户端不得绕过好友关系。

#### 私聊

- 显示好友会话列表、最近消息和当前会话。
- 支持加载历史消息、发送私聊和接收实时 `dm_message`。
- 私聊仅允许好友之间发送，文本上限为 300 字。

### 3.2 鱼获与背包

- 至少显示 80 个背包格子和实际占用数量。
- 每个鱼获显示鱼种图标、名称和品质。
- 选中鱼获后显示鱼种、品质、体长和出售价格。
- 显示金币余额。
- 支持出售鱼获和分享到动态；操作完成后以服务端返回结果刷新。
- 支持加载中、空背包、请求失败、权限拒绝和重试状态。
- 客户端不得自行修改库存、金币或出售价格。

### 3.3 图鉴

- 显示鱼种网格和已解锁数量。
- 已解锁鱼种显示图标、名称和详情。
- 未解锁鱼种显示锁定状态，不显示不应公开的详细结果。
- 详情至少包括：食性、基础咬钩信息、脱钩率、累计捕获、最大体型、首次捕获时间、推荐鱼饵 Top3。
- 打开时从服务端加载玩家图鉴；收到 `codex_unlocked` 后允许刷新。
- 无玩家身份、加载失败和空数据必须有明确提示。

### 3.4 设置

第一阶段只实现窗口和通知设置：

- 窗口模式、普通窗口尺寸、无边框/全屏入口。
- 关闭窗口后的托盘行为。
- 鱼咬钩通知开关。
- 好友邀请通知开关。
- 免打扰开关。

设置变更只影响本地窗口和通知表现，不修改鱼塘规则、库存或服务端状态。

## 4. Steam 桌面交互

```text
Overlay 右键菜单 / 主窗口底栏
    ├─ 当前鱼塘     → 显示主窗口 + 鱼塘页签
    ├─ 好友与聊天   → 显示主窗口 + 好友/聊天页签
    ├─ 鱼获/背包    → 显示主窗口 + 背包页签
    ├─ 图鉴         → 显示主窗口 + 图鉴页签
    └─ 设置         → 显示主窗口 + 设置页签
```

- 底栏与 Overlay 菜单走同一条 `PanelRouter.Show(ShellPanelId)`，禁止再 `Open` 功能弹窗。
- 07A 页签里的占位文案由本需求的真实数据页替换，不得两套并存。
- 切换页签不得跳转移动端多级路由，不得 `leave_pond`。
- 从 Overlay 恢复主窗口时，不得重复启动进程、重复创建 Overlay 或重复订阅鱼塘。

### 4.1 主窗口必须高于 Overlay（P0）

Overlay 默认 `Topmost`。仅 `ShowFromTray` / `Focus` **不够**：主窗口会被 960×480 Overlay 挡住。

**规则：** 用户从 Overlay 右键菜单（或等价入口）打开主窗口后，**主窗口在 z-order 上必须盖住 Overlay**，功能页完整可见、可点，不得被鱼塘 Overlay 遮挡。

| 状态 | 层级 |
|------|------|
| 仅 Overlay 挂机（主窗口隐藏/托盘） | Overlay 保持置顶陪伴 |
| 主窗口因菜单/底栏被唤起且可见 | 主窗口高于 Overlay |
| 主窗口再次隐藏到托盘或关闭（按现有生命周期） | Overlay 恢复置顶 |

实现约束（任选，验收看结果）：

- Unity 通知 Overlay 让出置顶（Pipe 状态字段或命令，例如 `mainWindowRaised` / `yield_topmost`），主窗口 `Show` + 聚焦；或
- 短暂提升主窗口 `HWND_TOPMOST`，并保证叠在 Overlay 之上，**不得**让主窗口永久置顶挡住整个桌面。

禁止：为了躲开 Overlay 再开一层功能弹窗；销毁或重启 Overlay；把 Overlay 挪到屏幕外当作“不挡”。

### 4.2 主窗口 UI 预制体

当前壳层由 `DesktopShellUi` 运行时拼 uGUI。07E 应将主窗口壳与各功能页做成 Editor 预制体（如 `DesktopShell.prefab` + `PanelSocial` / `PanelCatch` / `PanelGallery` / `PanelSettings`），脚本只绑定数据与切页。

- Overlay（WPF）不实例化这些 Prefab。
- 与 `STEAM-DESKTOP-ART-02` 的 960×480 Overlay 布局 Prefab 分开，不要混用。

## 5. 数据与事件对齐

### REST

| 类型 | Web 基准 | Steam 用途 |
|---|---|---|
| GET | `/api/inventory/:playerId` | 背包和鱼获 |
| GET | `/api/player/codex?playerId=...` | 图鉴 |
| GET | `/api/friends/:playerId` | 好友列表 |
| GET | `/api/friends/:playerId/requests` | 好友请求 |
| GET | `/api/dm/:playerId/:friendPlayerId` | 私聊历史 |
| POST | 现有好友请求/接受/拒绝/移除接口 | 好友管理 |
| POST | `/api/inventory/sell` | 出售鱼获 |
| `/api/players/:playerId/settings` | 现有设置接口 | 玩家设置；窗口本地设置另行保存 |

所有受保护请求必须沿用 Steam JWT，统一处理 `401/403`、超时、断线和服务端错误。

### Socket 事件

| 事件 | 用途 |
|---|---|
| `chat_message` | 鱼塘公共聊天和公告 |
| `inventory_updated` | 收鱼、出售后刷新背包 |
| `codex_unlocked` | 刷新图鉴解锁状态 |
| `friend_request` | 更新好友请求 |
| `dm_message` | 更新私聊会话 |
| `pond_user_joined/left/updated` | 更新在线钓友状态 |

各页签不得分别创建 Socket 连接，统一消费已有桌面会话层事件。

## 6. 非目标

- 不把 Web 动态墙、好友 Feed、排行榜、商店直接并入 07E。
- 不复制 Web 的移动端路由、页面导航和响应式布局。
- 不在 Unity 客户端重写服务端鱼获、经济、好友权限或聊天规则。
- 不因页签切换离开鱼塘或重新认证。
- 不在 Overlay 内实现好友/背包/图鉴/设置整页。
- 不把主窗口做成永久桌面置顶宠物（那是 Overlay 的职责）。
- 不在本设计中替换原生 Overlay 进程或 Named Pipe 架构。

## 7. 验收标准

- [x] 主窗口底栏打开四类**页签**（不是功能弹窗）。
- [x] Overlay 右键对应项：显示主窗口并切到同一页签；不 `Open` `DesktopModalHost` 功能层。
- [x] **从 Overlay 菜单唤起后，主窗口视觉上高于 Overlay，功能页不被 Overlay 挡住。**
- [x] 主窗口隐藏到托盘后，Overlay 恢复置顶陪伴。
- [x] 好友列表、好友请求、鱼塘聊天和私聊使用真实服务端数据。
- [x] 鱼塘聊天限制 200 字，私聊限制 300 字。
- [x] 背包至少显示 80 格、金币、选中鱼获详情，并能处理出售结果。
- [x] 图鉴显示解锁状态、鱼种详情和推荐鱼饵。
- [x] 设置可以修改窗口/托盘/通知表现。
- [x] loading、empty、error、401/403、断线和重试状态清晰。
- [x] `inventory_updated`、`codex_unlocked`、`friend_request`、`dm_message` 能更新对应页签。
- [x] 关闭主窗口或切换页签不触发 `leave_pond`，不清空鱼塘和 Overlay 状态。
- [x] 不重复创建 Socket、鱼塘会话或 Overlay。
- [x] 主窗口壳与功能页以 Prefab 承载（或已从运行时拼装迁到 Prefab），不再维护一套 Modal 副本。
