## 0. 文档目的

`v0.4.4-patch` 已落地 `phase_transition_invalid`、P2 性能日志、`verify-pending-timeout` 等能力，但**埋点表（xlsx）与代码仍未完全对齐**。

本补丁用于：

1. 复核当前 33 条埋点的真实落地情况
2. 补齐仍缺失的 3 条埋点
3. 统一 2 条 eventType 命名与表内约定
4. 补全 `slow_query` 字段、慢测验收说明
5. 同步更新 xlsx「状态」列，避免策划/排查误判

**埋点表格式标准**（后续更新一律遵守）：

- 文件：`docs/planning/reports/v0.4.4-埋点表清单.xlsx`
- Sheet：总览 + 连接与会话 / 钓位与鱼塘 / 状态机 / 咬钩与产出 / 性能 / 慢测验证
- 列顺序：类别 · 事件名 · 类型 · 触发时机 · 必填字段(核心) · 示例 payload JSON · 优先级 · 状态 · 推荐落点文件
- 必填字段：每个字段单独一行，末尾保留两个空行；单元格 `wrap_text`

## 2. 修改建议（策划决策）

### 2.1 eventType 对齐策略：**写入表内 canonical 名，summary 兼容旧名**

避免破坏已有 timeline/报表查询：

1. **新写入**统一使用表内 eventType：`socket_disconnect`、`pending_catch_accept`
2. `FishingMetricEvent` union 增加上述类型；**保留** `disconnect`、`catch_accept` 类型定义（只读兼容）
3. `getFishingMetricsSummary` / `getPlayerFishingTimeline` summary 的 `switch`：**新旧 eventType 合并计数**
4. `pending_catch_accept` payload 补全表要求的 `sizeM`（当前仅 `speciesId`、`quality`）

**不采用**双写两条 metrics 记录（避免 SQLite 膨胀）。

### 2.2 `sqlite_query_slow` 与 `slow_query`

同一慢查询命中时：

1. 主 eventType 使用表内名 **`sqlite_query_slow`**
2. 日志行额外保留 **`[slow_query]`** 前缀一行（向后兼容 grep/日志采集）
3. 或单行 JSON 内 `eventType: sqlite_query_slow` + `alias: slow_query`（二选一，推荐前者 + 兼容日志前缀）

### 2.3 `snapshot_build_duration_ms` 采样策略

`buildSnapshot` 调用频繁（join、每秒广播、perf tick）。建议：

1. 在 `buildSnapshot` 内计时
2. 仅当 `shouldLogPerf` 同类节流（复用 `PERF_LOG_INTERVAL_MS`，默认 10s）输出一条聚合日志
3. 字段：`durationMs`, `pondId`, `userCount`, `ts`

可选：热路径仅在 `index.ts` 包装一层计时，但会漏 `fishingDebug` 调用；**推荐在 `gameState.buildSnapshot` 内统一包装**。

### 2.4 `session_rebound` 触发点

| 场景 | 触发时机 | 必填字段 |
|------|----------|----------|
| 注册绑定 | `register_player` 且 `playerSockets` 已有旧 socketId 或发生覆盖 | `playerId`, `socketId`, `previousSocketId?`, `ts` |
| 重连绑定 | `join_pond` reconnect 分支，`socketByUserId.set` 之前 | `playerId`, `userId`, `socketId`, `pondId`, `ts` |

类型：**结构化日志**（表内未要求 metrics）；若实现简单可同步 `recordStructuredMetric`，非必须。

### 2.5 慢测验收

1. 保持 `verify:pending-timeout` 默认快测 SKIP
2. 在 `verify-server-observability.ts` 末尾增加 **文档性断言**：检测 `verify-pending-timeout.ts` 存在且 `package.json` 有 script（不跑真实等待）
3. README/CHANGELOG 注明完整验收需：`npm run verify:pending-timeout -- --slow`

## 3. 需求明细

### 3.1 `session_rebound`（P1）

**R1** `register_player`：当 `playerSockets.set(playerId, socket.id)` 且旧值存在且不等于新 socketId 时，打：

```json
{
  "eventType": "session_rebound",
  "ts": 1783500000800,
  "playerId": "p_123",
  "socketId": "s_456",
  "previousSocketId": "s_123",
  "reason": "register_player"
}
```

**R2** `join_pond` reconnect 成功分支：在 `socketByUserId.set` 前打 `session_rebound`，含 `userId`、`pondId`。

**R3** 验收：跑 `verify-server-observability` 或新增轻量用例，模拟双 socket 注册可见日志。

---

### 3.2 `snapshot_build_duration_ms`（P2）

**R4** 包装 `buildSnapshot`，节流输出：

| 字段 | 必填 |
|------|------|
| `eventType` | 是 |
| `durationMs` | 是 |
| `pondId` | 是 |
| `userCount` | 是 |
| `ts` | 是 |

**R5** 验收：启服 10s 后日志可见至少 1 条。

---

### 3.3 `sqlite_query_slow` + `slow_query` 字段（P2）

**R6** `timedDbQuery` 超阈值时：

- 若结果为数组，`rows = result.length`
- 日志 `eventType` 用 `sqlite_query_slow`
- 保留 `[slow_query]` 日志前缀或 `alias` 字段

**R7** 验收：人为降低 `SLOW_QUERY_MS` 或查询大 timeline，可见 `rows` 字段。

---

### 3.4 eventType 对齐（P1）

**R8** `handleDisconnect`：`recordFishingMetric('socket_disconnect', ...)` 替换 `disconnect`。

**R9** `accept_catch`：`recordFishingMetric('pending_catch_accept', ...)` 替换 `catch_accept`，payload 含 `sizeM`。

**R10** summary/timeline 计数兼容旧 event_type 行。

---

### 3.5 埋点表 xlsx 同步（必须）

**R11** 按 §1.4 更新「状态」列；`socket_disconnect` / `pending_catch_accept` 对齐后去掉「兼容 xxx」备注。

**R12** 不破坏现有列顺序与必填字段换行格式。
