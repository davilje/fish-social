## 1. 现象

1. 在鱼塘点「← 地图」**没反应**，页面仍停在鱼塘场景。
2. 此后点「开始钓鱼」提示 **「请先加入鱼塘」**，鱼塘功能全部失效（死屏）。
3. 有时自己从在场列表消失，底栏剩余又变回满额（其实是 `me` 已丢失的假象）。
4. 点「收起鱼竿」后按钮**闪烁两下**（收起鱼竿 →「...」→ 收起鱼竿 → 开始钓鱼）；开始钓鱼时也有一次同类跳变。

非本单：时长不入库见 **BUG-16**（后端）。

---

## 2. 根因（定案）

### 2.1 先毁会话、后导航

```ts
const handleLeaveToMap = useCallback(() => {
  leavePondWithReason('navigation_back');
  router.back();
}, [leavePondWithReason, router]);
```

`leave_pond` 一发出，服务端立即删除 session / 内存用户 / checkpoint；而 `router.back()` 在**无历史记录**（Web 直接打开、刷新、深链进入）时是 no-op，页面留在原地 → 「已离塘但没走成」。

### 2.2 离塘闩锁不可复位

`emitLeavePond` 用 `leftPondRef.current` 做一次性闩锁，且 socket effect 依赖 `[pondId, nickname, playerId, emitLeavePond]` 不变，**不会重新 join**。于是 2.1 之后客户端永远回不到有会话状态，任何操作都被服务端判为「请先加入鱼塘」。

### 2.3 自身条目被移除造成额度错觉

服务端广播 `pond_user_left` 后客户端把自己从 `users` 移除，`me` 变为 `undefined`；`remainingDailyFishingMs(undefined, ...)` 按已用 0 计算返回满额，看起来像「额度刷新了」，实际只是死屏。

### 2.4 相位中间态直接驱动按钮

- 开始钓鱼：服务端先广播占位后的 `seated`（非活跃 → 按钮「开始钓鱼」），紧接着广播 `baiting`（→「收起鱼竿」）
- 收起鱼竿：先进 `stopping`（200ms，仍属活跃 → 仍显示「收起鱼竿」），200ms 后才 `seated`

叠加本地 `actionLoading` 的「...」，按钮在 ~300ms 内跳变 2～3 次。

## 3. 修复方案（定案）

**导航优先、会话可恢复、中间态收敛。**

| # | 改动 | 说明 |
|---|------|------|
| 1 | **先导航、后离塘** | `router.canGoBack() ? router.back() : router.replace('/')`；确认导航生效后再发 `leave_pond`（或统一在卸载时发） |
| 2 | **闩锁可复位** | 页面仍挂载却已离塘时允许复位 `leftPondRef` 并重新 `join_pond`，禁止出现「有 socket 无 session」的死态 |
| 3 | **死态自愈** | 收到 `请先加入鱼塘` / `me` 丢失且页面仍在鱼塘时，自动重新 join 一次并提示 |
| 4 | **社交出口口径统一** | `handleLeaveToSocial` 按 **BUG-06**「切页不误离塘」保持会话，但必须保证鱼塘页卸载时不静默断连丢会话（与 BUG-16 联动） |
| 5 | **按钮中间态** | `stopping` 期间显示「收杆中…」并禁用；开始钓鱼 ack 后到进入活跃相位前保持 pending，不回落成「开始钓鱼」 |

### 非目标

- 不改服务端结算逻辑（BUG-16 负责）
- 不改 8h 上限与底栏插值语义
- 不重做鱼塘导航栈结构

## 4. 验收标准

- [x] Web 直接打开 `/pond/<id>`（无历史）点「← 地图」：**能回到地图**（无历史时走 replace 首页）
- [x] 点返回后再进鱼塘：可正常开始钓鱼，不再出现「请先加入鱼塘」
- [x] 若离塘后页面仍停留在鱼塘：**自动重新加入**，功能可用（不需要手动刷新）
- [x] 从鱼塘进社交再返回：会话保持，钓鱼相位与秒表连续（BUG-06 口径）
- [x] 点「收起鱼竿」：按钮显示 `收杆中…`（禁用）→ `开始钓鱼`，**无来回闪烁**
- [x] 点「开始钓鱼」：按钮从 pending 直接进入 `收起鱼竿`，中途不回落
- [x] 回归：BUG-13 头顶秒表不闪 0；BUG-14 钓鱼中剩余逐秒下降

## 6. 风险与依赖

| 风险 | 缓解 |
|------|------|
| 重新 join 造成重复占位 | 服务端 join 已有 reconnect / checkpoint 分支；客户端仅在无 session 时触发一次 |
| 与 BUG-06「切页不 leave」冲突 | 明确：切页保持会话，只有显式返回地图才离塘 |
| 按钮 pending 卡住 | pending 设超时（如 3s）回落到服务端相位为准 |
