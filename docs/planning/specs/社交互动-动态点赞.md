## 1. 背景与目标

### 1.1 背景

动态墙（`PostCard`）目前只能查看：头像、文案、纪念照、品质。发布后无反馈闭环，分享动力弱。

### 1.2 目标

- 对可见动态点赞 / 取消点赞（toggle）
- `PostCard` 显示点赞数与「我是否已赞」
- 可查看点赞用户列表（P1）
- 墙面可选按赞数排序（P1）

### 1.3 非目标

- 不做踩（dislike）
- 不做系统推送 / 站内信「有人赞了你」（仅 Socket 实时刷新 UI）
- 不做点赞排行榜、不做表情反应多类型

---

## 2. 用户与场景

| 角色 | 场景 | 期望 |
|------|------|------|
| 玩家 | 动态墙看到公开鱼获 | 点 ❤️ → 变红、计数 +1；失败回滚 |
| 玩家 | 再次点击 | 取消赞，计数 −1 |
| 玩家 | 刷新 / 重进社交页 | 赞状态与计数保持 |
| 玩家 | 好友动态流 / 他人主页动态 | 仅对**当前可见**的帖可赞 |
| 玩家 | 点赞数 | 打开点赞用户列表（头像+昵称） |

## 3. 功能范围

### 3.1 功能列表

| # | 功能点 | 优先级 | 说明 |
|---|--------|--------|------|
| 1 | 点赞 / 取消 | P0 | toggle；JWT 鉴权 |
| 2 | 计数 + likedByMe | P0 | 列表接口带回 |
| 3 | 持久化 | P0 | `post_likes` + `like_count` |
| 4 | 点赞用户列表 | P1 | 分页 |
| 5 | 按赞数排序 | P1 | `GET /api/posts/wall?sort=likes` |
| 6 | Socket 刷新 | P0 | `post_liked` 推给在线客户端 |

### 3.2 交互与 UI

**`PostCard` 底部操作栏**（与评论同迭代共用一行）：

```text
[❤️ n]  [💬 m]
```

- 未赞：灰色心；已赞：红色心（可短缩放动画）
- 点击心：乐观更新，请求失败回滚并 Toast/Alert
- 点击数字区域（P1）：点赞用户列表弹层（可复用简易列表，点头像 → `UserProfileModal`）
- 无赞时仍显示 `0`，不隐藏

**可见性**：只能对当前接口已返回的帖点赞；对不可见帖返回 `404`（不泄露存在性）。

### 3.3 规则

- 每玩家每帖至多 1 赞（复合主键）
- 允许赞自己的帖
- 无冷却、计数无上限
- Bot 帖（`player_id` 以 `bot-` 开头）**允许被赞**；Bot **不主动点赞**

## 4. 技术影响

### 4.1 数据模型

```sql
CREATE TABLE post_likes (
  post_id TEXT NOT NULL,
  player_id TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  PRIMARY KEY (post_id, player_id)
);
CREATE INDEX idx_post_likes_post ON post_likes(post_id, created_at DESC);

-- social_posts 增量
ALTER TABLE social_posts ADD COLUMN like_count INTEGER NOT NULL DEFAULT 0;
```

`like_count` 与表行数保持一致：点赞 `+1` / 取消 `-1`（事务内）；可选启动时 reconcile。

### 4.2 类型（`shared/social.ts`）

```ts
export interface SocialPost {
  // ...existing
  likeCount: number;
  commentCount: number; // 评论规格一并加；点赞单独上线时可先恒 0
  likedByMe?: boolean;  // 需带 viewer；未登录省略或 false
}

export interface PostLikeUser {
  playerId: string;
  nickname: string;
  avatarUrl?: string;
  likedAt: number;
}
```

Socket（`shared/types.ts`）：

```ts
post_liked: (payload: {
  postId: string;
  playerId: string;
  liked: boolean;
  likeCount: number;
}) => void;
```

### 4.3 API

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/api/posts/:postId/like` | `requireAuth` | toggle；**playerId 以 JWT 为准**，禁止信任 body |
| GET | `/api/posts/:postId/likes` | 可选登录 | `limit`/`offset`；校验可见性 |
| GET | `/api/posts/wall` | 可选 | 扩展返回 `likeCount`/`likedByMe`；`sort=time\|likes`（默认 time） |
| GET | `/api/posts/friends/:playerId` | `requireSelf` | 同上字段 |

**POST like 响应**：`{ liked: boolean, likeCount: number }`

**错误**：帖不存在或不可见 → `404`；未登录 → `401`。

### 4.4 涉及文件（预估）

- `shared/social.ts`、`shared/types.ts`
- `server/src/posts.ts`、`socialRoutes.ts`、migration、`playerPrivacy.ts`（导出/删除含 likes）
- `mobile/components/PostCard.tsx`、`mobile/lib/socialApi.ts`、`mobile/app/social.tsx`

### 4.5 隐私

- 导出：用户发出的 `post_likes` 行
- 删除账号：删该用户 likes，并回减对应 `like_count`

## 5. 验收标准

- [ ] JWT 用户可对可见帖 toggle 点赞；❤️ 与计数正确；失败回滚
- [ ] 刷新后 `likedByMe` / `likeCount` 正确
- [ ] 墙 / 好友流 / 他人主页动态列表带计数
- [ ] Socket `post_liked` 到达同页其他在线客户端（或至少作者在线时计数更新）
- [ ] （P1）点赞用户列表可打开并跳转资料
- [ ] （P1）`sort=likes` 按 `like_count DESC, created_at DESC`
- [ ] 隐私删除用户后 likes 清理且计数不漂移

## 6. 风险与依赖

| 风险 | 缓解 |
|------|------|
| 并发双击 | UNIQUE 主键 + 事务；二次 toggle 幂等 |
| count 漂移 | 写路径事务；可选 Admin reconcile |
| 与评论抢 UI | 同迭代统一操作栏，避免两次改 PostCard |

**依赖**：现有 `social_posts`、JWT；评论规格可并行，共享操作栏。
