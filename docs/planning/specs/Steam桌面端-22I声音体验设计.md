## 1. 声音方向

「安静的水边，轻轻翻开手账」。UI 是短纸张／木质轻点；水声柔和、尾音短；咬钩比入水清晰、音高略上扬；收获是一次短暖音，自动猫叫稍后回应。避免尖锐金属警报、每个发力帧都响、每轮打窝都重复大音量撒料声。

保留当前《池畔晴日》与三种已有猫叫、原授权和本地离线播放；本轮不另做长 BGM、不增加环境音常驻循环。新增候选是 bite/reel/escape/groundbait 四种 WAV，不等同于四套整包风格；用户未选择的候选不自动覆盖正式音频。

## 2. 现状与本次设计增量

已有 `policy.json` 是试听参数，当前正式播放器仍以 cue 冷却和 PlayOneShot 为主。实现需要补事件级去重、并发声部、动画实际显示标记和统一 UI 语义。

旧审计称结果 ID 缺失；本次读到当前服务端／Unity DTO 已有 `catchId`、失败 `resultId`，但正在并行开发，尚不能认定完整链路可靠。以实现时的 commit 核验 ACK／结算／自动回鱼／IPC 的一致性，优先复用，不能照旧文档重新造 ID。

[原试听审计](../../engineering/2026-10-24-audio-22i-preview.md) 保留为历史证据；本设计补齐生产规则，不把浏览器试听通过等同于游戏端去重或同步已完成。

## 3. 音效触发和制作表

增益均相对于「音效与猫叫」滑杆，最终音量 = 滑杆 × cue 增益 × 淡入淡出，不修改用户保存值。

| cue | 声音／建议时长 | 唯一触发点 | 增益／优先级 |
|---|---|---|---|
| ui_click | 木质纸面点按，40–90ms | 有效提交／普通按钮动作 | .65／1 |
| ui_open / ui_close | 纸页轻展开／收合，90–180ms | 页面实际开始开／合，一次导航只播此项 | .65 / .60／1 |
| ui_toggle | 纸签轻扣，50–100ms | 选项值确实变化 | .60／1 |
| ui_tick | 极轻刻度，≤60ms | 用户拖动音量滑杆，至少隔 180ms | .45／0 |
| ui_success / ui_error | 柔和确认／低短双音，≤300ms | 真实操作结果；同一操作 ID 一次 | .65／2 |
| cast | 短空气挥动，150–260ms | 自己 cast.release 画面标记 | .80／1 |
| splash | 小滴落入水，160–300ms | float.contact，和 H 的 FX01 同源 | .65／1 |
| bite（候选） | 两个紧凑水滴＋短上扬提示，180–320ms | 新权威咬钩且当前有效画面可见 | .90／3 |
| reel（候选） | 轻收线／线轮，220–400ms | retrieve.start 一次，不按帧循环 | .65／1 |
| escape（候选） | 短下落水声，180–300ms | resultId 确认逃脱＋对应表现标记 | .60／2 |
| groundbait（候选） | 小颗粒落水，120–220ms | 撒饵接触点，每三轮最多一次且间隔 ≥2.16s | .50／0 |
| catch | 温暖双音，350–600ms | 同一 catchId 的结果确认与展示节点均具备 | .80／3 |
| meow_01–03 | 沿用现有三种变体 | 手动有效点击／成功后自动回应 | .65／1 |

UI 全局 90ms 间隔；同一次导航不叠 click+open。声音资源可先保留当前时长，表中为本轮制作目标，超出需审听记录理由。

**事件身份优先于冷却：**同 ID 绝不重播；不同权威咬钩或鱼获不能被旧 cue 冷却误吞，受有限声部仲裁。试听 policy 中 bite .8s、catch 1.2s 等只作为无身份的预览节流，正式关键事件不能据此跳过新的真实结果。普通 UI 和撒饵仍保留节流。

## 4. 声部、优先级和音乐

- 1 个音乐声部；短音最多 4 个（UI 1、钓鱼 2、猫叫 1）。实际用受控 AudioSource 池，不能继续用无限 PlayOneShot 叠加来声称满足上限。
- 同组满额：高优先级替换最低优先级；同级关键结果替换最旧的同类，40ms 淡出。低优先级丢弃，不排队补播历史声音。
- 咬钩 > 收获（同属 3，咬钩有时间敏感性）> 脱钩 > 动作 > 撒饵。同塘其他玩家自动声音继续为零。
- 咬钩音乐乘 .5 保持 .7s，收获保持 1.2s；80ms 降低、250ms 恢复。重叠取最小乘数和最晚结束，不累乘，不提前恢复，不改变保存音量。
- 手动猫叫 ≥2.5s，三变体避免连续重复；自动庆祝猫叫 ≥12s 且遵守全局 2.5s，下一个空闲 voice 声部才可发。庆祝音结束后 120ms 播放；期间换塘、离席、取消或又有咬钩则丢弃，不排队。
- 音乐仍沿用当前托盘播放习惯。新增「后台咬钩提示」开关默认开启：窗口全部隐藏时，只允许新且仍有效的自己咬钩提示一次；无普通 UI、挥竿、水花、撒饵、自动猫叫。音效音量为 0 优先于后台提示。恢复窗口不能重播该事件。
- 原生 Overlay 可见、Unity 主窗口隐藏不算后台静默；焦点在其他应用但 Overlay 可见仍按正常桌宠模式。后台策略依据可见性和用户开关，不仅依据 Unity focus。

## 5. 同步、失败与生命周期

共用 [表现契约](../../design/ui/steam-desktop-22hij/presentation-contract.md)。WPF 只发送语义 marker，Unity 校验会话、角色、当前 owner、事件身份后播放；杜绝把任意文件路径或任意 cue 从 IPC 直接放行。

入水与咬钩不再共用 splash；收获 ACK 与结算合并到同一 catchId。开页导航失败不播 open；收费／入包失败只播一次 ui_error，不先成功后补失败。普通停钓无 escape，若权威确认为 escaped 则按真实结果处理。

后台提示是“等待可见动画标记”规则的唯一例外：所有窗口隐藏时由 Unity 消费新权威 bite，一次发声并记录相同去重键，恢复可见后 WPF 标记不得再响；如果截止时间已过则省略。首次／重连快照不属于新事件，仍静默。

首次／重连快照静默设基线；音频资源失败不阻断游戏，缺 cue 省略并记一次诊断，不用更响的系统音代替。停止／换塘关闭当前动作 pending marker，短音 40–80ms 淡出，音乐按现有导航逻辑保留。

静音仍消费事件，调回音量不补发。旧协议无事件标记时禁用新的动作音路径，最多保留一次受控的 UI 反馈；不能让 Unity 阶段音和 WPF marker 双路同时存在。

## 6. 资源与音频质量

- 复用 14 个正式音频及 CREDITS；4 个候选先留在 `docs/art/audio-22i/assets/`。评审后替换／增加正式资源，并更新 StreamingAssets manifest、SHA-256、来源与许可记录。
- 沿用 PCM 16-bit、44.1kHz；短音单声道，BGM 立体声流式。新增短音解码内存 ≤4MiB，不为变体加载多个长文件。
- 无削波、无首尾爆音，至少 5ms 边缘淡化；素材峰值设计上限 −3dBFS，混音保留余量。不得将所有短音硬归一到同一响度；响度通过同一系统音量下的试听调校。
- 现有音乐的循环边界与静音／持久化测试必须保留；新音乐或环境声是独立后续项。

## 7. 试听与实施顺序

沿用六场景：正常钓鱼、脱钩／停钓、持续打窝、快速 UI、重复消息、8 人同塘。追加“两个不同 catchId 间隔小于旧冷却”、“全部窗口隐藏但新咬钩有效”、“音乐压低期间静音再恢复”三种边界。试听台须标注演示数据，不能宣称实测 IPC。

先统一事件身份与音频仲裁，再接真实动画 marker，再导入已认可候选，最后与 H 同录验证；不先大批换 WAV 掩盖重复／抢跑问题。
