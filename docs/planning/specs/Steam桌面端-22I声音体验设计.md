## 2026-10-24 v3 听感修订（历史制作记录）

## 1. 声音方向

「安静的水边，轻轻翻开手账」。操作声音优先取自纸张、书页、纸签、铅笔、印章等手账物体；音乐用柔和轻缓的器乐；水花须有真实、清晰的落水瞬态与回落尾声，较旧方案更响、更有水体感。

- **操作音**：翻页就是书页翻动，选项是纸签拨动，确认是轻印章／纸面落笔。普通点击不用电子哔声、数字按键音或所有按钮共用硬木敲击；木质物音只作为有具体物件对应的辅声。
- **音乐**：优先柔音钢琴、尼龙弦木吉他、低音区轻拨弦和少量柔弦乐。轻缓节奏、留白、温暖中低频；排除尖锐电子主旋律、芯片音、明亮金属铃／高频木琴反复敲击、重鼓点和突兀高潮。数码采样制作可以使用，但最终听感必须像自然乐器，不能靠“合成器”音色充数。
- **水声**：使用真实录制或可信物理拟音的滴落、拍水、翻水与回落。不能以正弦音、上扬提示音、夸张卡通“啵”代替。小鱼轻脆短促，大鱼更厚、更宽且有回流水；大鱼不是把小滴声调低音高再加音量。

当前《池畔晴日》和4个候选仅作为旧版比较基线，**不默认保留为v2合格成品**；先审听并重做不符音色。音乐修订纳入22I：优先重配现曲，若核心音色仍不符再替换一首同用途循环曲。保留已授权猫叫、播放器、独立音量、离线分发；不增加多场景配乐包或常驻环境噪声。设计时未生成新音频；2026-10-24 开发已交付 [v2 试听](../../art/audio-22i/v2/index.html) 与正式资源，旧版冻结比较；听感仍须人工验收。

## 2. 现状与本次设计增量

已有 `policy.json` 是v1试听参数，未包含本次纸张物音、器乐和分档水声修订；不能作为v2音色验收。现有六场景仍可用于交互比较。设计基线播放器以 cue 冷却和 PlayOneShot 为主；本次实现已替换为事件去重、四短音受控声部、实际显示 marker 与统一 UI 语义，见 [实现验证报告](../../engineering/2026-10-24-audio-22i-v2.md)。

旧审计称结果 ID 缺失；本次读到当前服务端／Unity DTO 已有 `catchId`、失败 `resultId`，实现核验发现基线咬钩／ACK／settled 透传不完整，已把已有 catchId 提前到权威咬钩并贯穿待领取、ACK、结算和自动回鱼，失败复用同一次尝试 ID；后端集成测试覆盖该链路，不另造平行结果 ID。

[原试听审计](../../engineering/2026-10-24-audio-22i-preview.md) 保留为历史证据；本设计补齐生产规则，不把浏览器试听通过等同于游戏端去重或同步已完成。

## 3. 音效触发和制作表

增益均相对于「音效与猫叫」滑杆，最终音量 = 滑杆 × cue 增益 × 淡入淡出，不修改用户保存值。

| cue | 声音／建议时长 | 唯一触发点 | 增益／优先级 |
|---|---|---|---|
| ui_click | 指腹轻触纸面／小纸片轻落，45–100ms | 有效提交／普通按钮动作 | .50／1 |
| ui_open / ui_close | 单页翻开／纸本轻合，140–300ms；弹层用短纸片抬起／落下变体 | 页面实际开始开／合，一次导航只播此项 | .60 / .55／1 |
| ui_toggle | 纸签滑动／卡片轻拨，60–140ms | 选项值确实变化 | .50／1 |
| ui_tick | 铅笔短擦纸／纸边轻拨，40–80ms | 用户拖动音量滑杆，至少隔180ms；不为每个数值发声 | .35／0 |
| ui_success / ui_error | 轻盖章／纸片轻退回，100–220ms；无电子确认和错误警报 | 真实操作结果；同一操作ID一次 | .55 / .50／2 |
| cast | 自然挥竿的短风切／鱼线摩擦，150–260ms | 自己cast.release画面标记 | .65／1 |
| splash | 清楚的浮漂落水声＋短滴水尾音，180–320ms | float.contact，和H的FX01同源；不套未来鱼大小 | .85／1 |
| bite（重做） | 浮漂下沉／鱼翻动的真实水声，按鱼大小分档，无上扬电子提示 | 新权威咬钩且当前有效画面可见 | .90–1.00／3 |
| water_struggle / water_slap（新增） | 真实扰水／尾部拍水／破面回落，见分档表 | H的FX04/05真实水面动作标记，不按每帧触发 | .75–1.00／1 |
| reel（审听） | 自然线轮和鱼线短摩擦，220–400ms，无机械高频长啸 | retrieve.start一次，不循环；不新增收线视觉特效 | .55／1 |
| escape（审听） | 仅保留与现有逃脱动作实际相符的短水声，无下降电子提示；无接触则静默 | 权威失败＋现有动作真实接触；不新增脱钩视觉特效 | .75／2 |
| groundbait（重做） | 数颗窝料真实落水的细碎声，160–300ms | 撒饵接触点，每三轮最多一次且间隔≥2.16s | .75／0 |
| catch（审听） | 纸页记下一笔／轻印章，150–280ms，不用奖励电子双音 | 同一catchId的确认与展示节点均具备；不新增收获确认视觉特效 | .55／2 |
| meow_01–03 | 沿用已授权猫叫，审听确保不过度盖住水声 | 手动有效点击／成功后自动回应 | .60／1 |

UI 全局 90ms 间隔；同一次导航不叠 click+open。表中为v2制作初值；不同素材不能只按gain数值推断响度，须在同一设备／系统音量下A/B。旧候选保留用于比较，不因文件名一致视作已符合。

**事件身份优先于冷却：**同 ID 绝不重播；不同权威咬钩或鱼获不能被旧 cue 冷却误吞，受有限声部仲裁。试听 policy 中 bite .8s、catch 1.2s 等只作为无身份的预览节流，正式关键事件不能据此跳过新的真实结果。普通 UI 和撒饵仍保留节流。

## 4. 声部、优先级和音乐

- 1 个音乐声部；短音最多 4 个（UI 1、钓鱼 2、猫叫 1）。实际用受控 AudioSource 池，不能继续用无限 PlayOneShot 叠加来声称满足上限。
- 同组满额：高优先级替换最低优先级；同级关键结果替换最旧的同类，40ms 淡出。低优先级丢弃，不排队补播历史声音。
- 咬钩（3）> 真实结果（2）> 水面拍水／动作（1）> 撒饵（0）。同塘其他玩家自动声音继续为零。
- 咬钩音乐乘.5保持.7s；其他清晰水花短时乘.7覆盖实际水声，单次最多.7s；纸面收获音不再强制压低音乐1.2s。80ms降低、250ms恢复。重叠取最小乘数和最晚结束，不累乘，不提前恢复，不改变保存音量。
- 手动猫叫 ≥2.5s，三变体避免连续重复；自动庆祝猫叫 ≥12s 且遵守全局 2.5s，下一个空闲 voice 声部才可发。收获纸面确认音结束后 120ms 播放；期间换塘、离席、取消或又有咬钩则丢弃，不排队。
- 音乐仍沿用当前托盘播放习惯。新增「后台咬钩提示」开关默认开启：窗口全部隐藏时，只允许新且仍有效的自己咬钩提示一次；无普通 UI、挥竿、水花、撒饵、自动猫叫。音效音量为 0 优先于后台提示。恢复窗口不能重播该事件。
- 原生 Overlay 可见、Unity 主窗口隐藏不算后台静默；焦点在其他应用但 Overlay 可见仍按正常桌宠模式。后台策略依据可见性和用户开关，不仅依据 Unity focus。

## 5. 同步、失败与生命周期

共用 [表现契约](../../design/ui/steam-desktop-22hij/presentation-contract.md)。WPF 只发送语义 marker，Unity 校验会话、角色、当前 owner、事件身份后播放；杜绝把任意文件路径或任意 cue 从 IPC 直接放行。

入水与咬钩不再共用 splash；收获 ACK 与结算合并到同一 catchId。开页导航失败不播 open；收费／入包失败只播一次 ui_error，不先成功后补失败。普通停钓无 escape，若权威确认为 escaped 则按真实结果处理。

后台提示是“等待可见动画标记”规则的唯一例外：所有窗口隐藏时由 Unity 消费新权威 bite，一次发声并记录相同去重键，恢复可见后 WPF 标记不得再响；如果截止时间已过则省略。首次／重连快照不属于新事件，仍静默。

首次／重连快照静默设基线；音频资源失败不阻断游戏，缺 cue 省略并记一次诊断，不用更响的系统音代替。停止／换塘关闭当前动作 pending marker，短音 40–80ms 淡出，音乐按现有导航逻辑保留。

静音仍消费事件，调回音量不补发。旧协议无事件标记时禁用新的动作音路径，最多保留一次受控的 UI 反馈；不能让 Unity 阶段音和 WPF marker 双路同时存在。

## 6. 分档水声、音乐与资源制作

### 6.1 多种水声与S/M/L/XL

与H使用同一 `waterSizeTier`，未知鱼尺寸沿用中性S，不在鱼露面前泄露隐藏信息。浮漂落水、等待和撒饵按物体本身处理；**等待波纹不配周期滴答声**。声音实际对应水的动作，不能每个视觉弧线都发一次声。

| 鱼档 | 音色／形态 | 咬钩／扰水／拍水素材时长范围 | 目标增益初值 |
|---|---|---|---|
| S 小鱼 | 细小破面、短滴落；轻但有清楚瞬态 | 120–260ms | .75–.90 |
| M 中鱼 | 几滴紧接的小拍水，略有空腔水感 | 180–360ms | .85–.95 |
| L 大鱼 | 宽面拍击＋数滴回落，水体更厚实 | 280–500ms | .90–1.00 |
| XL 超大鱼 | 更宽的翻水／低频水体＋较长回流尾音，无爆炸轰鸣 | 380–700ms | .95–1.00 |

每档准备「咬钩／扰水／拍水」三类、每类至少2个真实不同变体，共24个短片；可以从少量合法长录音剪出，不允许把同一段仅变速变调充作不同动作。浮漂入水和撒饵各至少2个变体，合计至少28段水体候选。成组审听后删除不合格样本，不为了数量保留重复或噪声。

同类相邻事件不连播同一变体；固定事件键选样，重发不重抽。扰水／拍水合并限频，每900ms最多一次；普通扰水每三次可见动作最多响一次；强拍水优先并替换同一动作的弱扰水声。打窝仍≥2.16s一次，避免清晰水声变成持续噪音。其他玩家自动水声保持静音。

在音乐35%、音效70%默认配置下，用户应清楚听到浮漂入水和S级水花，L/XL有更大水体感而不突兀。比较旧版时，入水／撒饵的事件有效片段短时RMS初始目标提高约3–5dB，最终靠同音量A/B实听确认；不是整体音效滑杆或所有cue统一加大。保留水花瞬态与回落细节，清理风噪／底噪／过长混响，不靠高频激励器制造“清晰”。

### 6.2 柔和器乐音乐

- 配器候选：柔音／毡音钢琴为主，少量尼龙吉他分解和弦、柔弦乐长音；同时突出旋律声部最多2个。高音区点缀少而轻，避免锐利琴槌、亮铃、尖木琴和高频重复音型。
- 节奏初值60–76BPM，4/4或6/8；不加重拍电子鼓，不密集铺满。动态缓和，转段不突然升高音量或出现强烈高频。
- 先提供同一旋律20–30秒的两种配器A/B；选择后交付60–90秒可无缝循环成品。旧《池畔晴日》作为对照，重配不合格才更换曲目；不据“钢琴”文件名免除实听。
- 水声出现时音乐适度让位；环境安静时音乐自然恢复，不能听出明显抽吸。连续多次水花保持最小乘数／最晚结束，不反复拉扯。

### 6.3 资源规格与授权

- 操作音逐cue录制纸张／手账物件，常用click/open/toggle至少2变体。现有14个音频与4个候选逐项审听，符合者复用，不符者替换；不沿用“全部保留”的v1假设。
- 优先实录或可商用且可随游戏分发的拟音素材；逐条记录录音物体／水面动作、来源、许可、处理与hash，更新StreamingAssets manifest和CREDITS。不可把来源不明的网络录音直接入包。
- PCM16-bit、44.1kHz；短音单声道，BGM立体声流式。新增短音实际解码预算≤4MiB，按所有UI／水声／动作变体总时长核验；音乐不整曲解码常驻。
- 单素材峰值≤−3dBFS；四声部＋音乐最坏组合无削波，最终true peak目标≤−1dBTP。保留必要混音余量或轻限幅，不能用硬削波换音量。边缘用短淡化去爆音，不截断落水瞬态。
- 保留循环边界、静音与持久化测试。音色、清晰度和柔和度必须同时在耳机及普通扬声器验收，不能只看峰值／RMS达标。

## 7. 试听与实施顺序
