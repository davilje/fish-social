---

## 1. 背景

当前 `todayKey()` 使用 `toISOString().slice(0, 10)`，按 **UTC 自然日** 累计，国内玩家实际在 **北京时间 08:00** 才换日，与「每天 0 点刷新」预期不符。

---

## 2. 目标

1. 每日 8 小时额度按 **Asia/Shanghai 自然日 00:00** 切换 `date_key` 并重新累计。  
2. **跨日仍在钓鱼过程中**：只刷新「今日剩余时长」，**不打断**当前钓鱼状态机 / 钓位 / 会话。

---

## 3. 规则

### 3.1 日界

| 项 | 约定 |
|----|------|
| 时区 | `Asia/Shanghai` |
| `date_key` | `YYYY-MM-DD`（上海日历日），与排行榜 / 运营日报一致 |
| 实现 | 复用已有 `getShanghaiDateKey` / `Intl…timeZone: 'Asia/Shanghai'`，**禁止**再用 UTC `toISOString().slice(0,10)` 作为钓鱼日额度 key |

### 3.2 跨日仍在钓（必须）

当上海日从 D 滚到 D+1 时，若玩家仍处于钓鱼流程（如 `waiting` / `hooked` / `resolving` / `baiting` / `casting`，或 `status=======fishing'` 且已占位在钓）：

| 做 | 不做 |
|----|------|
| 将 **日界前** 已钓时长写入 `daily_fishing` 的 **D** 日行（若尚未落库） | 不强制 `stop_fishing` / 离位 / 清 pending |
| 将内存中「今日已用」切到 **D+1**：`todayFishingMs` 从 0 起算（仅计日界后时长） | 不改 `fishingPhase`、不改 `spotId`、不改钩上鱼/pending |
| 重锚计时：使「今日剩余」≈ 8h − 日界后已过时长（通常接近满额 8h） | 不踢下线、不发失败 toast（可选轻提示「今日钓鱼时长已刷新」——非必须） |
| UI / `enrichPondUser` 读到的剩余时长随新日更新 | |

推荐实现要点（任选等价方案，验收看行为）：

- 检测到 `todayKey()` 与会话缓存的 `fishingDayKey` 不一致时做 **day rollover**：  
  - flush：`min(now, dayBoundary) - fishingStartedAt`（及已累计）→ 旧日；  
  - `fishingStartedAt = max(fishingStartedAt, dayBoundaryMs)` 或等价「今日段从日界起算」；  
  - `todayFishingMs = 0`（或仅日界后已 flush 的增量）；  
  - `fishingDayKey = 新日`。  
- 触发点：至少覆盖 **session timer tick / enrich / getTodayFishingMs·addTodayFishingMs / start_fishing 校验前**，避免跨日后 UI 仍显示旧日剩余或误拒开钓。

### 3.3 跨日未在钓

仅换 `date_key`：新日 `getTodayFishingMs` 自然为 0；无状态可清。

### 3.4 开钓校验

`start_fishing`（占位）仍用 **当日上海日** 的累计：`>= MAX_DAILY_FISHING_MS` →「今日钓鱼时长已达 8 小时上限」。跨日 rollover 后应能再次开钓（若此前因满额停过）。

---

## 4. 非目标

- 不改 8 小时数值本身  
- 不改 bot 是否受 8h 限制的产品策略（若 bot 当前不受限则保持）  
- 不重做状态机相位

## 6. 验收

- [ ] `date_key` 与上海日历日一致（UTC 日与上海日不同时抽检）  
- [ ] 上海 0 点前已接近满额、跨日后未停钓：仍在原相位/钓位，剩余时长刷新为新日额度  
- [ ] 跨日后 `daily_fishing` 旧日有累计、新日从 0（或仅新日段）计  
- [ ] 满额拒绝开钓仍有效（新日内钓满 8h）
