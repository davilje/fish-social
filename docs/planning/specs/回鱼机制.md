## 1. 背景与目标

### 1.1 背景

现有捕获后仅有「入包 → 卖出」。卖出只删背包、不回写塘内实体。需要「回鱼」：把鱼放回**当前塘**，塘内该鱼**增重**，玩家获得**金币 + 熟练度**（与卖价可不同比例），形成「养塘 / 社交塘」循环。

### 1.2 目标

- 提供与**卖出**明确区分的**回鱼**动作。
- 回鱼成功：背包移除该鱼 → 塘内对应物种实体**尺寸增大** → 玩家得金币 + 玩家/塘熟练度。
- 准入可配置：品质门槛、尺寸区间；**已达该种最大尺寸不可回**。
- Steam：收杆弹窗 + 背包入口（须在本塘）。

### 1.3 非目标

- 跨塘回鱼、邮寄回鱼、保管箱/水族箱。
- 改变卖出逻辑（卖出仍不回写塘实体）。
- Mobile/Web 完整对齐。
- 回鱼相册自动收录的完整 UI（由 `FEAT-ALBUM-01` 消费事件即可）。

### 3.2 交互与 UI（Steam）

1. **收杆弹窗**（`DesktopCatchBagModalView`）：在「卖出 / 入包」旁增加 **「回鱼」**；展示预估金币与「塘内将增重约 Xm」。
2. **背包**：仅当玩家 `spotId` 有效且在当前 `pondId` 时，「回鱼」可点；否则灰显 + Tooltip「需在当前鱼塘钓位」。
3. 失败提示：文案气泡或 toast，原因码见 §4.2。
4. 成功：关闭/刷新弹窗；金币与熟练度 HUD 刷新；可选短暂「鱼回塘」反馈。

### 3.3 规则与数值

权威表 sheet：`return_rules`（进 `钓鱼玩法固定数值表.xlsx` → `game-data:export`）。

| 字段 | 类型 | 说明 |
|------|------|------|
| `minQuality` | enum/int | 低于不可回（建议 common 及以上可回，或按档） |
| `minSizeRatio` | float | 相对种 max 的下限，如 0.2 |
| `maxSizeRatio` | float | 相对种 max 的上限；**=1.0 时恰好满尺寸不可回** |
| `goldMulVsSell` | float | 回鱼金 = `floor(calcFishSellPrice × goldMulVsSell)`，建议 **0.70** |
| `playerXp` | int | 每次回鱼玩家熟练度 |
| `pondXp` | int | 每次回鱼塘熟练度 |
| `sizeGainMinM` | float | 增重下限，建议 **0.02** |
| `sizeGainMaxM` | float | 增重上限，建议 **0.05** |
| `sizeGainMode` | enum | `uniform_random`（默认） |

**核心规则（定稿）**

```text
sellGold = calcFishSellPrice(item)          // PROG-01 已有
returnGold = floor(sellGold × goldMulVsSell)
sizeGain = random(sizeGainMinM, sizeGainMaxM)
newSize = min(speciesMaxSizeM, currentPondEntitySizeM + sizeGain)
若 item.sizeM >= speciesMaxSizeM 或 塘内目标已满 → 拒绝
```

- 回鱼写入：优先匹配塘内同 `speciesId` 可增重实体；若无存活实体则**新生成一条**以 `item` 尺寸为基再 +gain（实现可选，spec 要求「塘内该种有可感知增重」）。
- 回鱼**不**增加图鉴「首次捕获」以外的重复计数（图鉴只增不减；回鱼可不触发新物种解锁）。
- 熟练度走 PROG-01 既有发放管道，受 `maxPondLevel` 等锁级规则约束。

## 4. 技术影响

### 4.1 数据模型

- 无强制新表；可复用 inventory item id + pond fish entity id。
- 可选审计：`fish_return_log`（后置，非本票必做）。

### 4.2 API / Socket

| 类型 | 名称 | 说明 |
|------|------|------|
| REST | `POST /api/inventory/return-to-pond` | body: `{ inventoryItemId }`；须在塘；成功返回 `{ gold, playerXp, pondXp, newSizeM }` |
| Socket | 可选 `pond_fish_updated` / 既有塘快照刷新 | 同步塘内尺寸 |

**错误码（建议）**

| code | 含义 |
|------|------|
| `NOT_IN_POND` | 不在塘或无钓位 |
| `QUALITY_TOO_LOW` | 品质不足 |
| `SIZE_OUT_OF_RANGE` | 尺寸不在准入区间 |
| `AT_MAX_SIZE` | 已达种最大尺寸 |
| `ITEM_NOT_FOUND` | 背包无此鱼 |

### 4.3 涉及文件（预估）

- `shared/`：`economy` 旁可加 `calcFishReturnReward`；`generated/game-data`
- `server/src/`：`inventory.ts`、生态实体更新、`socialRoutes` 或 inventory 路由
- Unity：`DesktopCatchBagModalView`、背包面板

### 4.4 埋点（实现时走 metrics-catalog-sync）

| eventType | 关键 |
|-----------|------|
| `fish_returned_to_pond` | playerId, pondId, speciesId, sizeM, gold, sizeGainM |

## 5. 验收标准

- [ ] 回鱼：删包 + 塘内尺寸增大 + 发金币/熟练度；数值符合 `return_rules`
- [ ] 卖出：不改塘实体
- [ ] 满尺寸 / 品质不足 / 不在本塘 → 拒绝且有明确提示
- [ ] 收杆弹窗与背包均可回鱼（本塘）
- [ ] 回鱼金明显低于或等于配置倍率下的卖价（默认 70%）
- [ ] 埋点 `fish_returned_to_pond` 可查（实现阶段入库埋点表）
