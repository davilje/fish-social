## 1. 目标

在现有 Unity 空工程上建立 Windows 桌面端基础壳，为后续 Steam 登录、鱼塘场景、好友 Lobby 和挂机通知提供稳定容器。

本阶段的完成标准不是“做出完整游戏”，而是：

```text
启动桌面端
→ 进入主界面
→ 查看鱼塘占位状态
→ 最小化/恢复或隐藏到托盘
→ 打开设置
→ 收到通知占位事件
→ 构建 Windows 测试包
```

---

## 2. 范围与非目标

### 2.1 本阶段范围

- Windows 桌面启动和退出生命周期
- 普通窗口、全屏、无边框模式
- 最小化、恢复和托盘隐藏
- 低干扰后台运行容器
- 窗口和通知设置
- 主界面、鱼塘占位页、好友/聊天占位入口
- 可替换的通知接口
- Windows 构建和基础性能验证

### 2.2 非目标

- 不接入 Steam Ticket、SteamID 或 Steam Lobby
- 不实现 Steam Networking/Relay
- 不接入真实 Node Socket.IO
- 不实现真实钓鱼、鱼群、库存和聊天业务
- 不导入 `mobile/`、`server/` 或 TypeScript 源码到 Unity
- 不制作正式美术资源
- 不实现开机启动、置顶、透明窗口和多平台支持

## 3. 子任务拆分

### STEAM-DESKTOP-04A：工程基线与构建

**优先级：P0**

- 使用现有 `fish-social-unity/` 工程。
- 固定 Windows 构建目标和基本 Player Settings。
- 建立 `Assets/Scenes`、`Assets/Scripts`、`Assets/UI`、`Assets/Prefabs` 等目录。
- 保证空场景可以运行和构建。
- 不提交 `Library/`、`Temp/`、`Obj/`、`Logs/`、`UserSettings/`。

**出口：**

- Unity Editor 可打开工程。
- 默认场景运行无报错。
- Windows Development Build 可生成并启动。

### STEAM-DESKTOP-04B：应用生命周期与窗口模式

**优先级：P0**

- 启动时加载桌面主场景。
- 支持普通窗口、全屏和无边框模式。
- 支持窗口大小和位置保存。
- 支持最小化、恢复和关闭事件。
- 关闭行为隐藏到托盘，不直接退出进程。

**出口：**

- 三种窗口模式可切换。
- 重启后恢复上次窗口配置。
- 关闭窗口后进程行为符合托盘规则。

### STEAM-DESKTOP-04C：托盘与后台挂机容器

**优先级：P0**

- 提供托盘图标和基本菜单。
- 支持“显示窗口”“隐藏窗口”“退出游戏”。
- 隐藏到托盘后客户端进程继续运行。
- 后台状态不创建高频无意义渲染负载。
- 为后续真实钓鱼会话预留生命周期接口。

**出口：**

- 托盘菜单可以恢复、隐藏和退出。
- 隐藏期间进程不崩溃，恢复后状态仍可见。
- “隐藏”与“退出”行为明确区分。

### STEAM-DESKTOP-04D：主界面和功能占位

**优先级：P0**

- 建立桌面主界面布局。
- 提供鱼塘、好友/聊天、鱼获/背包、设置四个入口。
- 提供鱼塘场景占位页。
- 提供登录状态、连接状态和错误提示占位。
- 允许未来替换为真实 Unity 场景而不重做窗口壳。

**出口：**

- 从主界面可以进入和返回四个入口。
- 窗口缩放后布局不重叠。
- 占位页不绑定真实后端数据。

### STEAM-DESKTOP-04E：设置与通知接口

**优先级：P1**

- 设置窗口模式。
- 设置通知开关和免打扰状态。
- 保存本地非权威偏好。
- 提供统一通知接口，至少支持：
  - 鱼咬钩
  - 好友邀请
  - 连接错误
- 当前使用本地模拟事件验证，不接入 Steam 或 Node。

**出口：**

- 设置重启后仍然有效。
- 关闭通知后不触发桌面提醒。
- 模拟通知可从统一接口发送。

### STEAM-DESKTOP-04F：性能和发布验证

**优先级：P1**

- Windows Development Build 可启动。
- 空闲桌面状态 CPU/内存占用达到可接受水平。
- 托盘隐藏后不持续高频渲染。
- 记录构建版本和运行环境。
- 建立 Unity 客户端基础冒烟清单。

**出口：**

- 至少完成启动、窗口切换、托盘恢复、设置保存、通知模拟五项冒烟。
- 构建包可在未安装 Unity Editor 的 Windows 环境启动。

## 4. 推荐实现顺序

```text
04A 工程基线
  ↓
04B 生命周期/窗口
  ↓
04C 托盘/后台
  ↓
04D 主界面占位
  ↓
04E 设置/通知
  ↓
04F 构建/性能验收
```

04D 可以与 04B、04C 部分并行，但 04E 依赖设置存储和生命周期接口，04F 必须在全部子任务完成后执行。

---

## 5. 技术边界

- 所有 Unity 代码放在 `fish-social-unity/Assets/`。
- 本阶段不改变 `server/`、`shared/`、`mobile/` 业务代码。
- 本地设置只保存窗口、通知等非权威偏好。
- 不在客户端保存金币、库存、鱼获、每日额度或 Steam 密钥。
- 后续真实网络接入通过独立的 `NetClient`/适配层，不把 Socket.IO 调用散落在 UI。

## 6. 验收标准

- [x] Unity 工程可打开、运行和构建 Windows 包。
- [x] 普通窗口、全屏、无边框模式可切换。
- [x] 关闭窗口隐藏到托盘，托盘可恢复或退出。
- [x] 主界面包含四个约定入口和鱼塘占位页。
- [x] 窗口和通知设置可以保存并恢复。
- [x] 通知接口可模拟鱼咬钩、好友邀请和连接错误。
- [x] 后台隐藏时无持续高频渲染。（`BackgroundRenderGate` → 5 FPS）
- [x] 完成 Windows Development Build 冒烟（见 `fish-social-unity/Docs/STEAM-DESKTOP-04-smoke.md`）。
