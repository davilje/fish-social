## 1. 背景与目标

### 1.1 背景

鱼塘表现已经是手账猫咪和粉彩场景，但地图和塘数据仍按中国实景写。`ponds.json` 的 `realWorldRef` 是「浙江淳安」「江苏无锡」这类地名，`bioRegion` 是东平湖、长江中游、东北冷水等现实分区。玩家看到的世界因此分成两层：画面是猫，文字是中国钓场。

### 1.2 目标

- 玩家能读到的世界地图分区、鱼塘介绍和 Overlay 场景说明，都发生在猫咪的世界里。
- 每个现有鱼塘有一段场景描述，能对上它已经在用的粉彩场景（湖、河、库、海岸、河口），而不是再解释成某省某市。
- `pondId` 不变，已有存档、社交和进塘记录不断。

### 1.3 非目标

- 不删 FEAT-FISH-CN-01 的鱼种，不改出鱼表。现实鱼名可以继续被钓到，叙述上它们生活在猫咪世界的对应水域。
- 不实现 22J 的筛选、缩放和点位布局。
- 不新画 20 张场景，不新增第 21 个塘。
- 不改票价、等级、品质和钓鱼公式。

## 2. 用户与场景

| 角色 | 场景 | 期望 |
|------|------|------|
| 玩家 | 打开世界地图 | 分区名称和短介绍是猫咪世界，不是省份钓场目录 |
| 玩家 | 点开一个鱼塘或进入 Overlay | 介绍对得上眼前的岸线和水，不出现「浙江淳安」这类实景说明 |

## 3. 功能范围

### 3.1 世界观（写入数据，不另起百科页）

猫咪世界用五个分区覆盖现有 `bioRegion`，一对一替换玩家可见名称。内部 `bioRegion` 键可以保留，避免迁移存档。

| 现有 bioRegion | 玩家可见分区 | 场景气质 |
|----------------|--------------|----------|
| east_plain_lake | 暖湖郡 | 浅湖、荷叶、软岸 |
| yangtze_mid | 长水湾 | 宽河、渡口、晨雾 |
| southwest_plateau | 云阶 | 高湖、冷色远山 |
| northeast_cold | 霜耳原 | 薄冰边缘、深色林线 |
| south_reservoir | 阳库 | 大坝、开阔水面、暖色天空 |

分区各用两三句说明「猫为什么在这里钓鱼」。不要写真实行政区。

### 3.2 每塘文案

对 `ponds.json` 里每一个塘：

- 新增玩家可见字段 `sceneBlurb`（一两句，对应该塘 Overlay 布局：湖 / 河 / 水库 / 海岸 / 河口）。
- `realWorldRef` 不再出现在地图、选塘详情和 Overlay。字段可以留在表里给策划对照，界面禁止读取它。
- 塘的显示名如果仍是现实钓场名，改成同水域气质的猫咪地名；`pondId` 不动。

### 3.3 界面

世界地图、选塘详情、鱼塘右栏使用分区名和 `sceneBlurb`。22J 没做完之前，接到现有 `DesktopWorldMapPanel` 和选塘详情已有的介绍位，不重做三栏。

## 4. 技术影响

- 数据：`shared` 鱼塘表增加 `sceneBlurb`；显示名可改，`pondId` 不改。
- 界面：Unity 世界地图和选塘详情改读新字段；Overlay 若有塘名条，同步。
- 不改 API 路径。旧客户端没有 `sceneBlurb` 时继续显示原塘名，不得显示 `realWorldRef`。

## 5. 验收标准

- [ ] 地图和选塘详情不再出现省、市或「浙江淳安」这类 `realWorldRef`。
- [ ] 五个现有 bioRegion 都有猫咪世界分区名和短介绍。
- [ ] 每个现有鱼塘有 `sceneBlurb`，且 `pondId` 与改前一致。
- [ ] 出鱼表、票价、等级门槛与改前一致。

## 6. 风险

| 风险 | 缓解 |
|------|------|
| 改显示名后玩家找不到原塘 | `pondId` 不变；选塘列表仍按原顺序 |
| 与 22J 抢地图改动 | 本项只换文案字段；布局仍归 22J |
