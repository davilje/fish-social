## 0. 文档目的

fish-social 已有：

- **实时排查**：Admin「钓鱼指标」168h 滑动窗口、`/api/admin/metrics/fishing/player/:id` 时间线
- **离线模拟**：`docs/analytics/pond-day-simulation/` 蒙特卡洛 7 日报告、咬钩校准表
- **日聚合雏形**：`daily_player_stats` / `daily_pond_stats` 表、`aggregate-daily-metrics.mjs`、`daily-pipeline.mjs`

但 **缺少面向策划/运营的「昨日怎么样」固定页面**：无法按自然日对比、无法与产品目标（~100 条/天）对照、无法与模拟设计值并排阅读。

本文档定义 **运营日报 v1** 的产品范围、指标口径、页面结构、数据流、分期交付与验收标准，作为开发与 `docs/analytics/daily/` 归档的权威依据。

---

## 1. 背景与问题

| 现状 | 问题 |
|------|------|
| Admin 指标为近 168h 滑动窗口 | 无法回答「昨天全服日钓多少」 |
| 模拟报告为设计态 | 与真实玩家行为脱节 |
| 终端 / 内存 error 日志 | 非运营视角 |
| 日批脚本已有 MVP | 仅 4 个 KPI + 鱼塘简表，缺对照/告警/索引 |

**核心诉求**：每天固定生成 **T-1 日（昨日）** 运营快照，浏览器打开即可读，并纳入 analytics 归档体系。

## 2. 用户与使用场景

| 角色 | 典型问题 | 使用频率 |
|------|----------|----------|
| 策划 | 昨日日钓是否接近 ~100 条目标？调参后趋势？ | 每日 |
| 运营 | DAU、断线率、弃钓率是否正常？ | 每日 |
| 开发 | 断线/pending 超时是否突增？某塘是否枯竭？ | 出问题时 |
| 负责人 | 一屏看产量、生态、经济、稳定性 | 每周/每日 |

**与 Admin 实时面板的分工**：

| 工具 | 用途 |
|------|------|
| Admin 钓鱼指标 / timeline | **实时**排障、单玩家追溯 |
| **运营日报** | **日度**决策、趋势、目标对照 |

---

## 3. 产品目标

1. 按 **自然日**（默认 **Asia/Shanghai**）查看运营数据，日期选择器默认昨日。
2. **一屏总览 + 分模块下钻**，视觉风格与 `docs/analytics/pond-day-simulation/report.html` 一致（Chart.js、表格、KPI 卡片）。
3. **与模拟/目标对照**：设计目标 vs 昨日实测 vs（可选）7 日模拟参考。
4. **只读、低门槛**：静态 HTML + JSON；不依赖 SSH / 手工 SQL。
5. **可归档**：每日产出 `docs/analytics/daily/YYYY-MM-DD/`，由 `docs/analytics/index.html` 索引（D-L3-09）。

## 5. 指标定义

### 5.1 通用约定

| 项 | 约定 |
|----|------|
| **统计日** | `date_key = YYYY-MM-DD`，边界 `[dayStart, dayEnd)` |
| **时区** | **Asia/Shanghai（UTC+8）**；实现时禁止误用 `T00:00:00Z` 当作北京时间 |
| **玩家** | `player_id` 非空且非 `bot-*` 前缀（Bot 单独统计或排除） |
| **上岸** | `event_type IN ('catch_accept', 'pending_catch_accept')`，按 `dedup_key` 或业务 `eventId` 去重（若已启用） |
| **断线** | `disconnect` + `socket_disconnect` |
| **数据源** | 主：`fishing_metrics`；辅：`daily_*` 聚合表；生态：`pond_fish` 日末快照 |

每个首屏 KPI 展示：**当日值 | 前日值 | 7 日均 | 环比 | 状态色**。

### 5.2 §1 健康度总览（MVP 必含）

| 指标 ID | 名称 | 计算口径 | 目标参考 |
|---------|------|----------|----------|
| `kpi_daily_catch` | 日钓总量 | 全服上岸事件去重计数 | 设计 ~**100 条/天**（20 人全服场景） |
| `kpi_dau` | DAU | 当日任意 metrics 的唯一玩家 | — |
| `kpi_fishing_dau` | 钓鱼 DAU | 当日 `fishing_start` 唯一玩家 | — |
| `kpi_catch_per_fisher` | 人均上岸 | 日钓总量 / 钓鱼 DAU | ~5 条/人/天 |
| `kpi_disconnect_rate` | 断线率 | 断线次数 / `join_pond_success` | 越低越好 |
| `kpi_abandon_rate` | 弃钓率 | `abandon_fishing` / `fishing_start` | — |
| `kpi_avg_pop_ratio` | 四塘平均人口率 | 日末各塘 population/max 均值 | ≥ **85%** |

**状态色建议**：

| 色 | 条件示例 |
|----|----------|
| 绿 | 日钓 80–120；人口率 ≥85%；断线率 <20% |
| 黄 | 日钓 50–80 或 120–150；人口 70–85% |
| 红 | 日钓 <50 或 >150；任塘人口 <70%；断线率 >30% |

### 5.3 §2 玩家与活跃

| 指标 | 说明 | 事件/表 |
|------|------|---------|
| 新增注册 | 当日新 `players` 行 | `players.created_at` |
| DAU / 钓鱼 DAU / 占座 DAU | 分事件统计 | metrics |
| 人均 session 数 | `fishing_start` / 钓鱼 DAU | metrics |
| 人均钓鱼时长（估） | `daily_player_stats.fishing_ms` 求和 / 钓鱼 DAU | daily_player_stats |
| Bot 占比 | bot join 或 `isBot` payload | metrics |

### 5.4 §3 钓鱼产出

| 指标 | 说明 |
|------|------|
| 日钓 · 分塘 | `daily_pond_stats.catch_count` 或 metrics group by `pond_id` |
| 日钓 · 分品质 | payload.quality 聚合 |
| 被钓均长 | `sizeM` 加权平均 |
| 咬钩命中率 | ~~`bite_tick_hit` / (`hit`+`miss`)~~ → **自 [D-L2-15](./埋点优化-咬钩脱钩计数替代tick.md) 起废弃**；改：上钩频率（`bite_hook`/钓鱼时长）、脱钩率（`escape`/`bite_hook`）、获鱼率（上岸/`bite_hook`） |
| 脱钩率 | `escape` / (`escape`+上岸)；**D-L2-15 起优先** `escape` / `bite_hook` |
| pending 超时率 | `pending_catch_expired` / `pending_catch_created` |

**图表（P1）**：分塘柱状图、品质占比饼图、命中率折线（近 7 日）。

### 5.5 §4 体验与稳定

| 指标 | 事件 |
|------|------|
| 断线 / 重连 / 超时清场 | `disconnect*`、`reconnect`、`disconnect_timeout` |
| leave 按 reason | `leave_pond` payload.reason |
| join 失败率 | `join_pond_fail` / `join_pond_attempt` |
| phase 异常 | `phase_transition_invalid` |
| 连续脱钩玩家 | `escape_streak` 涉及玩家数 |

### 5.6 §5 经济

| 指标 | 事件 | MVP |
|------|------|-----|
| 金币 sink | `bait_buy` + `tackle_buy` + `tackle_repair` 的 cost | ✅ |
| 金币 faucet | 卖鱼等 | ⚠️ 若无埋点则展示「待补」 |
| 净变化 | faucet − sink | 依赖 faucet |
| 饵/渔具结构 | 按 baitId、tackleId | ✅ |

### 5.7 §6 鱼塘生态

| 指标 | 来源 | 阶段 |
|------|------|------|
| 各塘人口/上限/人口率 | 日末 `pond_fish` count | P1 |
| 各品质占比、均长 | 日末快照 | P1 |
| 补充条数 | supplement 埋点或推算 | P2 |
| 平均人口（日内） | metrics payload.population 均值 | ✅ 已有 `avg_population` |

### 5.8 §7 与目标对照

| 对比项 | 来源 |
|--------|------|
| 产品目标 100 条/天 | 常量 `TARGET_DAILY_CATCH = 100` |
| 模拟 7 日均（5 人/塘场景） | `docs/analytics/pond-day-simulation/analysis.json` → `perDayCaught` |
| 昨日线上实测 | 本日报 `kpi_daily_catch` |
| 偏差 | `(实测 − 目标) / 目标 × 100%` |

### 5.9 §8 异常清单（日报内嵌）

| 规则 ID | 条件 | 默认阈值 |
|---------|------|----------|
| `alert_catch_high` | 日钓超目标 | >120 |
| `alert_catch_low` | 日钓过低且有人玩 | <50 且 DAU>5 |
| `alert_pop_low` | 任塘人口率 | <70% |
| `alert_disconnect` | 断线率 | >30% |
| `alert_pending_expired` | pending 超时率 | >10% |
| `alert_no_data` | 当日无 metrics | 事件数=0 |

Phase 2（D-L3-08）：超阈值 Webhook 通知策划。

## 6. 交互与非功能需求

### 6.1 交互

| 功能 | MVP | P1 |
|------|-----|-----|
| 日期选择（默认昨日） | ✅ | |
| 近 30 天已归档日期列表 | | ✅ |
| vs 前日 / vs 7 日均 切换 | ✅ KPI | 全模块 |
| 分模块表格下钻 | ✅ 鱼塘 | 品质/经济 |
| CSV 导出汇总 | | ✅ |
| 链到 Admin timeline | | ✅（带 playerId 说明） |

### 6.2 非功能

| 项 | 要求 |
|----|------|
| 生成时间 | 每日 **00:30 Asia/Shanghai** cron；支持 `npm run analytics:daily -- --date=YYYY-MM-DD` 补跑 |
| 性能 | 单日聚合 <60s（SQLite 百万级 metrics） |
| 权限 | 静态 HTML 内网/VPN；或 Admin API + `x-admin-key` |
| 保留 | 日报目录至少 **90 天**；更早可压缩 JSONL 归档 |
| 数据完整度 | 页眉展示：metrics 条数、首末事件时间、是否完整日界 |

### 6.3 明确不做（v1）

- 实时刷新（交给 Admin）
- 用户级明细列表（交给 timeline API）
- 多租户 / 分渠道

## 7. 技术方案

### 7.1 数据流

```text
每日 00:30 (Asia/Shanghai)
  │
  ├─ scripts/aggregate-daily-metrics.mjs  → daily_player_stats / daily_pond_stats
  ├─ （P1）ecology-daily-snapshot.mjs     → daily_pond_ecology.json
  │
  └─ scripts/analytics/daily-pipeline.mjs
         ├─ summary.json    （全量指标）
         ├─ compact.json    （图表用精简结构）
         └─ report.html     （运营日报页面）
              ↓
     docs/analytics/daily/YYYY-MM-DD/
              ↓
     docs/analytics/index.html  （type=live-daily 索引，D-L3-09）
```

### 7.2 产出物结构

```text
docs/analytics/daily/
└── 2026-07-11/
    ├── summary.json      # 机器可读全量指标 + 告警
    ├── compact.json      # 图表/对照用
    └── report.html       # 运营日报页面
```

### 7.3 访问方式

| 方案 | 说明 | 阶段 |
|------|------|------|
| **A. 静态 HTML** | 与 pond-day `report.html` 同模式 | **MVP** |
| **B. Admin API** | `GET /api/admin/ops/daily?date=` | P1 |
| **C. 日历索引页** | `docs/analytics/daily/index.html` | P1 |

### 7.4 与现有代码映射

| 模块 | 路径 | 现状 vs 目标 |
|------|------|--------------|
| 日聚合 | `scripts/aggregate-daily-metrics.mjs` | ✅ 有；需改 **UTC+8 日界** |
| 日批报告 | `scripts/analytics/daily-pipeline.mjs` | △ MVP 4 KPI；需扩展为 v1 全模块 |
| 聚合表 | `server/src/migrations/daily_stats.ts` | ✅ 有 player/pond；P1 扩展 ecology |
| 报告模板 | 新建 `generate-daily-ops-report.mjs` | 参考 `generate-pond-day-report.mjs` |
| npm | `analytics:daily` | 需串联 aggregate + pipeline + index |
