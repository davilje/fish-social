# 生态调优：咬钩间隔 · 鱼群补充 · 脱钩成长 · 成长周期

**版本**：v0.3.2（D1–D8 已实现）  
**状态**：**已实现**  
**背景**：鱼塘生态分析显示，30s 咬钩判定导致鱼群在少量用户下快速枯竭。本方案从咬钩节奏、定期补充、脱钩反馈、**绝对长度生长曲线**四方面调优，并**移除繁殖机制**。v0.3.2 在 D2 基础上进一步**按在线钓鱼人数调节补充频率**、**按品质缺口定向补充**。

## 2. D1 — 咬钩判定间隔 300 秒

### 2.1 设计意图

- 将玩家/Bot 的咬钩 tick 从 30s 延长至 **300s（5 分钟）**，单用户理论钓取速率约降为原来的 **1/10**。
- **不改变** `QUALITY_BITE_BASE` 等「每 tick 概率」数值；概率仍表示「每 300 秒判定一次时该鱼贡献的咬钩率」。
- 与生态 tick（`POND_ECOSYSTEM_TICK_MS = 30s`）**解耦**：鱼塘成长/补充仍每 30s tick，仅咬钩循环改为 300s。

### 2.2 常量

```typescript
// shared/constants.ts
export const FISH_BITE_CHECK_MS = 300_000; // 5 分钟
```

### 2.3 配置与迁移


| 项                                | 说明                             |
| -------------------------------- | ------------------------------ |
| `game_config.FISH_BITE_CHECK_MS` | 迁移强制写入 `300000`                |
| `initGameConfig()`               | upsert 默认 `300000`             |
| `getBiteCheckMs()`               | 下限同步为 `300_000`（禁止 DB 覆盖为更小值）  |
| 注释/文案                            | 所有「每 30 秒」改为「每 300 秒」或「每 5 分钟」 |


### 2.4 影响面

- `server/src/index.ts` — 玩家咬钩 `scheduleRuntimeInterval(..., getBiteCheckMs)`
- `server/src/bots.ts` — Bot 咬钩循环
- `server/src/fishingDebug.ts` — `checkIntervalMs` 展示
- `mobile` — Debug / 图鉴 / 商店中咬钩率后缀文案
- `scripts/a0-verify.ts` — 期望值改为 `300000`

### 2.5 验收标准

- [ ] 启动日志：`bite check interval = 300000ms`

- [ ] 实际游戏中两次咬钩判定间隔约 5 分钟（允许 ±调度误差）

## 3. D2 — 鱼群定期补充机制（替代耗尽一次性恢复）

### 3.1 设计意图

废弃「鱼数归零 → 等待 15 分钟 → 播种 minPopulation」的**阻断式恢复**，改为：

> **每 15 分钟**检查鱼塘当前数量；若低于目标上限，则**自动补充一批鱼**。补充鱼的**品质**按全局权重分布，**尺寸一律为幼年**（不触发满尺寸出生概率）。

鱼塘在有人钓鱼时也能持续回血，避免长期维持在 `minPopulation` 附近的死循环。

### 3.2 新常量（`shared/pondEcology.ts`）

```typescript
/** 鱼群补充检查间隔（15 分钟） */
export const POND_SUPPLEMENT_CHECK_MS = 15 * 60 * 1000;

/** 补充目标：当前鱼数 / maxPopulation 低于此比例时触发补充 */
export const POND_SUPPLEMENT_TARGET_RATIO = 1.0; // 1.0 = 补满至 maxPopulation

/**
 * 每次补充量 = min(缺口 × 本比例, POND_SUPPLEMENT_BATCH_MAX)
 * 例：缺口 40 条、比例 0.50 → 本次补 12 条（受 BATCH_MAX 截断）
 */
export const POND_SUPPLEMENT_BATCH_RATIO = 0.50;

/** 单次补充条数上限（防止一次跳变过大） */
export const POND_SUPPLEMENT_BATCH_MAX = 12;

/** @deprecated 仅保留常量兼容；不再用于阻断式恢复 */
export const POND_DEPLETED_RECOVERY_MS = 15 * 60 * 1000;
```

### 3.3 补充目标与数量公式

```
targetCount   = floor(maxPopulation × POND_SUPPLEMENT_TARGET_RATIO)
gap           = max(0, targetCount - currentCount)
supplementN   = min(
                  POND_SUPPLEMENT_BATCH_MAX,
                  max(1, ceil(gap × POND_SUPPLEMENT_BATCH_RATIO))
                )
若 gap = 0 → 本次不补充
```

**各塘示例**（`BATCH_RATIO=0.50`, `BATCH_MAX=12`）：


| 鱼塘  | max | 当前  | 缺口  | 本次补充                 |
| --- | --- | --- | --- | -------------------- |
| 静谧池 | 80  | 20  | 60  | 12（cap，50%×60=30 截断） |
| 静谧池 | 80  | 70  | 10  | 5                    |
| 落霞湾 | 60  | 55  | 5   | 3                    |

| --------------------------------------- | ------------------------------------------------------------------------------ |

### 3.5 幼年尺寸（绝对体长，`shared/fishing.ts`）

**与品质解耦**：所有幼年鱼体长在同一绝对区间随机，不按 `QUALITY_SIZE_CAP` 的百分比计算。

```typescript
/** 幼年鱼绝对体长区间（米），全品质通用 */
export const JUVENILE_SIZE_M_MIN = 0.08;
export const JUVENILE_SIZE_M_MAX = 0.20;

/**
 * 播种 / 系统补充专用：绝对幼年体长，无 NEAR_MAX_SPAWN_CHANCE
 * 若随机值超过该鱼品质上限（极少数），截断至 maxSize × 0.95
 */
export function rollJuvenileSize(quality: FishQuality, species: FishSpecies): number {
  const maxSize = getQualityMaxSize(quality, species);
  const raw = JUVENILE_SIZE_M_MIN + Math.random() * (JUVENILE_SIZE_M_MAX - JUVENILE_SIZE_M_MIN);
  const capped = Math.min(raw, maxSize * 0.95);
  return round2(Math.max(MIN_FISH_SIZE_M, capped));
}
```


| 示例    | 说明                        |
| ----- | ------------------------- |
| 普通鱼幼年 | 0.08~0.20m（与史诗鱼相同区间）      |
| 至尊鱼幼年 | 0.08~0.20m（同上，非 40m 的 5%） |

### 3.10 D7 — 按活跃钓鱼人数调节补充频率（v0.3.2）

#### 3.10.1 设计意图

固定 15 分钟补充在**无人钓鱼**时仍会快速把塘补满，高品质鱼在纯生长环境下堆积，与「钓鱼消耗」脱节。  
改为：**塘内正在钓鱼的人越多，补充检查越接近基线；人越少，检查间隔越长**，让冷清鱼塘鱼群恢复更慢、留给自然生长更多时间。

> **注意**：调节的是**检查间隔**（多久评估一次是否补充），不是单次 `supplementN` 公式（§3.3 不变）。  
> 鱼数 = 0 的**强制兜底**仍立即补充，不受 D7 影响。

#### 3.10.2 活跃钓鱼人数

```typescript
/** 计入补充频率的活跃玩家（不含 Bot） */
function countActiveAnglers(pondId: string): number {
  return listUsersInPond(pondId).filter(
    (u) => !u.isBot && isFishingActive(u.fishingPhase),
  ).length;
}
```

`isFishingActive` 与 `fishingStateMachine.ts` 一致：`baiting | casting | waiting | hooked | resolving | stopping`。

#### 3.10.3 新常量（`shared/pondEcology.ts`）

```typescript
/** 基线补充检查间隔（人多时） */
export const POND_SUPPLEMENT_CHECK_MS = 15 * 60 * 1000;

/** 活跃人数达到此值及以上 → 间隔倍率 = 1（正常 15min） */
export const POND_SUPPLEMENT_FULL_ACTIVITY_ANGLERS = 3;

/** 每少 1 名活跃钓鱼者，间隔增加的倍率步长（线性） */
export const POND_SUPPLEMENT_IDLE_INTERVAL_STEP = 0.5;

/** 无人钓鱼时间隔倍率上限 */
export const POND_SUPPLEMENT_MAX_INTERVAL_MULT = 3.0;
```

#### 3.10.4 有效检查间隔公式

```
active     = countActiveAnglers(pondId)
shortfall  = max(0, POND_SUPPLEMENT_FULL_ACTIVITY_ANGLERS - active)
mult       = min(
               POND_SUPPLEMENT_MAX_INTERVAL_MULT,
               1 + shortfall × POND_SUPPLEMENT_IDLE_INTERVAL_STEP
             )
effectiveCheckMs = floor(POND_SUPPLEMENT_CHECK_MS × mult)
```

| 活跃钓鱼人数 | 间隔倍率 | 有效检查间隔 |
| ------------ | -------- | ------------ |
| ≥3           | 1.0×     | **15 min**   |
| 2            | 1.5×     | **22.5 min** |
| 1            | 2.0×     | **30 min**   |
| 0            | 2.5×     | **37.5 min** |
| 0（下限）    | 3.0× cap | **45 min**   |

```
若 force === true（鱼数=0 兜底）→ 跳过间隔判断
若 now - last_supplement_at < effectiveCheckMs → return
```

#### 3.10.5 服务端改动要点

- `trySupplement(pondId, config, force)` 内用 `effectiveCheckMs` 替代固定 `POND_SUPPLEMENT_CHECK_MS`
- 从 `gameState.listUsersInPond` + `isFishingActive` 取人数；**不要**在 `shared/` 引 server 模块——在 server 实现 `countActiveAnglers`，或把人数作为参数 `trySupplement(..., activeAnglers?)`
- 日志追加：`active=${active} checkMs=${effectiveCheckMs}`

#### 3.10.6 验收标准

- [ ] 3 人同塘钓鱼时，补充行为与 v0.3.1 一致（约 15min 一轮）
- [ ] 0 人时，两次补充间隔 ≥ 37.5min（45min cap 内）
- [ ] 鱼数 = 0 仍立即补充，不等待长间隔
- [ ] Admin / 日志可看到当前 `activeAnglers` 与 `effectiveCheckMs`

### 3.11 D8 — 按品质缺口定向补充（v0.3.2）

#### 3.11.1 设计意图

v0.3.1 每次补充独立 `rollFishQuality()`，与塘内实际结构无关，导致：

- 高品质鱼未被钓走仍可能继续刷入同品质幼鱼；
- 低品质被快速钓空后，补充不够「补底层」。

v0.3.2：**以全局初始品质比例（`FISH_QUALITIES` 权重 38/28/18/9/4/2/1）为理想结构**，结合塘内各品质**实际数量**计算本次补充的抽样权重——**缺口大的低品质权重大；塘内仍有存量且不低于理想占比的高品质，几乎不再补充**。

#### 3.11.2 基准比例（与初始播种一致）

```typescript
// shared/fish.ts — FISH_QUALITIES[].weight
// gray 38, green 28, blue 18, purple 9, red 4, orange 2, gold 1  → 合计 100
baselineFrac[q] = weight[q] / 100
idealCount[q]   = baselineFrac[q] × maxPopulation   // 理想条数（浮点）
```

不在 DB 存每塘初始快照；**理想比例 = 配置权重**，与 `seedPond` / `rollFishQuality()` 一致。

#### 3.11.3 新常量（`shared/pondEcology.ts`）

```typescript
/** 史诗及以上：塘内仍有该品质鱼时，补充权重乘数（相对缺口权重） */
export const SUPPLEMENT_HIGH_TIER_PRESENT_MULT = 0.02;

/** 稀有（蓝）：塘内仍有且占比 ≥ 理想×此比例时，压低补充权重 */
export const SUPPLEMENT_MID_TIER_SATURATION_RATIO = 0.6;
export const SUPPLEMENT_MID_TIER_PRESENT_MULT = 0.15;

/** 低品质（灰/绿）缺口加成，鼓励补底层 */
export const SUPPLEMENT_LOW_TIER_DEFICIT_BOOST = 1.25;

/** 高品质索引阈值（purple=3, red=4, orange=5, gold=6） */
export const SUPPLEMENT_HIGH_TIER_MIN_INDEX = 3;
export const SUPPLEMENT_MID_TIER_INDEX = 2; // blue
```

#### 3.11.4 单条补充品质权重

对塘内各品质统计 `actual[q]`，`total = Σ actual`：

```
deficit[q] = max(0, idealCount[q] - actual[q])
share[q]   = total > 0 ? actual[q] / total : 0

raw[q] = deficit[q] + baselineFrac[q] × maxPopulation × 0.1   // 基线保底项

// 低品质（gray, green）：缺口放大
if q.index <= 1:
  raw[q] *= (1 + SUPPLEMENT_LOW_TIER_DEFICIT_BOOST × (deficit[q] > 0 ? 1 : 0))

// 稀有蓝：存量饱和则压低
if q.index === SUPPLEMENT_MID_TIER_INDEX && actual[q] > 0
   && share[q] >= baselineFrac[q] × SUPPLEMENT_MID_TIER_SATURATION_RATIO:
  raw[q] *= SUPPLEMENT_MID_TIER_PRESENT_MULT

// 史诗+：只要塘里还有该品质，极大压低（未被钓走则不补）
if q.index >= SUPPLEMENT_HIGH_TIER_MIN_INDEX && actual[q] > 0:
  raw[q] *= SUPPLEMENT_HIGH_TIER_PRESENT_MULT

weight[q] = raw[q]
若 Σ weight = 0 → 回退 rollFishQuality()（极端空塘）
否则按 weight 加权随机选品质
```

**直觉对照**：

| 情况 | 补充倾向 |
| ---- | -------- |
| 灰/绿被钓空，紫/红仍在 | **大量补灰/绿**，几乎不补紫/红 |
| 各品质比例接近理想 | 接近初始 38/28/18… 分布 |
| 塘内仍有 2 条紫鱼未动 | 紫补充权重 ≈ 缺口×0.02，**极小** |
| 紫被钓光（actual=0） | 按 `deficit` 正常补，但仍低于灰绿优先级 |

## 4. D3 — 脱钩后加速成长（当前体长 +2%）

### 4.1 设计意图

鱼咬钩后**概率脱钩**（未上岸），按**当前体长的 2%** 即时增尺寸：

- 1.00m 脱钩 → 1.02m
- 0.30m 脱钩 → 0.31m（四舍五入后）

与品质上限无关的增量计算，触顶时截断至 `maxSize`。

### 4.2 常量

```typescript
/** 脱钩后尺寸乘数：newSize = sizeM × (1 + 本值) */
export const ESCAPE_GROWTH_BONUS_RATIO = 0.02;
```

### 4.3 公式

```
maxSize   = getQualityMaxSize(quality, species)
newSizeM  = round2(min(maxSize, sizeM × (1 + ESCAPE_GROWTH_BONUS_RATIO)))
```

**示例**：


| 当前体长          | 脱钩后        |
| ------------- | ---------- |
| 1.00m         | 1.02m      |
| 5.00m         | 5.10m      |
| 39.5m（上限 40m） | 40.00m（封顶） |


连续脱钩 5 次：`1.0 × 1.02^5 ≈ 1.104m`（复利式，仍受 maxSize 截断）。

### 4.4 触发时机（必须全部覆盖）


| 路径      | 文件                                             | 条件                      |
| ------- | ---------------------------------------------- | ----------------------- |
| 状态机自动脱钩 | `fishingStateMachine.ts` → `advanceFromHooked` | `outcome === 'escape'`  |
| 旧会话脱钩   | `fishingSession.ts` → `scheduleHookResolution` | `hook.escaped === true` |
| Bot 脱钩  | `bots.ts` / `fishingSession.ts` Bot 路径         | 同上                      |


**不触发**：玩家主动 `handleStopFishing` 收杆；已成功上岸。

## 5. D4 — 绝对长度生长曲线（全鱼共用）

### 5.1 设计意图

- 所有鱼共用**同一条「体长–时间」曲线** `L(t)`，与品质无关。
- 曲线为**减速型**：初期长得快，越大越慢；**第 7 天**曲线值恰为 **40m**（至尊上限）。
- 每条鱼有品质决定的 `maxSize`；当 `L(t) ≥ maxSize` 时**停止生长**（触顶封顶）。
- 因此：**低品质鱼更早达到各自上限**；仅至尊金品在 7 天达到 40m。

不再使用：统一 `GROWTH_DAYS` 日历天、`growth_multiplier` 个体波动、按品质上限百分比计算幼年尺寸。

### 5.2 常量（`shared/fishing.ts`）

```typescript
/** @deprecated 别名 = GROWTH_CURVE_DAYS */
export const GROWTH_DAYS = 7;

/** 生长曲线走完所需天数（至尊 40m 触顶时间） */
export const GROWTH_CURVE_DAYS = 7;

/** 曲线在 t=GROWTH_CURVE_DAYS 时的体长（= 至尊 QUALITY_SIZE_CAP） */
export const GROWTH_CURVE_CEILING_M = 40;

/** 减速曲线指数：越大则初期越快、后期越慢 */
export const GROWTH_CURVE_EXPONENT = 1.8;
```

### 5.3 曲线公式

**无上限时的标准体长**（仅与时间有关）：

```
ageDays   = max(0, (now - bornAt) / 86_400_000)
progress  = clamp01(ageDays / GROWTH_CURVE_DAYS)
L(t)      = GROWTH_CURVE_CEILING_M × (1 - (1 - progress) ^ GROWTH_CURVE_EXPONENT)
```

**实际目标体长**（品质封顶 + 不低于出生体长 + 单调不减）：

```
maxSize     = getQualityMaxSize(quality, species)
targetSizeM = min(maxSize, max(birthSizeM, L(ageDays)))
sizeM       = round2(max(currentSizeM, targetSizeM))
```

**性质**：


| 性质        | 说明                             |
| --------- | ------------------------------ |
| 与品质无关的速度  | 同龄鱼 `L(t)` 相同                  |
| 品质仅作上限    | gray 0.3m 在 L(t) 达 0.3m 后不再长   |
| 7 天 / 40m | 仅 gold（max=40m）在 7 天触顶         |
| 减速曲线      | progress=0.5 时 L≈13.4m，非线性 20m |


### 5.4 各品质触顶时间表（理论值）

由 `L(t) = maxSize` 反解 `t`（`growth_multiplier` 无）：


| 品质        | maxSize | 触顶约需时间      | 7 天末体长     |
| --------- | ------- | ----------- | ---------- |
| 普通 gray   | 0.30m   | **~41 分钟**  | 0.30m（已封顶） |
| 优良 green  | 0.80m   | **~1.9 小时** | 0.80m      |
| 稀有 blue   | 2.0m    | **~4.8 小时** | 2.0m       |
| 史诗 purple | 4.5m    | **~10 小时**  | 4.5m       |
| 传说 red    | 9.0m    | **~21 小时**  | 9.0m       |
| 神话 orange | 18m     | **~1.9 天**  | 18m        |
| 至尊 gold   | 40m     | **7 天**     | 40m        |


反解公式（实现参考）：

```
progress = 1 - (1 - maxSize / GROWTH_CURVE_CEILING_M) ^ (1 / GROWTH_CURVE_EXPONENT)
t_days   = progress × GROWTH_CURVE_DAYS
```

### 5.5 曲线采样表（无品质截断）


| 时间  | L(t)    |
| --- | ------- |
| 0   | 0m      |
| 6h  | ~1.6m   |
| 12h | ~3.0m   |
| 1d  | ~4.5m   |
| 2d  | ~9.5m   |
| 3d  | ~15m    |
| 5d  | ~28m    |
| 7d  | **40m** |


### 5.6 代码实现

```typescript
/** 标准生长曲线：给定年龄返回无品质截断的体长（米） */
export function calcStandardLengthAtAge(ageDays: number): number {
  const progress = clamp01(ageDays / GROWTH_CURVE_DAYS);
  const curve = 1 - Math.pow(1 - progress, GROWTH_CURVE_EXPONENT);
  return round2(GROWTH_CURVE_CEILING_M * curve);
}

/** 鱼塘鱼成长（替换 growFishSizeV2 逻辑） */
export function growFishSizeV2(
  quality: FishQuality,
  species: FishSpecies,
  currentSizeM: number,
  birthSizeM: number,
  bornAt: number,
  now = Date.now(),
): number {
  const maxSize = getQualityMaxSize(quality, species);
  const ageDays = Math.max(0, (now - bornAt) / 86_400_000);
  const standardL = calcStandardLengthAtAge(ageDays);
  const targetSize = Math.min(maxSize, Math.max(birthSizeM, standardL));
  return round2(Math.max(currentSizeM, targetSize));
}
```

**不新增** `growth_multiplier` 列；若 v0.3.1 草案已加，迁移中删除或忽略。

### 5.7 存量鱼

- 下次 `growAllFish` 按新曲线重算 `size_m` 即可。
- 建议迁移脚本：对所有 `pond_fish` 按 `born_at` 立即跑一次 `growFishSizeV2` 写回。

### 5.8 验收标准

- [ ] 同龄普通鱼与至尊鱼在 1 小时内 `L(t)` 相同，但普通鱼在 ~41min 触顶 0.3m 后不再长
- [ ] 至尊鱼 7 天后 `size_m ≈ 40m`
- [ ] 曲线前期快、后期慢（抽样 1d vs 6d 增量对比）
- [ ] 无 `tryBreed`、无 `growth_multiplier`

## 6. D6 — 脱钩率 & 收杆窗口：仅体长、非线性曲线

### 6.1 设计原则

| 原则 | 说明 |
|------|------|
| **与品质/物种无关** | 同体长的普通鱼与至尊鱼，脱钩率、收杆时间**完全相同** |
| **仅输入 `sizeM`** | 运行时不再读取 `quality`、`speciesId` 计算脱钩/收杆（咬钩率仍按品质×尺寸） |
| **非线性曲线** | 小鱼脱钩低/收杆短；大鱼脱钩高/收杆长；增速随体长递减缓 |
| **锚点** | **40m → 脱钩 98.5%、收杆 2 小时** |

`isNearMaxSize()` 仅 Debug 角标；`QUALITY_ESCAPE_BASE` / 近满硬编码**不再参与**脱钩/收杆运行时。

### 6.2 归一化体长

```
REFERENCE_SIZE_M = 40          // 曲线锚点体长（= 至尊上限）
n                = clamp01(sizeM / REFERENCE_SIZE_M)
curve(n)         = 1 - (1 - n) ^ CURVE_EXPONENT     // 减速型，n=0→0，n=1→1
```

**`CURVE_EXPONENT = 1.8`**（与生长曲线 easing 一致；初期快、后期慢）

### 6.3 脱钩率公式

```typescript
/** 40m 时脱钩率锚点（渔具减免前） */
export const ESCAPE_AT_40M = 0.985;

/** 体长脱钩曲线指数 */
export const SIZE_ESCAPE_CURVE_EXPONENT = 1.8;

export function calcSizeEscapeRate(sizeM: number): number {
  const n = clamp01(sizeM / REFERENCE_SIZE_M);
  const curve = 1 - Math.pow(1 - n, SIZE_ESCAPE_CURVE_EXPONENT);
  return Math.min(ESCAPE_RATE_MAX, ESCAPE_AT_40M * curve);
}
```

**运行时脱钩**（含个体偏置、渔具，**不含品质**）：

```
baseEscape = calcSizeEscapeRate(sizeM) × escapeMultiplier
effectiveEscape = clamp01(baseEscape - tackleEscapeReduction(tackleId))
```

- **删除** `calcQualitySizeEscapeRate` 在服务端咬钩/脱钩/Debug 路径的调用，改为 `calcSizeEscapeRate(sizeM)`
- `calcQualitySizeEscapeRate` 标 `@deprecated`（图鉴历史展示可保留，鱼塘不用）
- `NEAR_MAX_ESCAPE_RATE`、`QUALITY_ESCAPE_BASE` 标 `@deprecated`，鱼塘运行时不再读取

### 6.4 收杆窗口公式

```typescript
/** 40m 时收杆窗口锚点 */
export const HOOK_AT_40M_MS = 2 * 60 * 60 * 1000; // 7_200_000 ms = 2h

/** 最小收杆窗口（极小幼鱼） */
export const HOOK_MIN_MS = 2_000;

export const SIZE_HOOK_CURVE_EXPONENT = 1.8;

export function calcSizeHookDurationMs(sizeM: number): number {
  const n = clamp01(sizeM / REFERENCE_SIZE_M);
  const curve = 1 - Math.pow(1 - n, SIZE_HOOK_CURVE_EXPONENT);
  const span = HOOK_AT_40M_MS - HOOK_MIN_MS;
  return Math.round(HOOK_MIN_MS + span * curve);
}
```

- `calcHookDurationMs(quality, sizeM, speciesId)` **改为薄包装**：内部只调 `calcSizeHookDurationMs(sizeM)`，**忽略** quality/species
- **删除** `isNearMaxSize` → `FULL_SIZE_HOOK_MS` 分支
- `FULL_SIZE_HOOK_MS` 标 `@deprecated`（数值并入 `HOOK_AT_40M_MS`）
