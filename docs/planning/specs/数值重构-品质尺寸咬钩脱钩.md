# 数值重构：咬钩率 & 脱钩率 — 品质×尺寸体系

**版本**：v0.3.0-bite-escape-rework  
**状态**：**已实现**
**作者**：策划  
**日期**：2026-07-06

---

## 1. 设计目标

| 目标 | 说明 |
|------|------|
| 品质决定难度 | 品质越高，基础咬钩率越低、基础脱钩率越高 |
| 尺寸连续影响 | 同品质下，尺寸越接近上限，咬钩越难、脱钩越容易 |
| 公式化、去物种绑定 | `species.biteWeight` / `species.baseEscapeRate` 不再参与计算 |
| 数据可调 | 所有基础参数集中定义为常量，Admin 面板可读（后续可接运行时配置） |

---

## 2. 核心公式

### 2.1 归一化尺寸

```
n = sizeM / QUALITY_SIZE_CAP[quality]       ∈ [0, 1]
```

其中 `QUALITY_SIZE_CAP` 为现有品质尺寸上限，无变化：

| 品质 | 尺寸上限 |
|------|---------|
| gray（普通） | 0.30 m |
| green（优良） | 0.80 m |
| blue（稀有） | 2.00 m |
| purple（史诗） | 4.50 m |
| red（传说） | 9.00 m |
| orange（神话） | 18.00 m |
| gold（至尊） | 40.00 m |

### 2.2 基础咬钩率公式

```
baseBiteRate(quality, sizeM) = QUALITY_BITE_BASE[quality] × (1 − SIZE_BITE_K × (1 − n))
```

- **SIZE_BITE_K = 0.65**
- `QUALITY_BITE_BASE` 为满尺寸（n=1）时的咬钩率（最高值）
- 最小尺寸（n=0）时降至满尺寸值的 **35%**（最低值）
- **尺寸越大，咬钩率越高**

### 2.3 基础脱钩率公式

```
baseEscapeRate(quality, sizeM) = min(
  QUALITY_ESCAPE_BASE[quality] × (1 + SIZE_ESCAPE_K × n),
  ESCAPE_RATE_MAX
)
```

- **SIZE_ESCAPE_K = 0.50**（满尺寸时脱钩率升至基础值的 **150%**，再受上限截断）
- **ESCAPE_RATE_MAX = 0.97**（公式计算的脱钩率上限，即 97%）

## 4. 特殊规则：满尺寸鱼（NEAR_MAX）

满尺寸条件：`sizeM ≥ QUALITY_SIZE_CAP[quality] × NEAR_MAX_SIZE_RATIO（0.975）`

| 规则 | 现行 | 本次变更 |
|------|------|---------|
| 咬钩率特殊值 `NEAR_MAX_BITE_RATE = 3%` | 所有满尺寸固定 3% | **废弃**，改用品质×尺寸公式（金色满尺寸 ≈ 0.02%，远比 3% 更难） |
| 脱钩率特殊值 `NEAR_MAX_ESCAPE_RATE = 98.4%` | 所有满尺寸固定 98.4% | **保留**，覆盖公式结果；满尺寸鱼不论品质脱钩均为 98.4% |
| 收杆窗口 `FULL_SIZE_HOOK_MS = 2小时` | 满尺寸鱼咬钩后 2 小时窗口 | **保留不变** |

## 5. 个体浮动

出生或繁殖时，对公式计算的基础值施加 ±10% 随机浮动，结果**入库**：

```
individualBiteRate   = baseBiteRate(quality, sizeM)   × (0.90 + rand × 0.20)   // 4 位小数
individualEscapeRate = baseEscapeRate(quality, sizeM) × (0.90 + rand × 0.20)   // 4 位小数
```

- 浮动系数在出生时确定后**终身固定**（不随成长改变）
- 运行时每次判定以当前 `sizeM` 代入公式，个体浮动视为对公式基准的**乘数偏置**，需单独列存储

> 具体含义：运行时 baseBiteRate(quality, currentSizeM) × individualMultiplier；escape 同理
>
> 入库的是**个体偏置系数**（0.90 ~ 1.10），不是出生时的绝对值

## 6. 与现有机制交互

| 机制 | 交互方式 | 变化 |
|------|----------|------|
| 鱼饵加成 `baitBiteBonus` | 在 baseBiteRate 之后叠加，参与钓点贡献计算 | 不变 |
| 钓点运气 `spotMultiplier`（0~5） | 乘以（baseBite + baitBonus） | 不变 |
| 渔具脱钩减免（最多 −30%） | 在 baseEscapeRate 之后减去 | 不变 |
| Debug 面板 | 展示 baseBiteRate、baitBonus、spotBiteRate、escapeRate | 需同步更新展示来源 |

完整单条鱼运行时计算：

```
// 咬钩贡献（用于 tick 概率）
effectiveBite = clamp01(spotMultiplier × (baseBiteRate(q, s) × biteMultiplier + baitBonus))

// 脱钩（上钩判定时）
effectiveEscape = max(0, baseEscapeRate(q, s) × escapeMultiplier − tackleReduction)
```

## 7. 数值示例

### 7.1 史诗锦鲤，sizeM = 2.85m，无饵，运气 = 1.5，普通渔具（减免 8%）

```
n = 2.85 / 4.50 = 0.633
咬钩 baseBite = 0.80% × (1 − 0.65×(1−0.633)) = 0.80% × (1 − 0.65×0.367) = 0.80% × 0.761 = 0.61%
  → 个体偏置 ×1.05（举例）→ 0.64%
  → effectiveBite = 1.5 × (0.64% + 0%) = 0.96%

脱钩 baseEscape = 27.0% × (1 + 0.50×0.633) = 27.0% × 1.317 = 35.6%
  → 个体偏置 ×0.97（举例）→ 34.5%
  → effectiveEscape = 34.5% − 8% = 26.5%
```

### 7.2 至尊蓝旗鱼，满尺寸（sizeM = 39m），无饵，运气 = 2

```
n = 39 / 40 = 0.975 → 触发 NEAR_MAX_ESCAPE_RATE

咬钩 baseBite = 0.06% × (1 − 0.65×(1−0.975)) = 0.06% × (1 − 0.016) = 0.06% × 0.984 = 0.059%
  → effectiveBite = 2 × 0.059% = 0.118%（约每 7 小时判定到一次）

脱钩 → NEAR_MAX_ESCAPE_RATE 覆盖 = 98.4%（最优渔具后 = 68.4%）
```

### 7.3 对比：同品质 purple，最小尺寸（第1档）vs 满尺寸（第10档）

```
第 1 档 n=0.10：
  咬钩 = 0.80% × (1 − 0.65×0.90) = 0.80% × 0.415 = 0.33%（刚出生的幼鱼，不爱咬）

第 10 档 n=1.00：
  咬钩 = 0.80% × (1 − 0.65×0) = 0.80%（满尺寸大鱼，最爱咬钩）
  脱钩 = 27.0% × 1.50 = 40.5%（但一旦咬了很难收）
```

## 8. 代码改动范围

### 8.1 新增常量（`shared/fishing.ts`）

```typescript
/** 品质基础咬钩率（per 30s，n=0 时） */
export const QUALITY_BITE_BASE: Record<FishQuality, number> = {
  gray:   0.0500,
  green:  0.0320,
  blue:   0.0180,
  purple: 0.0080,
  red:    0.0035,
  orange: 0.0015,
  gold:   0.0006,
};

/** 品质基础脱钩率（n=0 时） */
export const QUALITY_ESCAPE_BASE: Record<FishQuality, number> = {
  gray:   0.055,
  green:  0.095,
  blue:   0.160,
  purple: 0.270,
  red:    0.430,
  orange: 0.600,
  gold:   0.650,
};

/** 满尺寸咬钩降幅系数（1 = 无变化；0.65 = 满尺寸降至 35%） */
export const SIZE_BITE_K = 0.65;

/** 满尺寸脱钩提升系数（0 = 无变化；0.50 = 满尺寸升至 150%） */
export const SIZE_ESCAPE_K = 0.50;

/** 公式计算脱钩率上限（满尺寸金色鱼约触顶） */
export const ESCAPE_RATE_MAX = 0.97;
```

### 8.2 新函数（替换现有函数）

```typescript
/** 取代 getFishBaseBiteRate + getSpeciesBiteRatePerTick
 *  QUALITY_BITE_BASE 为满尺寸（n=1）时的最高值；
 *  尺寸越大咬钩率越高，最小尺寸时降至满尺寸值的 35%。
 */
export function calcQualitySizeBiteRate(
  quality: FishQuality,
  sizeM: number,
): number {
  const n = clamp01(sizeM / QUALITY_SIZE_CAP[quality]);
  return QUALITY_BITE_BASE[quality] * (1 - SIZE_BITE_K * (1 - n));
}

/** 取代 species.baseEscapeRate + QUALITY_ESCAPE_BONUS */
export function calcQualitySizeEscapeRate(
  quality: FishQuality,
  sizeM: number,
): number {
  if (isNearMaxSizeByQuality(quality, sizeM)) return NEAR_MAX_ESCAPE_RATE;
  const n = clamp01(sizeM / QUALITY_SIZE_CAP[quality]);
  return Math.min(ESCAPE_RATE_MAX, QUALITY_ESCAPE_BASE[quality] * (1 + SIZE_ESCAPE_K * n));
}
```

### 8.3 数据库变更（`pond_fish` 表）

新增两列（存储个体偏置系数，非绝对值）：

```sql
ALTER TABLE pond_fish ADD COLUMN bite_multiplier REAL;    -- 个体咬钩偏置 0.90~1.10
ALTER TABLE pond_fish ADD COLUMN escape_multiplier REAL;  -- 个体脱钩偏置 0.90~1.10
```

> 旧列 `bite_weight` 可留作历史记录，但不再读取参与咬钩计算。

出生时赋值：

```typescript
const biteMultiplier   = parseFloat((0.90 + Math.random() * 0.20).toFixed(4));
const escapeMultiplier = parseFloat((0.90 + Math.random() * 0.20).toFixed(4));
```

### 8.4 运行时咬钩/脱钩使用（`fishingSession.ts`、`fishingDebug.ts`）

```typescript
// 现行：
const baseBite = getFishBaseBiteRate(fish, species);

// 改为（以成长后当前 sizeM 为基准）：
const baseBite = calcQualitySizeBiteRate(fish.quality, fish.sizeM)
               * (fish.biteMultiplier ?? 1.0);

// 现行（calcEscapeRate 内部 species.baseEscapeRate + QUALITY_ESCAPE_BONUS）：
const escape = calcEscapeRate(species, fish.quality, tackleId, ...);

// 改为：
const escape = Math.max(
  0,
  calcQualitySizeEscapeRate(fish.quality, fish.sizeM)
  * (fish.escapeMultiplier ?? 1.0)
  - tackleEscapeReduction(tackleId)
);
```

### 8.5 废弃

| 元素 | 位置 | 处理方式 |
|------|------|---------|
| `NEAR_MAX_BITE_RATE = 0.03` | `shared/fishing.ts` | 删除常量 + 删除 `isNearMaxSize` 在咬钩路径的分支 |
| `QUALITY_ESCAPE_BONUS` | `shared/fishing.ts` | 删除（合并进 `QUALITY_ESCAPE_BASE`） |
| `species.biteWeight` 参与计算 | `getSpeciesBiteRatePerTick` | 函数保留但不再被调用，标记 `@deprecated` |
| `species.baseEscapeRate` 参与计算 | `calcEscapeRate` | 函数保留但内部改用新公式 |
| `game_config` 的 `SPECIES_BITE_WEIGHT_*` | `gameConfig.ts` | 不再写入/读取（可保留列但清空用途注释） |

## 9. 数据迁移

启动时执行迁移脚本 `migrations/quality_size_bite_escape.ts`：

1. 为 `pond_fish` 表添加 `bite_multiplier`、`escape_multiplier` 列（若不存在）
2. 将现有鱼的 `bite_weight`（旧个体值）转换为 `bite_multiplier`：
   - `bite_multiplier = clamp(bite_weight / calcQualitySizeBiteRate(quality, sizeM), 0.90, 1.10)`
   - 若转换值超出 [0.90, 1.10]，直接赋 1.00
3. `escape_multiplier` 无历史数据，统一赋 1.00
