## 1. 背景与目标

### 1.1 背景

`FEAT-RETURN-02` 已交付进塘双价与自动回鱼管道，但体验仍有缺口：

1. **触发时机**：自动回鱼挂在 `accept_catch`（需玩家点「领取鱼获」），与「钓到即自动回鱼」的产品预期不符。
2. **即时反馈**：服务端 ACK 已带 `autoReturned` / 金币 / XP，客户端未消费，玩家不知道已回塘。
3. **离塘总结**：本局鱼获、回鱼收入、入场扣费与盈亏缺少结算页。
4. **Debug 鱼**：Debug 直发入包不走钓获结算，不会自动回塘（设计如此，需文档澄清）。

### 1.2 目标

- **回鱼档**：钓获成功即服务端结算并尝试自动回鱼，无需手动领取。
- 回鱼 / 入包结果通过 **`fish_catch_settled`** 即时 Toast/提示。
- **离塘**推送 **`pond_session_summary`**，主界面弹出结算弹窗（`PanelPondSettlement`）。
- 澄清 Debug 发鱼不触发自动回鱼；Debug 菜单改为 Overlay **顶层模态弹窗**（相对 STEAM-DESKTOP-12 的 UX 升级）。

### 1.3 非目标

- 改回鱼准入 / 金价 / 塘门禁（仍归 RETURN-03）。
- Debug 存量背包鱼批量自动回塘。
- Mobile 对齐。
- 进塘后中途改收费模式（仍归 RETURN-02）。

## 2. 用户与场景

| 角色 | 场景 | 期望结果 |
|------|------|----------|
| 玩家 | 回鱼档钓到达标鱼 | 无需点领取；Toast「已自动回塘 +金币」；鱼不进背包 |
| 玩家 | 回鱼档钓到不达标鱼 | 入包；Toast 说明未达标准 |
| 玩家 | 出售档钓到鱼 | 仍走 `fish_bite` → 手动领取（不变） |
| 玩家 | 离塘 | 主界面结算弹窗：鱼列表、回鱼收入、扣费、XP、盈亏 |
| 开发者 | Overlay 点 Debug | 全屏遮罩 + 居中顶层弹窗，盖住场景控件 |
| 开发者 | Debug 发放鱼获 | 入背包；**不**自动回塘（须文档/提示知晓） |

## 3. 功能范围

### 3.1 功能列表

| # | 功能点 | 优先级 | 说明 |
|---|--------|--------|------|
| 1 | 回鱼档即时结算 | P0 | resolving 钓获成功 → `settleAcceptedCatch`（跳过 pending 领取） |
| 2 | `fish_catch_settled` | P0 | 推送自动回塘 / 入包文案与数值 |
| 3 | Session 台账 | P0 | 本局鱼获、回鱼金、扣费、XP；离塘汇总 |
| 4 | 离塘结算 UI | P0 | `pond_session_summary` + `PanelPondSettlement` 预制体 |
| 5 | 客户端消费 ACK/事件 | P1 | Toast；抑制误导性「背包已更新」闪烁 |
| 6 | Debug 顶层弹窗 | P1 | Overlay `GameplayDebugModal` ZIndex 最高 |
| 7 | Debug 发鱼说明 | P2 | 文档：不走自动回鱼链 |

### 3.2 交互与 UI

**回鱼档 · 钓获**

```text
hook 成功 → lockPendingCatch
  → returnFeeMode === auto_return
      → settleAcceptedCatch（入包尝试 → tryAutoReturn）
      → emit fish_catch_settled + inventory_updated
      → 不 emit fish_bite（无「领取鱼获」）
  → else → emit fish_bite（既有领取流）
```

**离塘结算弹窗字段**

- 塘名、收费模式（出售档 / 回鱼档）
- 鱼获列表：种名、品质、尺寸、已回塘(+金) / 已入包
- 回鱼总收入、入场扣费、玩家/塘 XP、本局盈亏（收入 − 扣费）

预制体：`Assets/Resources/Desktop/Prefabs/PanelPondSettlement.prefab`  
Bake：Unity 菜单 `Fish Social → Bake PanelPondSettlement`

**Overlay Debug**

- 按钮「Debug」仅开关弹窗；内容区独立于右上角菜单栈
- `Panel.ZIndex=500`，高于场景与 OverlayPrompt
- Esc / 点遮罩 / 关闭按钮可关

### 3.3 规则与数值

- 回鱼准入 / 金价 / 塘门禁：**不变**，沿用 RETURN-03。
- Session 台账：进塘开账；扣费 tick 累加 `feesPaid`；每条结算记 catch；离塘推送后清账。
- Debug `grant_fish*`：仅 `addFishToInventory`，**不**调用 `settleAcceptedCatch` / `tryAutoReturnFish`。

## 4. 技术影响

### 4.1 数据模型

- 内存台账：`server/src/pondSessionLedger.ts`（按 playerId）
- 无新增 DB 表

### 4.2 API / Socket

| 类型 | 名称 | 说明 |
|------|------|------|
| Socket ↓ | `fish_catch_settled` | 钓获结算结果（含 `autoReturned`、金币、文案） |
| Socket ↓ | `pond_session_summary` | 离塘本局汇总 |
| Socket ↑ | `leave_pond` ack | 可附带 `sessionSummary` |
| Socket ↑ | `accept_catch` | 出售档仍用；回鱼档即时路径一般不再依赖 |

### 4.3 涉及文件（实现侧，供对照）

- `server/src/catchSettlement.ts`、`pondSessionLedger.ts`
- `server/src/fishingStateMachine.ts`、`socketPondHandlers.ts`、`playerProgress.ts`
- `shared/types.ts`
- Unity：`DesktopPondSettlementModalView.cs`、`DesktopShellUi.cs`、`SocialSocketClient.cs`
- Overlay：`MainWindow.xaml` / `.xaml.cs`（`GameplayDebugModal`）

### 4.4 埋点

- 沿用 `fish_auto_returned` / `fish_returned_to_pond` / `return_fee_mode_selected`
- `pending_catch_accept` 可带 `auto: true`（即时结算路径）
- 本票**不强制**新增埋点表行；若后续要查「离塘结算曝光」再补

## 6. 风险与依赖

| 风险 | 缓解 |
|------|------|
| 即时结算与 Overlay「领取」按钮竞态 | 回鱼档不发 `fish_bite`，无 pending |
