## 1. 目标

**唯一目标**：咬钩发生时，同塘所有玩家可看到「玩家 XX 头顶飘出咬钩鱼种」的文字动效。

> 主 spec §4（完整状态机）与 §5.2（阶段动画：baiting/casting/reeling/escaped 视觉表现）**本阶段不实施**，需求描述保留在 `状态机需求描述.md` 中，实施排期归属 C6。

## 2. 范围

### In-Scope

- 新增 socket 事件 `fishing_float_text`（服务端 → 客户端广播）
- 服务端：咬钩瞬间（A0 中判定成功那一刻）广播 hook 飘字；脱钩计时结束时广播 escape 飘字
- 客户端：在 `PondCharacter` 上方显示一条向上淡出文本，1.2s 消失
- 文案国际化：服务端只下发 `kind` + `speciesId` + `quality`，客户端本地化
- 客户端限流：同一角色头顶最多 1 条，新来覆盖旧的
- `escape` 类型飘字**广播给同塘所有玩家**（依据 §4.11 决策 1：方案 B）

### Out-of-Scope

- `fishingPhase` 服务端状态机（保留旧 `status: 'idle' | 'fishing'`）
- `baiting/casting/hooked/resolving` 各阶段动画
- `hookEndsAt` 前端校正显示
- `PondCharacter` 姿态变化

## 3. 事件设计

### 3.1 `fishing_float_text` (Server → Client)

```ts
{
  userId: string;          // 触发飘字的玩家
  pondId: string;          // 用于客户端过滤
  kind: 'hook' | 'escape';
  speciesId: FishSpeciesId;
  quality?: FishQuality;   // hook 时携带，供客户端色彩差异化
  timestamp: number;       // 服务端毫秒时间戳
}
```

**广播规则**：
- `kind: 'hook'` → 广播给同塘所有玩家（含当事人）
- `kind: 'escape'` → 广播给同塘所有玩家（**§4.11 决策 1：方案 B，提升鱼塘氛围**）

### 3.2 客户端文案（i18n）

| key | zh-CN |
|---|---|
| `fishing.float.hook` | `🐟 {species} 咬钩！` |
| `fishing.float.escape` | `💨 {species} 脱钩了！` |

`{species}` 由 speciesId 查本地化表。金色/橙色品质可选前缀「✨」。

## 4. 客户端实现要点

- 新建组件 `mobile/app/components/FishingFloatText.tsx`
- 挂载在 `PondCharacter` 上方，绝对定位，向上偏移 40~60px
- 动画：opacity 0→1 (150ms) → 保持 (900ms) → 0 (150ms) + translateY -20px
- 同一 `userId` 已有飘字未消失时，直接替换文本并重置动画
- 组件在同塘视图卸载时清理所有飘字
- 品质颜色映射：`quality` → 文本颜色（gray/green/blue/purple/red/orange/gold）

## 5. 服务端触发点

在 A0 的 `fishingSession.ts` 中：

**咬钩瞬间**（`weightedPick` 之后、计时开始前）：

```ts
broadcast(pondId, 'fishing_float_text', {
  userId, pondId,
  kind: 'hook',
  speciesId: target.speciesId,
  quality: target.quality,
  timestamp: Date.now(),
})
```

**hookDurationMs 到期且 `escaped === true`**：

```ts
broadcast(pondId, 'fishing_float_text', {
  userId, pondId,
  kind: 'escape',
  speciesId: target.speciesId,
  quality: target.quality,
  timestamp: Date.now(),
})
```

**封装要求**：将上述两次广播封装成 `emitFishingFloatText(pondId, userId, kind, target)` 单一函数，将来 C6 状态机接入时只改调用位置，签名不变。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 未来状态机开发时飘字触发点需迁移 | 封装成 `emitFishingFloatText(...)` 函数，C6 上线只改调用位置 |
| 飘字与将来阶段动画时序冲突 | 本阶段飘字生命周期 1.2s < 最短 hookDurationMs 2s，无冲突 |
| 满塘同时多人咬钩造成飘字轰炸 | 客户端每角色单条限流已解决；服务端不做额外节流 |
