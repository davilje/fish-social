## 1. 背景与问题

当前运营平台已从「裸链接列表」进化为「有说明的入口页」（分区、BI vs 归档辨析、Admin 页签说明、health/ready 中文展示）。  
仍存在体验缺口：

| # | 痛点 | 表现 |
|---|------|------|
| U1 | **打开后仍要自己找「今天看什么」** | 卡片墙并列，无「今日运维」主路径 |
| U2 | **昨日日报需两跳** | 先进索引再点日期，不能一键打开 T-1 `report.html` |
| U3 | **日批成败不可见** | 计划任务跑没跑、exit code、日志路径不在入口页 |
| U4 | **告警要进报告才看得见** | `summary.alerts` 有红项，入口无条数提示 |
| U5 | **Admin 与入口脱节** | 无 tab / playerId 深链；排障要手动切页签、粘贴 ID |
| U6 | **工程入口挤占主视线** | BI CSV、xlsx、cron 说明与「每日必看」同级，角色混乱 |

**北极星**：策划/运维早上打开 `/ops/`，**10 秒内**知道：服务是否活着、昨日日报在哪、有没有红灯、日批是否成功；需要排障时能一键进 Admin 对应页签。

---

## 2. 目标用户与场景

| 角色 | 主场景 | 成功标准 |
|------|--------|----------|
| 策划 | 日会前看昨日产量与告警 | 一键打开昨日日报；入口可见告警条数 |
| 运维/开发 | 排障「某人卡住」 | 深链 Admin Timeline / Live，可带 `playerId` |
| 数据同事 | 拉 CSV 做表 | 在折叠区找到 BI，不被当成看板 |

## 3. 信息架构（目标）

```
运营平台.html
├── 【今日运维条】← 首屏唯一主焦点（本需求核心）
│   ├── 服务：health / ready 摘要（沿用并收进条内）
│   ├── 昨日日报：深链 + KPI 三数（钓获 / DAU / 断线）
│   ├── 告警：T-1 alerts 条数（bad/warn）+ 跳转报告锚点
│   └── 日批：上次运行时间 / 目标日 / exit / 日志提示
├── 【每日必看】仅 3 卡
│   ├── 昨日运营日报（同深链，可与条上按钮重复强调）
│   ├── 线上 vs 模拟
│   └── 策划进度看板
├── 【实时运维】Admin 内嵌 + 快捷深链
│   ├── 鱼塘概览 / Timeline / Fishing Debug / 业务健康 / Live
│   └── 游戏 Web :8082
├── 【服务探活】可保留详细 dl，或并入今日条后降为折叠
└── 【更多 · 工程与导出】默认折叠
    ├── 分析归档索引（历史 + 模拟）
    ├── BI CSV（Excel 下载）
    ├── 埋点表 / 计划表 xlsx
    ├── 日报定时任务说明
    └── 开发流程 / preview
```

原则：**首屏不做卡片墙**；工程词不进入「每日必看」。

## 4. 功能需求（分阶交付）

### 4.1 阶段 A — 今日运维条（必须 · MVP）

#### A1. 昨日日报一键打开

| 项 | 要求 |
|----|------|
| 日期 | Asia/Shanghai **昨天（T-1）** |
| 链接 | `/analytics/daily/<T-1>/report.html`（file 协议用 `docs/analytics/daily/...`） |
| 缺失时 | 显示「昨日报告尚未生成」+ 链到分析索引 + 提示 `npm run analytics:daily` / 计划任务 |
| 文案 | 按钮主文案：**打开昨日运营日报（YYYY-MM-DD）** |

#### A2. 昨日 KPI 摘要（入口可见）

从 T-1 的 `compact.json`（或增强后的字段）读取并展示：

| 展示 | 字段来源 |
|------|----------|
| 日钓获 | `totalCatches` |
| 活跃玩家 | `activePlayers` |
| 断线次数 | `totalDisconnects`（已有则用；无则显示 —） |

点击数字区域也可进 `report.html`。

#### A3. 告警条数

| 项 | 要求 |
|----|------|
| 数据 | T-1 `summary.json` 的 `alerts[]`，或把 `alertCount` / `alertBad` / `alertWarn` 写入 `compact.json`（**推荐后者**，入口只拉小文件） |
| UI | 「告警 N（红 x · 黄 y）」；N=0 显示「无告警」 |
| 跳转 | 打开报告并尽量落到告警区（`report.html#alerts`；生成器需保证锚点存在） |

#### A4. 日批任务状态

| 项 | 要求 |
|----|------|
| 写入方 | `scripts/ops/run-daily-analytics.ps1`（及直接 `npm run analytics:daily` 结束时）写出状态文件 |
| 路径 | **`docs/analytics/daily-batch-status.json`**（随 analytics 静态服务可读） |
| 字段 | 见 §5.1 |
| UI | 「上次日批：时间 · 目标日 · 成功/失败」；失败时提示看 `logs/daily-analytics/` |
| 缺失 | 「尚无日批记录（可安装计划任务）」+ 链到 `docs/ops/daily-analytics-cron.md` |

#### A5. 服务状态收进今日条

- 复用现有 `/health`、`/ready` 探测逻辑。  
- 今日条左侧/顶部展示：进程是否活着、DB 是否 ok、真人在塘（可选）。  
- 原「第三节服务探活」可改为折叠「原始 JSON / 详细字段」，避免与今日条重复占首屏。

#### A6. 验收（阶段 A）

- [ ] `/ops/` 首屏可见「今日运维条」，含 T-1 日报按钮  
- [ ] 有报告时展示 KPI 三数；无报告时友好降级  
- [ ] 告警条数与 `summary.alerts` 一致（或与 compact 增强字段一致）  
- [ ] 跑完日批后 `daily-batch-status.json` 更新，入口刷新可见  
- [ ] `npm run verify:ops-portal-links` 扩展覆盖今日条关键文案/链接模式  
- [ ] file:// 打开时相对路径仍可用（与现有 `data-href-file` 策略一致）

### 4.2 阶段 B — 角色分区与 Admin 深链（必须 · 紧随 A）

#### B1. 「每日必看」收敛为 3 卡

仅保留：昨日日报、线上 vs 模拟、策划进度看板。  
分析归档索引、BI CSV、xlsx、cron、开发说明 → **「更多 · 工程与导出」** `<details>` 默认折叠。

#### B2. Admin URL 深链

| 能力 | URL 约定（admin-web） |
|------|----------------------|
| 切页签 | `/admin-web/?tab=ponds\|timeline\|debug\|health\|live` |
| 预填玩家 | 同上 + `&playerId=<id>`（Timeline / Live / Debug 读取） |
| 预填塘 | Debug：`&pondId=pond-calm`（可选） |

实现：

1. `admin-web/src/App.tsx` 启动时读 `URLSearchParams`，设置初始 `tab`。  
2. Timeline / Live / FishingDebug 挂载时若有 `playerId` 则预填并**自动查询一次**（Live 自动 connect）。  
3. 运营平台今日条或「实时运维」区提供快捷按钮：「鱼塘概览」「查玩家 Timeline」「Live 盯梢」。  
4. 内嵌 iframe：`src` 可跟 `?tab=ponds`；全屏链接同参。

#### B3. 从日报到排障（轻量）

- 日报 `report.html` 中若展示 playerId，链到  
  `/admin-web/?tab=timeline&playerId=...`（能链则链；没有 ID 的汇总行不强求）。  
- 本阶段最低要求：入口页提供 **playerId 输入框 +「打开 Timeline」**（可选增强，不阻塞 B2）。

#### B4. 验收（阶段 B）

- [ ] 每日必看仅 3 张主卡；工程入口默认折叠  
- [ ] `/admin-web/?tab=live&playerId=xxx` 打开即到 Live 且已填 ID  
- [ ] 运营平台快捷按钮能打开对应 tab（新标签或改 iframe src）  
- [ ] 无回归：无 query 时 Admin 行为与现网一致

## 5. 数据与接口契约

### 5.1 `docs/analytics/daily-batch-status.json`

```json
{
  "updatedAt": "2026-07-14T00:30:08.123Z",
  "dateKey": "2026-07-13",
  "exitCode": 0,
  "ok": true,
  "source": "scheduled-task",
  "logFile": "logs/daily-analytics/daily-20260714-003002.log",
  "durationMs": 1820,
  "message": optional string
}
```

| 字段 | 说明 |
|------|------|
| `dateKey` | 本次聚合的目标自然日（通常 T-1） |
| `exitCode` / `ok` | 流水线退出码；`ok === (exitCode===0)` |
| `source` | `scheduled-task` \| `manual` \| `npm` |
| `logFile` | 相对仓库根路径，便于人肉打开 |

写入时机：`run-daily-analytics.ps1` 在 FINISH 时；建议 `daily-pipeline.mjs` 成功/失败末尾也写一份（保证不经 ps1 的手工跑也有状态）。

### 5.2 `compact.json` 增强（推荐）

在现有字段上增加（日批生成时写入）：

```json
{
  "alertCount": 2,
  "alertBad": 1,
  "alertWarn": 1
}
```

由 `daily-pipeline.mjs` 在写 compact 时从 `summary.alerts` 统计。旧目录无此字段时入口按「未知 / 点进报告查看」降级，或回退 fetch `summary.json`（允许但非首选）。

### 5.3 报告锚点

`generate-daily-ops-report.mjs` 告警区块加 `id="alerts"`（若尚未有）。

### 5.4 Admin 深链参数

| 参数 | 值 | 消费方 |
|------|-----|--------|
| `tab` | `ponds` \| `timeline` \| `debug` \| `health` \| `live` | `App.tsx` |
| `playerId` | 字符串 | Timeline / Live / Debug |
| `pondId` | 如 `pond-calm` | Debug（可选） |
| `hours` | 数字 | Timeline（可选，默认 24） |

非法 `tab` → 回退 `ponds`。

## 7. 交互与文案约束

1. 今日运维条标题固定：**今日运维**。  
2. 区分「服务无响应」与「报告未生成」与「日批失败」三种黄/红提示，勿混用一句「出错了」。  
3. BI 文案必须继续出现「Excel / 下载 / 不是看板」。  
4. 不要求登录运营平台页本身；Admin 仍要密钥。  
5. 移动宽度 `<720px`：今日条纵向堆叠，主按钮可点区域足够大。
