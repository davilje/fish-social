## 2. 问题与根因

### 2.1 实际仍每 5 秒判定（P0 必改）

**设定**：A0-v2 `FISH_BITE_CHECK_MS = 30_000`。

**现网**：

- `shared/constants.ts` 已是 30000
- 服务端 **`getBiteCheckMs()` 读 `game_config` 表**，旧库或 Admin 热更可为 **5000**
- 咬钩循环、Bot 循环均用 `getBiteCheckMs()` → **运行时可能是 5s**
- Debug 鱼格文案 **写死 `/30s`**，与真实间隔脱钩，加剧误判

**修复目标**：DB + 运行时 + Debug 展示 **统一为 30 秒**。

---

### 2.2 Debug 基础咬钩率全是 2.00%（P0 必改）

**公式**（计算逻辑不变）：

```text
baseBite = getFishBaseBiteRate(fish)   // 满尺寸 0.03，否则 pond_fish.bite_weight 或 species 默认
```

**根因**：`fishingDebug.ts` 对 `baseBite` 做 **`round2()`（保留 2 位小数）** 再交给 UI；`0.024 → 0.02`，展示为 **2.00%**，个体差异被抹平。

**修复目标**：

- API / UI 展示 **真实 `baseBite`**，格式 **`(baseBite × 100).toFixed(2) + '%'`**（百分比 **2 位小数**）
- 例：`0.024 → 2.40%`，`0.016 → 1.60%`，满尺寸 `0.03 → 3.00%`
- **本点咬钩** `spotBiteRate`、**鱼饵加成** `baitBonus`、**本钓位 tick%** 等同规则

**注意**：展示精度与存储精度分离——鱼塘内计算仍可用既有 `round2`；**仅 Debug 输出与展示用 4 位小数或直接原值转 %**。

---

### 2.3 本钓位约 100% / 30 秒（不在本单修公式）

**公式**（A0-v2 §4.3，实现正确）：

```text
tickBiteChance = min(1, Σ effectiveBite_i)
```

满塘 48 条鱼时，Σ 常 ≥ 1，故显示 **100.00%** 属 **公式结果**，非 Debug 算错，**本版本不调整概率模型**。

**本版本仅要求**：

- 摘要行使用 **真实 `checkMs`**（30s 修复后即为「/ 30 秒」）
- tick 概率 **如实显示 2 位小数**（如 `100.00%`、`96.50%`）
- 可选一行说明：「多鱼贡献相加封顶 100%」（文案，非改数）

---

### 2.4 饵加成文案不一致（P0 必改）

**统一公式**（不改）：

```text
baitBiteBonus = globalBonus + affinityByDiet[diet]
```

| 界面 | 现状 | 目标 |
|------|------|------|
| ShopModal | 仅 `globalBonus`；偏好 `+0.06` 小数 | 基础 +X% + 食性偏好 +Y%（均 **2 位小数 %**） |
| CodexModal | `(+0.08)` 小数 | `(+8.00%)` 或与 Debug 一致 |
| Debug | 按鱼种 `baitBonus` ✓ | 保持，格式 **+X.XX%** |

商店展示 **全局 + 偏好分行**；对单鱼总加成 = 基础 + 对应食性，与 Debug 可对照相加。

## 3. 修复项（开发清单）

### 3.1 服务端：咬钩间隔固定 30 秒

| ID | 动作 |
|----|------|
| S1 | **启动时强制** `game_config.FISH_BITE_CHECK_MS = '30000'`（覆盖 5000 及任意非 30000 旧值，或迁移无条件写入一次） |
| S2 | `getBiteCheckMs()`：若 DB 缺失则 30000；**建议**对 `FISH_BITE_CHECK_MS` 忽略小于 30000 的覆盖，或 Admin 修改该键需确认 |
| S3 | `initGameConfig`：`INSERT OR IGNORE` 改为 **upsert 默认 30000**（新装与升级一致） |
| S4 | 启动日志：`Fish Social: bite check interval = {getBiteCheckMs()}ms` |
| S5 | Bot 咬钩循环与玩家循环 **同一 `getBiteCheckMs()`**（已用则验收即可） |

**验收**：重启服务后 Admin 配置为 30000；`waiting` 阶段 **每 30 秒** 触发一次判定（非 5 秒）。

---

### 3.2 Debug 面板：数值精度与间隔文案

| ID | 动作 |
|----|------|
| D1 | `fishingDebug.ts`：`fishBiteRate` / `baitBonus` / `spotBiteRate` / `tickBiteChance` **去掉 round2 或改用 round4** 再下发 |
| D2 | `AdminPondFishDebugGrid`：统一 `formatProb(rate) => (rate * 100).toFixed(2) + '%'` |
| D3 | 所有 **`/30s` 硬编码** 改为 `` `/${Math.round(data.constants.checkMs / 1000)}s` ``（摘要 + 鱼格） |
| D4 | 满尺寸鱼 `baseBite === 0.03` 显示 **3.00%** |

**验收**：

- 同塘不同鱼种可见 **2.40% / 2.00% / 1.60%** 等差异，非清一色 2.00%
- 摘要「判定间隔 **30** 秒」与配置一致

---

### 3.3 商店 / 图鉴：饵文案统一

| ID | 动作 |
|----|------|
| U1 | `shared/fishing.ts` 新增 `formatBiteRatePct(rate: number): string` → `(rate * 100).toFixed(2) + '%'` |
| U2 | **ShopModal**：`每 30 秒 +{formatBiteRatePct(globalBonus)}`；偏好标签 `草食 +6.00%` |
| U3 | **ShopModal** 副说明：「对每种鱼 = 基础 + 对应食性偏好（图鉴/Debug 可查）」 |
| U4 | **CodexModal**：推荐饵 `+{formatBiteRatePct(baitBiteBonus(...))}` |
| U5 | Debug 鱼格「鱼饵加成」「本点咬钩」复用同一 `formatBiteRatePct` |

**验收**：活虾 + 肉食鱼 — 商店基础 **4.00%**、偏好 **14.00%**；Debug/图鉴该鱼 **18.00%**。
