## 1. 目标

引入鱼饵购买消耗、渔具永久购买；在服务端咬钩/脱钩公式中生效；玩家有明确金币出口。

## 2. 范围

### In-Scope

- `player_gear` 表新建
- 鱼饵、渔具静态配置
- 商店 REST API 与背包 API
- 服务端咬钩/脱钩公式接入装备读取
- 鱼塘场景「补给」入口 + 商店 UI

### Out-of-Scope

- 鱼种偏好（B1 交付）
- 渔具耐久（P2 归 C3）
- 付费货币（永远不做）

## 3. 数据模型

### 3.1 新表 `player_gear`

```sql
CREATE TABLE player_gear (
  player_id TEXT PRIMARY KEY,
  equipped_bait TEXT NOT NULL DEFAULT 'basic',
  equipped_tackle TEXT NOT NULL DEFAULT 'basic',
  bait_inventory TEXT NOT NULL DEFAULT '{}',        -- JSON: { corn: 10, ... }
  owned_tackles TEXT NOT NULL DEFAULT '["basic"]',  -- JSON array
  updated_at INTEGER NOT NULL
);
```

**迁移**：为所有现有玩家插入默认行。

## 5. REST API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/shop/baits` | 鱼饵列表 |
| POST | `/api/shop/baits/buy` | body: `{ baitId, quantity }` |
| GET | `/api/shop/tackle` | 渔具列表 |
| POST | `/api/shop/tackle/buy` | body: `{ tackleId }` |
| POST | `/api/player/equip/bait` | body: `{ baitId }` |
| POST | `/api/player/equip/tackle` | body: `{ tackleId }` |
| GET | `/api/player/gear` | 当前装备与背包 |

**错误码**：
- `INSUFFICIENT_GOLD`
- `ALREADY_OWNED`（渔具重复购买）
- `INVALID_ITEM`
- `NOT_IN_INVENTORY`（装备未拥有的鱼饵/渔具）
- `INVALID_QUANTITY`（购买数量 ≤ 0 或过大）

**幂等**：`POST buy` 支持客户端幂等 token（header `X-Idempotency-Key`），10 分钟窗口内相同 key 返回同一结果，避免双击双扣。

## 6. 咬钩 / 脱钩公式接入

服务端 tick 计算时读取玩家 `player_gear`：

```
w_i        += baitBiteBonus(player.equippedBait)     // B0 只用 global bonus
escapeRate -= tackleEscapeReduction(player.equippedTackle)
escapeRate  = clamp01(escapeRate)
```

## 7. 饵消耗规则

**扣款时机**（依据 §4.11 决策 5：不延迟）：
- **`baiting` 阶段起点**扣 1 个当前装备付费饵；basic 不扣
- 未来 C6 状态机上线后，此触发点保持不变

**A0 无状态机时的临时口径**（B0 与 A0 并存时期）：
- A0 尚未引入 `baiting` 阶段，因此临时定义：**每次触发咬钩判定成功那一刻扣饵**
- C6 状态机上线后，扣饵点无缝迁移到 `baiting` 阶段起点，玩家无感知

**背包耗尽处理**：
- 若装备的付费饵背包数量为 0，服务端自动将 `equipped_bait` 回退到 `basic`
- 广播 `bait_depleted { previousBaitId }` 事件通知客户端弹提示

**脱钩不退饵**：脱钩后已扣的饵不返还（符合「饵被吃了」的语义）。

## 10. 验收标准

- [ ] 金币不足购买返回 `INSUFFICIENT_GOLD`，不扣款
- [ ] 重复购买渔具返回 `ALREADY_OWNED`
- [ ] 装备 pellet 饵后，A2 debug 面板中同一鱼 `effectiveWeight` 上升 0.08
- [ ] 装备 master 竿后，debug 面板中 `escapeRate` 下降 0.18（clamp 后）
- [ ] 背包 corn=1 场景：一次咬钩后 corn=0，第二次咬钩前自动回退 basic 并前端提示
- [ ] 并发买同一渔具（双击）不会双扣款（幂等 token 生效）
- [ ] 未登录访问 shop API 返回 401

## 11. 风险

| 风险 | 缓解 |
|---|---|
| 购买接口重放攻击 | 幂等 token + 服务端事务 |
| 钱包字段并发写 | 复用现有金币扣减事务锁 |
| A0 无状态机导致扣饵点尴尬 | 临时口径明确「咬钩判定成功时扣」，C6 无缝迁移 |
| 大额购买（如买 999 个 live）金币溢出 | 单次购买 `quantity ≤ 100` 上限 |
