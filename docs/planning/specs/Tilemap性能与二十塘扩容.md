## 1. 背景与目标



### 1.1 背景



- 96×96 稠密图 + 每格 `View`/`Pressable`，缩小时一屏数千节点 → Web 卡顿  

- 世界入口格仍有 🎣 等图标，干扰星露谷式纯色块观感  

- 仅 4 塘、陆地多为矩形块，空间单调  



### 1.2 目标



| # | 目标 |

|---|------|

| A | **性能**：世界（及鱼塘若同类问题）改为低节点绘制（Canvas/Skia/合并色块等任选）；**单点命中**取 `pondId`，禁止每格 Pressable；拖拽 transform 与 culling **节流** |

| B | **剔除图标**：世界地图不绘制钓点/入口 emoji 或独立图标（含 🎣）；入口仅靠色块/岸线区分即可 |

| C | **更大场景**：世界边长明显大于 TILE-2（建议 **128～160** 或等价像素量）；鱼塘内网格也可略放大（可辨 20 岸位） |

| D | **20 塘位**：`shared` 配置 **20** 个可进 `pondId`（服务端跟 `PONDS` 走）；世界地图上 20 处不规则陆地/水域足迹 |

| E | **非标准矩形**：每个塘的陆地/水面 footprint **不得**为单一轴对齐矩形；须用 L/T/阶梯/多矩形拼合或手绘连通格集合，外形可辨差异 |



### 1.3 非目标



- Unity / Tiled 编辑器完整管线  

- 改咬钩公式、人数上限数值本身  

- 为性能引入 WebGL 引擎重写全客户端

## 2. 功能范围



### 2.1 性能（世界优先，塘内同构则一并改）



| 手段 | 要求 |

|------|------|

| 绘制 | 视口内**不以数千 React 节点**铺色；推荐离屏 Canvas/`react-native-skia` 或同色合并矩形层 |

| 点击 | 视口一次 hit-test：`screen → tile → pondId` → 弹窗；void 无子弹 |

| 相机 | 平移优先改 transform/ref；`viewBox`/重绘用 rAF 或按格步进，禁止每 pointermove 全量 reconcile TileLayer |

| 缩放 | 限制一屏最大绘制格数或提高合理 `minScale`，避免「一屏 8000 格」 |



### 2.2 视觉与内容



| 项 | 要求 |

|----|------|

| 图标 | 世界层无钓点/入口图标与 emoji 标签 |

| HUD | 塘名/人数可保留屏幕 HUD（TILE-2）；随缩放可读 |

| 20 塘 | 扩展 [`ponds.ts`](../../shared/ponds.ts) / [`worldTileMap`](../../shared/worldTileMap.ts) / [`pondTileMap`](../../shared/pondTileMap.ts)；命名与色板可辨 |

| 不规则 | 生成或手写 footprint：**禁止** `c0..c1 × r0..r1` 单矩形作为唯一陆地形状 |

| 鱼塘内 | 水面亦非单一矩形；仍 **20** `fish_spot` 绑现有 spot 规则；无入口图标 |



### 2.3 服务端



- 以 `PONDS` 列表为准自动进塘/生态/bot；扩到 20 后需确认 bot 总量与生态初始化可承受（可降每塘 bot 或分批激活）  

- **无**协议事件名变更

## 3. 验收标准



- [x] 世界地图拖拽/缩放在桌面 Web 明显更流畅（目标：拖动时不再每帧挂载数千 Pressable）  

- [x] 世界地图无 🎣/钓点类图标  

- [x] 世界尺寸大于 TILE-2 现行 96 边（或文档注明等价更大可浏览范围）  

- [x] 存在 **20** 个可点击塘区（`pondId`），外形互异且**非**标准单矩形  

- [x] 点击塘区仍弹进入窗；进塘可钓（新塘至少能 join + 占位；生态可与旧塘同模板）  

- [x] 鱼塘内 Tile 观感仍正交硬边；岸边 20 钓位；无误导 dock/入口图标  

- [x] HUD 与 Scene 分层不回退

## 4. 风险



| 风险 | 缓解 |

|------|------|

| 20 塘 × bot 压垮单机 | 调低每塘 bot 上限或仅部分塘刷 bot |

| Canvas 与 RN 手势冲突 | 命中与拖拽分层，沿用 TILE-2 短拖/点击阈值 |

| 生态表按塘扩容 | 跟现有 `PONDS` 初始化路径走，上线前跑 `verify:server-boot` |
