## 1. 背景与目标

当前验证版中，“离开 Lobby”只让本地玩家离开，服务端 Lobby 记录仍可能保留；邀请按钮固定邀请好友列表第一项，且发送成功后没有明确反馈。

目标：

- 明确普通成员离开、房主离开、房主关闭 Lobby 的生命周期语义。
- 处理房主离开后的 Lobby 转移或自动解散。
- 明确当前实际邀请的好友对象。
- 展示邀请请求的成功、失败和 Steam 客户端不可用状态。

## 2. 非目标

- 本需求不改变当前版本的实现。
- 不改变鱼塘数据、鱼塘会话和离线生态生命周期。
- 不预设最终 Lobby UI；正式开发时以产品方案重新确认。

## 3. 功能范围

| # | 功能点 | 优先级 | 说明 |
|---|--------|--------|------|
| 1 | Lobby 成员离开 | P1 | 普通成员离开不删除服务端 Lobby |
| 2 | 房主离开策略 | P1 | 明确房主转移或自动关闭，避免孤儿 Lobby |
| 3 | 关闭 Lobby | P1 | 房主主动关闭，撤销后续加入与邀请 |
| 4 | 邀请对象确认 | P1 | 显示被邀请好友名称、SteamID64 后四位和在线状态 |
| 5 | 邀请结果反馈 | P1 | 显示服务端 Token 生成、Steam 发送请求成功或失败 |

## 4. 技术影响

- `server/src/socialRoutes.ts`：补充 Lobby 成员/房主生命周期管理。
- `fish-social-unity/Assets/Scripts/Desktop/Social/SocialLobbyController.cs`：区分成员离开、房主关闭和邀请反馈。
- `fish-social-unity/Assets/Scripts/Desktop/Social/SteamSocialLobbyAdapter.cs`：返回或报告 Steam 邀请请求结果。
- `fish-social-unity/Assets/Scripts/Desktop/UI/DesktopShellUi.cs`：展示明确的邀请目标和结果。

## 5. 验收标准

- [ ] 普通成员离开不会删除服务端 Lobby。
- [ ] 房主离开不会产生无主且不可管理的服务端 Lobby。
- [ ] 关闭 Lobby 后，新的邀请和加入请求被明确拒绝。
- [ ] 用户能看到实际被邀请的好友。
- [ ] 邀请请求成功或失败都有明确提示，且邀请失败不破坏当前 Lobby 状态。
