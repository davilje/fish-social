# 验收清单（模板）

复制本文件为 `docs/planning/specs/vX.Y.Z-验收清单.md`（可选），或在 PR / 对话中逐项勾选。

| 字段 | 内容 |
|------|------|
| 版本 | v【X.Y.Z】 |
| 主 Spec | `docs/planning/specs/【文件名】.md` |
| 开发交接 | `docs/planning/specs/vX.Y.Z-开发交接.md` |
| 验收人 | 【姓名/角色】 |
| 验收日期 | YYYY-MM-DD |

---

## 1. 文档

- [ ] 主 spec 状态为 **已确认**（开发前）或 **已实现**（结案后）
- [ ] 开发交接文档与主 spec 范围一致，无遗漏 P0
- [ ] `项目开发需求计划表.xlsx` 中该行「有效状态」与 spec 一致

## 2. 自动化验收

```bash
# 按 spec 填写实际命令，例如：
npm run verify:【脚本名】
```

- [ ] 上述命令 exit code = 0
- [ ] 无新增 linter / typecheck 错误（若项目有 CI）

## 3. 功能验收（对照 spec §验收）

| # | 验收项（从 spec 复制） | 结果 |
|---|------------------------|------|
| 1 | 【例：断线 60s 内重连保留钓位】 | ☐ 通过 ☐ 不通过 |
| 2 | 【】 | ☐ 通过 ☐ 不通过 |
| 3 | 【】 | ☐ 通过 ☐ 不通过 |

## 4. 回归

- [ ] 未破坏关联版本基线（交接文档「前置」所列）
- [ ] 手测核心路径：进塘 → 钓鱼 → 收杆 / 离塘

## 5. 结案

验收全部通过后执行：

```bash
npm run planning:accept -- vX.Y.Z --verify verify:【脚本名】
```

- [ ] `planning:accept` 已执行
- [ ] `CHANGELOG.md` 已追加实现节
- [ ] `specs/README.md` 索引已更新（若为新需求）
