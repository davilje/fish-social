# 开发交接说明（模板）

策划 Agent 完成 PRD 后，将下方 **「交接提示词」** 整段复制给用户，由用户转交 **开发 Agent**。策划 Agent **不得** 同时修改源码。

---

## 元信息（策划填写）

| 字段 | 内容 |
|------|------|
| 功能名称 | 【例：他人主页优化】 |
| Spec 路径 | `docs/planning/specs/【文件名】.md` |
| 目标版本 | v【X.Y.Z】 |
| Spec 状态 | 已确认 |
| 策划完成日期 | YYYY-MM-DD |
| 来源 Agent | 策划 |
| 目标开发 Agent | （留空则自动路由） |
| 标签 | mobile, server |

---

## 交接提示词（复制给开发 Agent）

```
你是 Fish Social 项目的开发 Agent。本次只写代码，策划已完成。

## 必读文档（按顺序）
1. docs/planning/specs/【文件名】.md
   - 需求、交互、API、验收标准以此为准
2. docs/planning/product/v0.1.0-功能全景.md
   - 相关功能章节与数据模型
3. docs/planning/WORKFLOW.md §4
   - 源码位置对照

## 实现要求
- 仅实现 spec 中 P0 项；P1/P2 未写明则不做
- 遵守 spec「非目标」列表
- 改动范围控制在 spec §4.3 所列文件；避免无关重构
- 匹配现有代码风格与命名

## 完成后必须
- [ ] 自检 spec §5 全部验收标准
- [ ] 将 spec 状态改为「已实现」
- [ ] 更新 docs/planning/product/v0.1.0-功能全景.md 对应章节
- [ ] 在 docs/planning/CHANGELOG.md 追加实现记录（开发侧一条即可）

## 禁止
- 扩大需求范围
- 修改登录/认证架构（除非 spec 明确要求）
- 在无 spec 或 spec 非「已确认」时开工
```

---

## 策划侧自检（交给用户前）

- [ ] `specs/【功能】.md` 状态为 **已确认**
- [ ] `INDEX.md` 专项策划表已登记
- [ ] 验收标准为可勾选的明确条目
- [ ] API / 数据结构已写清或标注「复用现有 xxx」
- [ ] **未** 修改 `mobile/`、`server/`、`shared/`

---

## 用户操作

1. 确认 spec 内容（尤其是 UI 形态、权限规则）
2. **新开** 开发 Agent 对话（与策划对话分离）
3. **推荐**：`@docs/planning/prompts/【版本】-dev.prompt.md` +「按此实现」（无需复制）
4. 或：粘贴下方「交接提示词」代码块（若未生成 prompt 文件）
5. 开发完成后，由开发 Agent 更新文档；你可对照 spec §5 验收

策划收尾请运行：`npm run planning:confirm -- 【版本】`（含计划表 + prompt）
