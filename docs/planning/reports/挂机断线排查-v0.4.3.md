## 4. 阶段 3 — leave_pond 排除

### 4.1 埋点统计（SQLite 全库）

| event_type | 次数 | 说明 |
|------------|------|------|
| `disconnect` | 12 | 含 verify 脚本与 1 次真人 |
| `reconnect` | 11 | 几乎均来自 verify 脚本 |
| `disconnect_timeout` | **0** | 尚无超时清场落库记录 |
| `leave_pond` | 1 | 仅 verify 脚本 `navigation_social` |

### 4.2 会触发 leave_pond 的客户端路径（已实现 reason）

| reason | 触发 |
|--------|------|
| `navigation_back` | 返回地图 |
| `navigation_social` | 打开社交 |
| `navigation_profile` | 编辑资料 |
| `auth_redirect` | 未登录跳转 |
| `unmount` | 组件卸载（兜底） |
| `pond_change` | 切换鱼塘 id |

**不会触发**：同页商店 / 图鉴 / 背包 Modal。

### 4.3 归因规则（可用）

```
leave_pond 存在          → 主动离塘（查 reason）
disconnect + reconnect   → 短暂断线已恢复
disconnect + disconnect_timeout → 超 60s 踢人
disconnect 无 reconnect 无 timeout → 进程结束/关页/服务端重启等
reconnect 后仍有 disconnect_timeout → P0 回归（当前自动化未复现）
```

## 5. 阶段 4 — Admin / SQLite 对照

### 5.1 工具

```bash
# 玩家时间线
curl -s -H "X-Admin-Key: $ADMIN_KEY" \
  "http://localhost:3001/api/admin/metrics/fishing/player/p_1783361691987_r4tsfn3i?hours=48" | jq .

# SQL
sqlite3 data/fish-social.db "
SELECT datetime(created_at/1000,'unixepoch','localtime') AS at,
       event_type, payload
FROM fishing_metrics
WHERE player_id = 'p_1783361691987_r4tsfn3i'
  AND event_type IN ('disconnect','reconnect','disconnect_timeout','leave_pond','fishing_start','fishing_stop')
ORDER BY created_at DESC LIMIT 20;"
```

Admin UI：`AdminMetricsPanel` → 输入 `player_id` →「查询时间线」。

### 5.2 真人样本：鸽子（`p_1783361691987_r4tsfn3i`）

| 字段 | 值 |
|------|-----|
| 昵称 | 鸽子 |
| 最近一次 disconnect | 2026-07-08 09:13:22 |
| disconnect payload | `{"spotId":null}` |
| 同期 reconnect | **无** |
| 同期 leave_pond | **无** |
| 同期 disconnect_timeout | **无** |
| 此前钓鱼 | 2026-07-08 02:59 `fishing_start`（pond-calm） |

**解读**：

1. `spotId:null` 表示断线时已 **无钓位**（可能已收竿、已离席，或未占座即断开）。
2. 无 `leave_pond` → **不是**通过导航按钮主动离塘（或未升级到带 reason 的客户端）。
3. 无 `reconnect` → 断开后 **未成功重连** 或未再 `join_pond`。
4. 无 `disconnect_timeout` → 未等到 60s 清场（可能关页、杀进程、服务端重启、或用户未再进塘）。

**结论**：该样本 **无法定性为 P0 Bug**；更符合「连接结束但未完成重连链路」或「关页/进程退出」。
