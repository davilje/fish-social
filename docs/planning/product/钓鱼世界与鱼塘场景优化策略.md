## 1. 现状摘要

| 场景 | 现状 |
|------|------|
| 钓鱼世界 | 逻辑画布约 800×600；4 色块区域 → 四塘；信息弱，与塘内视觉脱节 |
| 鱼塘场景 | 固定 400×440；伪等距色块水塘 + 椭圆 20 钓点 + 色块二头身；四塘同几何 |
| 壳层 | 头栏工具多；竖屏场景常被社交面板挤矮；桌面侧栏并排 |

近期 hotfix（FEAT-UI-1/2）已改善状态气泡、飘字层级、在线列表与弹窗，**未**解决「好看 / 可辨塘 / 场景可读」。

## 2. 批判要点

### 2.1 钓鱼世界

1. 更像选房列表，不像可游走的「世界」。  
2. 与塘内伪等距气质不统一。  
3. 人数 / 生态 / 渔获等几乎不进地图，选塘动机弱。  
4. 头栏与地图抢戏，入口品牌感弱。

### 2.2 鱼塘场景

1. 硬编码画布 + 四塘同布局 → 辨识靠文案。  
2. 「等距」为 View 旋转色块，角色为几何体；长期观感像调试沙盘。  
3. 20 人挤环：遮挡、无 y 深度排序、未入座堆底行。  
4. HUD 层多，竖屏场景易缩成小窗。  
5. 自动占空位，缺少「点岸坐下」的空间感。  
6. 无独立美术方向管线（`docs/art/` 近空）。

## 3. 优化策略（分档）

### 3.1 P0 — 场景可读（优先）

| 方向 | 做法（简） |
|------|------------|
| 分塘背景 | 岸 / 水 / 天分层图或强色板差异，四塘可辨 |
| 深度 | 角色按 `y` 排序绘制 |
| 竖屏布局 | 场景全宽优先；社交改抽屉 / Tab 浮层，少长期占高 |
| 信息收拢 | 生态 / 时长收角标或场景内一行，缩短独立大条 |

### 3.2 P1 — 世界入口

| 方向 | 做法（简） |
|------|------------|
| 轻量 | 区域插画 + 在线人数 / 满员 / 简单差异标签 |
| 中量 | 与塘共用色板与岸线语言 |
| 慎重 | 大地图 / 走廊叙事：先补信息与氛围，再扩复杂度 |

### 3.3 P2 — 角色与钓点

| 方向 | 做法（简） |
|------|------------|
| 角色 | sprite / 简化立绘，替代纯色块二头身 |
| 交互 | 可点选钓点入座（替代纯自动占位） |
| 反馈 | 岸边轻动效（涟漪、竿尖），不必上完整引擎 |

### 3.4 明确非目标（本参考默认）

- 不改咬钩公式 / 8h 时长等核心数值（除非另开数值 spec）  
- 不强制引入游戏引擎或 3D  
- 不在本参考内规定具体 asset 清单与验收勾选（留给正式 FEAT）
