# 开发交接提示词：Steam 桌面端产品定位与信息架构（STEAM-DESKTOP-01）

你是 Fish Social 的产品/交互设计 Agent。请不要直接开发 Unity、server 或 mobile 业务代码；本阶段目标是把 Steam 桌面端第一版产品范围、主循环和交互规则整理成可供 Unity 与后端并行执行的定稿。

## 必读

1. `docs/planning/specs/Steam桌面端产品定位与信息架构.md`
2. `docs/planning/specs/Steam桌面端独立游戏转型计划.md`
3. `docs/planning/specs/Unity移植-分阶段需求清单.md`
4. `docs/planning/architecture/Unity迁移决策记录.md`

## 当前已确定

- 平台：Steam Windows 桌面端
- 定位：2D 多人社交桌面宠物；桌面宠物是第一入口，鱼塘是多人社交场景
- 客户端：Unity
- 服务端：Node 继续作为鱼塘、钓鱼、库存和社交权威
- 第一阶段实时传输：继续使用现有 Node Socket.IO
- Steam：身份、好友、Lobby、邀请；Steam Networking/Relay 后置评估
- RN：仅紧急修复
- 宠物：显示自己的猫咪、同塘其他玩家宠物和鱼塘环境
- 交互：右键产品区域打开小菜单，功能内容使用弹窗承载

## 需要产出

1. 一页产品定位和目标用户说明。
2. 启动→登录→进塘→挂机→收鱼→聊天→最小化的用户流程。
3. Unity 桌面端信息架构和页面/面板层级。
4. 窗口、最小化、托盘、通知、后台挂机规则。
5. 鱼塘主界面的 P0/P1 控件清单。
6. 对文档末尾所有待确认问题给出选项、推荐默认值和影响说明。
7. 将问题按“必须阻塞开发 / 可后置决定”分组。
8. 将桌面宠物主视图、鱼塘主窗口、右键菜单、弹窗层和系统托盘层拆成明确的 Unity UI/窗口任务。
9. 输出“启动 → 登录 → 宠物主视图 → 进塘 → 多人场景 → 挂机 → 通知 → 弹窗 → 托盘”的主流程和异常恢复流程。

## 设计边界

- 不复制移动端全部页面。
- 不把 Steam Lobby 设计成游戏权威服务。
- 不设计一塘一服务器。
- 不承诺尚未确认的托盘、开机启动、无边框、透明窗口或多平台支持。
- 不改动服务端玩法规则；如发现规则冲突，记录为待确认问题。
- 右键菜单只作用于 Fish Social 窗口/宠物区域，不拦截 Windows 桌面其他区域。
- 弹窗打开和关闭不得触发 `leave_pond`，不得重置鱼塘或宠物场景状态。

## 验收

- 所有关键歧义都有编号和明确选项。
- P0 主循环可以被 Unity 工程师直接拆成屏幕和交互任务。
- Steam 账号、Lobby、鱼塘、聊天和通知的责任边界清楚。
- 桌面宠物、鱼塘场景、同塘玩家显示和弹窗交互可以直接拆分为开发任务。
- 输出更新后的规格文档，不直接改业务代码。

建议角色：`@ui-designer` + `@producer`；用户答复已汇总，STEAM-DESKTOP-01 可进入 Unity/后端并行开发。
