## 硬约束（相对初稿的修正）

1. **写接口一律 `requireAuth`，playerId 以 JWT 为准**，禁止信任 body.playerId。  
2. **排行榜主数据源 = `fishing_metrics` 的 `pending_catch_accept` / `catch_accept`**，禁止只扫 `inventory`（卖鱼丢成绩）。  
3. **`player_id LIKE 'bot-%'` 不上榜**。  
4. 价值用 `calcFishSellPrice`；日/周界 **Asia/Shanghai**。  
5. 收鱼埋点 payload 须含 `quality` + `sizeM`（核对现路径；缺则补）。  
6. `playerPrivacy` 导出/删号覆盖 `post_likes` / `post_comments`。

## 实现摘要

### 点赞

- 表 `post_likes`；`social_posts.like_count`
- `POST /api/posts/:postId/like` → `{ liked, likeCount }`
- `GET /api/posts/:postId/likes`
- 墙/好友流返回 `likeCount` + `likedByMe`
- Socket `post_liked`

### 评论

- 表 `post_comments`；`social_posts.comment_count`
- `POST/GET/DELETE /api/posts/:postId/comments...`
- Socket `post_commented` / `post_comment_deleted`
- 3s 防刷；最长 200 字

### 排行榜

- `GET /api/leaderboard/{daily-biggest,weekly-king,pond/:pondId,rare}`
- `GET /api/leaderboard/my-rank`（需登录）
- 5 分钟缓存；可选 `leaderboard_snapshots` 表

## 验收

见三份规格 §5；建议脚本 `verify:social-v060`（可选）：点赞 toggle、评论 CRUD、榜单排除 bot、卖鱼后成绩仍在。
