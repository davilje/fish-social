## 必须达成的听感

1. 点击、打开、关闭、切签、提交等优先真实纸张触碰、翻页、纸签、铅笔、轻印章等物体声，轻短自然，不用电子哔声或过硬点击。一次导航只有一个语义 cue，不叠 click＋open；禁用、悬停和拖猫不发声。
2. 音乐柔和轻缓，以柔音钢琴、尼龙弦吉他、温暖弦乐等自然乐器为主。初值 60–76 BPM、1–2 个主奏声部并留白；避免尖锐电子音、铃音、密集高音及重电子节拍。旧 Pond Daylight 先审听／重配，不默认保留。
3. 水声更响、更清晰且真实，用可信录音或拟音体现落水、扰水、拍水的水体感。不能用提示音代替，也不能只变调同一滴水冒充大水花。
4. 咬钩／挣扎／拍水三类 × S/M/L/XL 四档 × 至少两变体，共至少 24 条；浮漂入水和撒饵各至少两条，总计至少 28 条水声。H/I 共享档位，浮漂／窝料不套未来鱼的尺寸。
5. 默认音乐 35%、音效 70%。水声有效事件 RMS 比旧版提高 3–5dB 是试听初值，结合默认混音调整，不仅提高总音量；小鱼水声也清楚，大鱼有水体重量而非刺耳。

## 实施顺序与播放约束

1. 制作纸张逐操作试听、20–30 秒两种配器 A/B、四档水声盲听和猫咪同屏对照，再完成 60–90 秒音乐循环。保留旧版可比较，每项标注版本、来源、许可和 hash，不能拿旧资源冒充新音色。
2. 重做六场景：正常钓鱼、脱钩／停钓、持续打窝、快速 UI、重复消息、8 人同塘；增加两个不同 catchId 紧邻、全部窗口隐藏但新咬钩有效、音乐压低期间静音恢复。试听脚本标注演示，不声称验证了真实 IPC。
3. Unity 独占音频设备，WPF 仅上报实际画面 marker；原生 Overlay 与 Unity 兜底只有一个表现 owner。冷解码不能提前响；取消／旧 epoch 丢弃、快照／重连静默，其他玩家自动声音为零。
4. 有界 AudioSource 仲裁：UI 1、钓鱼 2、猫叫 1，短音最多 4 个，音乐另 1 个。优先级咬钩>结果>普通动作水声>撒饵；高优先替换低优先并短淡出，不无限 PlayOneShot、不排队补播旧音。
5. 同一事件的预测／ACK／结算／重发只播放一次；不同真实咬钩／鱼获不能被 cue 冷却误吞。普通 UI 90ms、滑杆 180ms；挣扎／拍水合并至少 900ms，普通挣扎每 3 次视觉触发发声一次，拍水替换同动作弱水声；撒饵至少 2.16s。详细例外与参数按 spec。
6. 咬钩音乐 ×0.5 持续 0.7s，普通水花 ×0.7 最多 0.7s，80ms 压低／250ms 恢复；重叠取更低倍率和更晚结束时间，不修改保存音量。手动猫叫至少 2.5s、自动至少 12s，与确认声错开 120ms，取消或新咬钩丢弃旧庆祝。
7. 后台新咬钩开关默认开启；全部窗口隐藏时有效权威新事件可响一次，恢复显示不重播。Unity 隐藏而 WPF 可见属于正常表现，不能误静音。
8. H 删除三类视觉特效不等于删除 I 全部对应声音。收线、纸面确认、条件满足的脱钩触水声按 I spec，不能因此恢复 H 特效或旧弹窗。
9. 更新正式 StreamingAssets manifest、CREDITS、资源校验。短音 44.1kHz/16-bit/mono，音乐 stereo 流式；新增短音总解码≤4MiB。素材峰值≤−3dBFS，最坏组合无削波，最终 true peak 目标≤−1dBTP，循环无爆音。

## 专项验证

- 交付新旧 A/B、资源来源与许可、完整 cue／音量配置；缺可靠素材时列明缺项，不用占位音声称完成。
- 验证六场景与新增边界、四声部上限、不同结果不漏、后台提示、独立音量持久化、静音／压低恢复、循环衔接。
- 与 H 联测 0/150/400ms 冷加载、重复包、取消，Windows 至少 30 个事件画声差目标≤80ms，>120ms 诊断。
- 耳机与普通扬声器分别实听纸张质感、乐器柔和度、水声清晰度。逐条对照 I spec 验收。
