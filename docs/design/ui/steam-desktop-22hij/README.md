## 三项共用的方向

沿用已认可的原版猫咪钓鱼手账：奶油纸、棕色线条、低饱和湖蓝／草绿、暖橙强调。把注意力留给猫咪动作与鱼塘，不恢复钓获／脱钩弹窗，不恢复 Overlay 状态栏，不用全屏闪白和震屏提示。

[表现事件与验收基线](presentation-contract.md) 定义 H/I 共用的事件身份、动画标记、取消、静音与性能口径。参数是待实机调校的设计目标，不是已测结果。

## 关键动作时间线

```text
抛竿画面开始 ─ 挥竿声 ─ 浮漂真实接触水面 ─ 小水花＋入水声 ─ 等待轻波纹
真实咬钩事件 ─ 咬钩画面＋按鱼大小分档水面波纹／真实水声 ─ 现有读条／扰水
咬钩／发力中的真实破水 ─ S/M/L/XL拍水形态＋相应水体声 ─ 自然回落
收杆画面开始 ─ 收线声（I） ─ 仅实际触水交点生成一次S档H水花 ─ 入包纸面确认音（I，无视觉庆祝）
真实脱钩结果 ─ 沿用原动作 ─ 无脱钩特效 ─ 原动作实际触水时才有短水声（I）
```

主动停钓的普通收线、网络断开、切塘不冒充脱钩。H不制作脱钩视觉反馈；I的独立音效仅在权威结果和原动作接触满足时播放。

## 交付与实施次序

1. 固定实际代码／资源基线，统一 H/I 事件身份和源动画标记，先验证一轮钓鱼的冷加载、重复包和取消。
2. 制作H四档猫咪同屏水花对照与I纸张物音／器乐／真实水声v2试听，再接共用标记和资源预算；保留原功能开关便于 A/B。
3. J 单独更新 Web 交互预览：完成所有筛选、详情、收费确认、错误和返回状态，再按同一布局／动效参数接 Unity。
4. Windows 同版本、同塘同猫同窗口实测。设计完成、Web 通过、Unity 编译通过、Windows 验收分别记录。

开发入口：[统一交接](../../../planning/prompts/steam-desktop-22hij-design-dev.prompt.md)。建议责任角色为 Unity／Overlay 前端工程师，H 配合动效美术、I 配合声音设计、J 配合 UI／地图美术；后端只补经核验确实缺少的权威字段。
