## 必需资源

以下为首轮制作规格；修改帧数或画布必须同步九种猫咪的时间表、注册点及清单。逐帧 PNG 必须为真实姿态变化、透明背景、固定画布和地面注册点；爪子可以抬起，角色注册点不随爪子包围盒漂移。保持现有猫咪五官、体型、描边、毛色及斑纹，不再另起一套 Q 版风格。使用均匀环境光，不绘制地板光斑和外部投影。运行时按时间换帧，不以旋转整只猫、缩放贴图或骨骼关键帧替代动作。

## 逐帧动作分解

帧号从 00 开始。12 fps 以每帧 `1000 / 12` 毫秒计时，避免累计整数舍入造成循环漂移。

### HR-A01 打滚

- 00–02：从当前标准站姿降低重心，前爪弯曲；00 与待机交接姿态一致。
- 03–05：肩部先落地，身体侧躺，尾巴自然避让，不穿过躯干。
- 06–08：腹部朝上，四爪收拢，头部跟随身体转动，表情放松。
- 09–11：翻至另一侧，露出该侧真实花纹；不得用整图旋转代替绘制。
- 12–15：前爪支撑、后腿收回、起身，15 回到 00 的地面注册点与待机姿态。

默认只需一套固定翻滚顺序；原地朝向不适合时，先以已有合法过渡回到标准朝向，不在动画中突然镜像。单次播放约 1.33 秒。身体滚动可有局部横向位移，但结束不能改变世界位置。

### HR-A02 / A03 倒粮与粮食状态

- 00–02：量勺从上方进入，食盆维持空状态；00 可为透明帧。
- 03–04：勺口对准左食盆内部并倾斜，首批粮粒落下。
- 05–08：持续颗粒流，落点始终位于左食盆内；盆内粮食按落粒节奏累积。
- 09–10：颗粒停止并落稳，量勺回正离开；09 标记“粮食已到满量”。
- 11：量勺和空中颗粒离场，切换至持久满粮层，不能叠出两份粮食。

倒粮帧只包含量勺、空中粮粒；盆内累积粮食另导出同时间表的 `food-fill` 图层，满粮终帧与 `bowl-food/full.png` 完全对齐。`empty` 与 `finished` 可共同引用透明粮食层。托盘和右侧水碗始终复用原图；原碗图如已有粮粒，必须先准备经确认的空食盆基底再叠加，不能用覆盖色块遮掉。

现有碗图实际为 270×88，135×58 是布局框而非贴图宽高比；禁止把碗图拉伸到 270×116。落点、盆口和粮层需基于实际碗图测量后写入清单，不用布局框中心代替左食盆中心。

### HR-A04 行走

- 00–02：一组前后脚支撑、另一组抬脚前摆。
- 03–05：摆动脚落地、重心经过支撑区；后脚随后推进。
- 06–08：另一半步相反支撑，四肢位置有真实差别。
- 09–11：完成第二半步，11 到 00 连续，不重复拷贝 00 作为末帧。

采用自然四拍轻步，不做同时伸出四脚的滑行。逐帧标注着地脚与脚掌接触点；路径位移与步幅匹配，移动速度改变时同步播放速率。动画稿只绘制原地步态，不把世界路径位移画入每帧。头部可轻微起伏，但不改变头部尺度。

到达猫窝或食盆前减速，在支持落脚的帧交接；到达误差不能靠突然缩放或大幅跳位修正。另提供每方向 4 帧 `walk-start` 与 4 帧 `walk-stop`：从现有待机姿态进入四足步态，再从稳定落脚帧返回待机。需要坐站转换的猫种由这组过渡处理，不能直接闪换。

### HR-A05 进食

- 00–02（起始）：在食盆旁稳定落脚，嗅闻后低头，嘴部到达盆沿。
- 03–10（循环）：8 帧小幅咀嚼与舔食，嘴、耳有变化；03 和 10 的衔接平滑。默认循环 3 次。
- 11–13（收尾）：停止进食、舔嘴、抬头，回到可接待机或行走的稳定姿态。

完整过程为 3 帧起始 + 8×3 帧循环 + 3 帧收尾，共 2.5 秒。第一次进入循环前校准嘴部与盆沿，循环期间脚底锁定；嘴部随咀嚼变化，不通过移动整只猫逐帧追踪嘴部。粮量在三轮循环完成后依次减少，收尾前为空；额外导出 `two-thirds`、`one-third` 两个粮层，避免最后突然整盆消失。

从食盆左右任一侧接近均只接触左侧食盆，不能吃右侧水碗。需要转向时先停步再接对应方向，不在接触盆沿时翻转贴图。

## 画布、注册点及遮挡约定

- 坐标原点为 PNG 左上角，X 向右、Y 向下；注册点记录为像素坐标，Unity 使用时再转换。默认地面注册点：512×384 画布为 `[256,352]`，512×512 画布为 `[256,480]`，保留底部透明安全区。
- 地面注册点用于放置角色，不要求每帧实际脚掌恰好占据该像素。不同动作画布分别设置固定展示倍率，并依据同一角色尺度板校准；不能将所有画布都拉满同一个矩形，也不能按每帧非透明包围盒自动放大。
- 每猫种记录头宽、躯干长度和站姿高度基准。躺下、转头、透视变化可以改变外轮廓，不能按手脚间距重新缩放全身。两方向和动作切换时维持同一角色的体量。
- 母版至少为运行帧的 2 倍边长，运行文件由母版一次性缩小导出。不能放大低清旧图充当高清母版；所有帧保留一致透明画布，禁逐帧紧裁、不同尺寸补边或不同导出倍率。
- 角色以完整姿态 PNG 为主，不强制沿用钓鱼时的头、手分层。需要食盆/猫窝遮挡时另外交付精确前沿遮挡层；不使用矩形裁切穿过角色或硬截掉身体。
- 食盆绘制顺序按猫咪接近方向核对：后侧盆体/水碗、猫咪、食盆前沿；粮食位于盆内且受盆沿遮挡。实际前后排序以局部交叠为准，不能固定整套碗都覆盖在猫脸上。
- 每帧保留 `mouthAnchorPx`（进食必填）及 `pawContacts`；倒粮清单包含碗局部坐标中的 `pourLandingPx`、`rimContactPx`、`foodLayerOffsetPx`。未实测值标记为待标定，不能填假坐标视作完成。

## 可后补资源

- HR-A06 `bed-enter`：8 帧、12 fps。00–01 靠近窝沿，02–03 前爪踏入，04–05 转身下伏，06–07 蜷好。终帧匹配该猫现有 sleep 姿势、尺寸及窝内锚点；提供猫窝前沿精确遮挡层。
- HR-A07 `sleep-loop`：6 帧、每帧 200 ms。胸腹轻微呼吸，耳尾偶尔动作；末帧到首帧无跳变。不用整体缩放模拟呼吸，睡眠位置不漂移。
- HR-A08 `wake`：6 帧、10 fps。睁眼、抬头、伸展、前爪支撑、后腿展开、稳定起身。首帧接睡姿，尾帧接标准待机，再通过 `walk-start` 离窝；不得从窝内瞬移到地面。

这些后补动作同样只覆盖九种猫咪，当前仍沿用静态睡姿及已有移动方式，新增素材验收后再替换。

## 喂食流程接入约定

1. 点猫碗启动一次喂食；倒粮期间重复点击合并，不叠加粮袋或队列。
2. 倒粮终帧切换满粮状态。读取当前猫碗位置，猫咪沿地面移动；移动用 walk 序列换帧，位移由路径控制。
3. 到达后按嘴部锚点对齐左侧食盆，播放 eat 起始、中段和收尾；再切空碗状态并恢复待机。
4. 猫碗拖动时取消未完成喂食并清理倒粮图层，再次点击时按新位置重新开始；猫窝拖动时睡着的猫随窝移动，去窝途中更新目标。
5. 打开功能页、切后台、失焦时暂停小屋行为；返回后回待机并清空未完成喂食，不补播多次倒粮。不向真实钓鱼会话提交新状态。
6. 所有行为有唯一当前命令。新点击可取消原地打滚或去窝；长距离拖动判定为搬动，不同时触发抚摸。打滚结束回到原落脚点。
7. 缺少当前猫种的左右行走、过渡、进食或公共粮层中任一必要资源时，不启用完整喂食链；保留猫碗拖放，不能先倒粮再卡住，也不能换为其他猫种。
8. 猫碗拖动采用“取消并恢复空盆，松手仅保存位置，再次点击重新开始”；不自动重复倒粮。角色切换、退出小屋、退出账号均清理旧角色命令及临时粮层。后台/功能页暂停后的默认策略为回待机、清空未完成喂食，禁止积压补播。
9. 减少动效模式不自动打滚或漫游；用户主动喂食可以使用静态关键状态和立即到达，仍按同一资源完整性与取消规则执行，不能伪造步行动画。

## 导出交付

- 文件：`<skin>/<clip>/frame-00.png ... frame-NN.png`，RGBA，无背景，画布尺寸固定；同动作各猫种逐帧对齐。

- 预览：提供 1x / 2x 循环预览和深色 / 米白底透明边缘对照。完整帧图不得只有合成 GIF。
- 若使用图集，最大 2048 × 2048、格间至少 2 px 透明留白；动画运行纹理控制为约 2x 展示大小。保留母版，运行文件独立导出。
- 当前摆件运行尺寸见 [texture-budget.json](../../../fish-social-unity/Assets/Resources/Desktop/Theme/Cozy/home-room/texture-budget.json)，原始资源保留在 `prototype/cozy-journal/assets/room-v4/`。

方向资源路径使用 `<skin>/<clip>/<left|right>/frame-NN.png`；固定朝向动作使用 `<skin>/<clip>/frame-NN.png`。公共资源置于 `shared/food-pour/`、`shared/food-fill/`、`shared/bowl-food/`，不要放入任意猫种目录。角色 PNG 不绘制食盆、量勺、地面或猫窝。

动画清单至少包含 `skinId`、`clipId`、`direction`、`canvasPx`、`displayScale`、`registrationPx`、`frames`、`durationMs`、`loopStart`、`loopEndExclusive`、`mirrorAllowed`、`sourceFacing`、`entryPose`、`exitPose`、`events`。循环区间统一为左闭右开：进食 `[3,11)`；非循环动作填空值。事件仅驱动本地画面状态，不触发服务器钓鱼状态。

### 验收顺序与检查项

1. **外观基准**：九猫侧别/花纹表确认；先锁定橘猫尺度板、左右站姿及已有睡姿交接。
2. **首套动作**：橘猫打滚、左右走路与起停、左右进食，配合公共碗资源完整演示；确认后再扩展其他品种。
3. **花纹高风险角色**：优先三花与奶牛，逐帧检查耳朵、脸部与躯干色块，不得左右互换或边缘跳闪。
4. **其余角色**：逐一检查蓝、棕、奶油、银渐层、黑、白猫；深色和浅色猫都在暗底/米白底验证。
5. **动作连续性**：1x、2x 和单帧查看；行走至少连续 10 圈、进食中段 3 圈、打滚前后叠图核对注册点。检查脚底滑动、头身缩放、末首帧停顿、透明白边、裁切及前沿遮挡。
6. **交互链**：移动食盆到允许范围两端，分别从左右接近；重复点击、倒粮中拖碗、走路中改目标、进食中切角色、打开面板、失焦、恢复都必须得到唯一且可预测的状态。
7. **交付检查**：每猫每动作登记“待绘制 / 待标定 / 待验收 / 已验收 / 已接入”。验证 PNG 透明通道、画布、帧号、时长、循环范围、锚点及图集边界；未完成条目保留明确状态，不能用重复静帧冒充完成。
