## 1. 替换策略

**保留已确认的场景、鱼、道具、猫和图标风格；重新制作或组合 UI 材质和装饰，补足动效所需的分层素材。**

完整替换不要求把所有原画重画一遍。现有原型本来就复用了 Unity 原画，而纸页、圆角、投影、活页环、胶带、印章、浮标等大量效果来自 CSS/SVG，尚不是可直接拖入 Unity 的素材包。把现有 panels/buttons 再上一次色无法达到原型效果，必须替换其表面结构并更新 prefab 引用。

实际原型优先于旧文档中不一致的尺寸：例如当前页面圆角24、活页环54×24、导航浮漂40×58；旧设计文档的圆角20、环28×40、浮漂36×52不能混作同一套验收标准。文中标“建议”的新切图尺寸需经Unity样板页验证后定版，不是已交付素材尺寸。

### 已发现的资源参数冲突

- `README.md` 记普通按钮border10、paper20；当前 `.meta` 与 `CatTheme` 是按钮12、paper22。
- `asset-manifest.json` 中普通按钮仍写407×400、border64；实际文件是64×63、border12。paper也有相同的旧尺寸记录，大按钮条目缺失。
- `CatTheme.SurfaceBorder()` 仅按文件名识别 `paper.png`，导致 `textures/paper.png` 也带border22；新纸纹必须明确按完整资源路径处理。

**制作交付时重新生成manifest并同步代码/.meta/README。现有manifest不能直接作为美术生产或九宫格参数的权威表。** 本次只记录差异，未修改现有资源设置。

## 6. Unity替换方式与工程交付

1. **新增专用资源目录。** 建议 `journal/surfaces/`、`decor/`、`motion/`、`characters/`、`ponds/`。避免一开始就覆盖旧 panels/buttons，导致WPF导出或旧弹窗意外变样。
2. **先做基础样板页。** 使用商店、地图右栏和设置开关验证A01–A19的圆角、厚边、白边、阴影、切片与缩放，再铺其他页。直接把整张效果图当背景会失去布局与交互能力。
3. **绑定到共享Library Variant。** CozyPanelBase/Card/Dialog/Sidebar、CozyButton系列、Input/Scroll系列与CozyPageHeader都改资源映射；卡片/照片/胶带独立子层。保留命中区和动态文本。
4. **统一脚本与导入规则。** `CatTheme`、`CozyPanelSkin`、`CozyButtonVisual`、`CozyItemArt`、`CozyRedesignAuthoring`、`CozySpriteImporter`、`CozyPrefabRepair`同步到新路径与border，防止运行时或Repair恢复旧资源。
5. **导入设置。** Sprite/UI、FullRect、透明正确、默认不生成mipmap；9-slice使用Sliced，图标/人物用Simple并保比例。纸纹如需Repeat，给独立例外，不能被现有全量Clamp修复覆盖。压缩/最大尺寸按实际屏幕验证，不能让高清图在Importer里被自动缩小后再放大。
6. **2×与边框验收。** PPU、border、Canvas scale一同核对；在实际UI尺寸检查，不仅看原图。透明padding与pivot逐项写入manifest，动画换帧不跳位置。
