# 多姿势提起与多部位抓取方案

状态：设计方案，尚未实现。保留用户认可手感方向的 V3 预览；本文不表示新模式已经可用。
统一预览入口仍为 `现行预览.html#home-soft-drag`。

## 现状与需要替换的部分

`drag-v3.js` 已支持对贴图的可见像素命中并保存局部 UV，但 `physics-v3.js` 的 `rotate()` 始终围绕头部附近 `(x, y + 0.20h)` 摆动。点击胸腹或脚掌只改变跟手位置，没有改变身体受力结构。

目前只有坐姿和垂直悬垂两套完整原画，使用 0.18 秒淡变。它们不能覆盖侧卧、蜷睡、仰躺，也无法用同一张垂直原画可靠表达中部托举或单爪悬提。保留已认可的惯性方向与防折叠保护，替换固定支点、单一悬垂姿态和通用淡变衔接。

## 抓取模式与视觉目标

| 命中区域 | 固定点 | 空中姿态 | 关键限制 |
| --- | --- | --- | --- |
| 头部 | 按下时头部表面的局部点 | 胸腹、臀部在下，四肢放松；沿用当前方向 | 头脸保持比例，不把脖子拉成细杆 |
| 躯干中部 | 按下时躯干表面的局部点，对应腰腹控制段 | 中部最高，头胸和臀尾向两侧垂下，呈柔软的拱形 | 脊柱从中间向两端求解；头和臀是不同质量块，不只是整图横过来 |
| 单只前爪 | 被抓的爪掌局部点 | 爪子跟手，腕—肘—肩带动身体转向；身体重心悬在支点下，另外三爪及尾巴自由下垂 | 被抓肢体不缩放，关节有弯曲限位，不能让前肢无限延长 |
| 单只后爪 | 被抓的后爪局部点 | 由后腿带动骨盆，身体可侧倾或头朝下；头部保持可辨识 | 单独准备倒悬/侧悬姿态，不能把前爪版简单旋转 180° |

头部 + 躯干 + 四只爪，共六个可命中区域。先实现前三类代表性姿态，再补左右爪和后爪变化。左右抓取不镜像整只猫，避免三花等不对称毛色反转。尾巴本轮只作为跟随部件，不新增尾巴抓取模式。

## 从现有八种姿势过渡

| 原姿势组 | 已有姿势 | 提起时需要表现 |
| --- | --- | --- |
| 坐姿组 | 收爪蹲坐、放松蹲坐 | 抓取处先受力，胸腹/骨盆逐渐离地，后腿从折叠变为下垂；抓爪时先展开被抓肢体 |
| 伏姿组 | 低身蹲伏、枕爪趴睡 | 保留尚未离地的爪掌支撑，按抓取位置决定哪一端先起来；抬到腿长极限后解除接地 |
| 卧姿组 | 侧卧睡、蜷身睡 | 解开蜷曲，躯干转向受力方向，近远肢体逐步露出；不插入一次无关的坐姿 |
| 仰姿组 | 四脚朝天睡、肚皮朝上伸懒腰 | 腹背与四肢的朝向先过渡，再进入对应悬提姿态；身体中部托举可保留仰卧方向，不强制翻正 |

每次抓取从当前正在显示的姿态开始，包括呼吸、转头或上一次余摆的中间状态。按下只绑定，不立即切图。点击与拖拽沿用现有交互约定；移动超过可配置的小阈值后才进入提起。

状态路径：原姿态 → 接触/受力 → 展开并逐点离地 → 对应抓取模式的空中平衡 → 松手下落 → 接地缓冲 → 稳定休息姿态。

- 抓取过渡由实际抬升距离、剩余接地点和关节状态驱动，速度影响余摆；时间只负责平滑，不能按固定时间把爪子从地面突然拔走。
- 接地点保持到受力抬离或腿长约束要求离地；爪子离地后有自己的速度，不每帧归零。
- 停在过渡中间时，应得到一张完整的中间姿态，不长期混合两张半透明图像。
- 松手后先保持释放速度、角速度，再用接地姿态收敛。高处从单爪释放允许空中转正；离地过近则用侧身/臀部缓冲关键姿态，不硬转到直立脚着地。
- 放下不强行恢复原来的睡姿。先稳定坐下或趴下，再交回原有室内待机系统。

## 实现结构

1. **姿态与命中数据。** 每个关键姿态提供头、胸、腰、骨盆、四肢关节、尾根、接地点、可见抓取区域和绘制层级。使用统一角色尺度与基准点，不按每帧包围盒重新缩放。
2. **抓取约束。** 按下记录 `grabRegion`、骨骼/面片局部坐标、世界抓取点及当前速度；整个拖拽过程锁定区域。指针滑过其他部位不重新分类。隐藏的爪子不可隔着身体选中；可见爪掌优先于重叠躯干命中。
3. **分段身体。** 头—胸—腰—骨盆组成有质量、弯曲限制和轻微弹性的脊柱链；尾巴至少两个控制段。头脸、爪掌保持尺寸，四肢使用上/下两段关节，限制伸长。柔软度主要作用在脊柱弯曲、有限躯干伸展和阻尼。
4. **动态受力支点。** 约束求解以被抓部位为固定点，重力作用在各质量块上。中部托举从腰部向头、臀两端求解；抓前爪由爪—前肢—肩传力；抓后爪由爪—后肢—骨盆传力。身体不是围绕同一个默认头像支点旋转。
5. **惯性与接触。** 使用现有固定步长；新抓取继承当前姿态和速度，解除抓取保留速度。约束限制骨长、关节角和地面穿透，边界修正与抓取约束协调，不能在渲染层额外平移来掩盖求解错误。
6. **美术驱动的蒙皮。** 采用完整姿态作为目标轮廓，平滑蒙皮连接关节；同视角的小幅运动做连续形变。转侧身、仰躺翻身、近远肢体换层使用补绘关键姿态和对应层级数据。新露出的腋下、腹背、髋部必须有完整素材，不能靠透明遮罩补空洞。
7. **过渡图。** 姿态族共享“开始受力/展开/空中平衡”等连接点，按抓取模式组合；不为八种起姿乘六个抓取点逐套重复绘制，也不让所有起姿强行经过坐姿。

建议姿态数据：`poseId / poseFamily / rigPoints / contacts / grabRegions / drawOrder / correctiveArt / transitionTargets`。
建议运行状态：`sourcePose / grabRegion / localAnchor / bodyPositions / bodyVelocities / activeContacts / transitionProgress / releaseState`。

## 需要补绘的关键姿态

先用橘猫校准，不直接批量扩猫种：

- 中部托举：刚受力、胸臀离地、头尾两端垂下的稳定姿态，以及左右摆动轮廓校正。
- 单前爪悬提：爪子被带起、肘肩展开、身体转向重心下方、稳定斜悬。
- 单后爪悬提：髋部带起、身体侧转、倒/侧悬；后续单独制作，不能复用前爪贴图旋转。
- 卧姿/仰姿：展开、半翻身、刚离地等可改变遮挡关系的关键姿态。
- 落地：脚掌支撑、低位侧身缓冲、收腿坐下/趴下。

每条代表性路径先准备 3–5 个有意义的关键姿态，数量按遮挡变化确定。关键帧之间的跟随、下垂、摆动由约束与蒙皮计算；需要露出新身体面的动作必须绘制，不能全部用脚本拉伸替代。定稿后再按同一结构绘制三花与蓝猫，保留各自毛色空间关系。

## 预览落地顺序

1. 保留当前 V3 页面和已认可手感作为对照。
2. 优先完成橘猫的“坐姿/趴姿 → 中部托举”和“坐姿 → 单前爪悬提”两条路径，加现有头部模式，形成三种抓取对照。
3. 增加起始姿势选择、悬停区域提示、自动演示各抓取点、暂停/慢放/逐帧、支点/重心/接地点可视化；自然点选和强制选择模式都使用同一套约束。
4. 再扩展侧卧、蜷睡、仰躺和左右/后爪，检查低位抓取及中途松手。
5. 整体造型和过渡经用户验收后，扩展猫种，再迁移到 Unity / Overlay。仍在同一总预览路由迭代，不另建分散入口。

## 验收重点

- 起姿切到受力姿态不瞬移、不改变角色尺寸，抓取处保持跟手。
- 中段托举时头胸和臀尾确实分别下垂；单爪模式身体重心落到爪子下方，被抓腿不变长。
- 前后景关系正确，没有第三只前腿、突然露出的接缝或花斑左右翻转。
- 静止时逐渐下垂收敛，快拖时有不同部位的滞后；中途停住显示完整姿态。
- 低位提起、快速甩动、离地前松手、半翻身松手、拖出窗口、取消操作均可恢复。
- 几何自动检查覆盖骨长、爪掌比例、接地、抓取点、可见面片翻转；同时保存关键阶段的实际渲染截图/录像。自动检查通过不替代视觉验收。
