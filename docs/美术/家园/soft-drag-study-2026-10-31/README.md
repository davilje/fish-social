# 猫咪软体拖拽 · 连贯姿态 V3

统一入口：`现行预览.html#home-soft-drag`。仅更新网页试验，未接入 Unity / Overlay。

下一阶段设计：[多姿势提起与多部位抓取方案](GRAB-TRANSITIONS.md)。包括头部、中部托举、单前爪/后爪的受力区别及八种起姿的衔接；目前为设计，尚未接入预览。

## 为什么替换 V2

用户提供的实际截图表明：七部件拼装的圆腹被拉成长袋，四肢如贴片，肩/髋与头部缺乏连贯解剖关系。V2 的几何和交互检查不能证明视觉合格；此前“修复完成”的描述不成立。

V3 重新绘制橘猫、三花猫、蓝猫的完整坐姿和悬垂姿态，先修正整体轮廓，再添加受限形变。三花保持左橘右黑额头，蓝猫为纯蓝灰毛色；清理悬垂原画中多余的肩后轮廓。两张图集尽量对齐头部位置。

## 当前实现

- `connected-v3/sitting-atlas.png` / `hanging-atlas.png`：各三只完整角色，透明 PNG。经内置 imagegen 生成/定向修改；完整提示词在同目录 `prompts.txt`。
- `drag-v3.js`：按同一坐标区域提取坐姿与悬垂贴图，60×100 连续纹理网格；不再叠放七张肢体图片。对实际渲染三角形反求点击 UV，忽略透明像素。
- `physics-v3.js`：头部、胸腹、左右前肢、左右后肢、尾巴的连续蒙皮权重；整体惯性摆动、躯干有限伸展和五组独立余摆。四肢末端尽量保持原画比例，关节附近使用混合权重，所以这不是“所有肢体像素绝对刚性”的分层实现。
- 网格保护：检测有图像内容的三角形，自动降低局部形变幅度，避免爪子边缘折叠或撕裂。整体摆动是刚性旋转，不改变身体比例。调高惯性也不会解除此限制。
- 坐姿/悬垂使用约 0.18 秒固定时长过渡，提起达到阈值后锁定悬垂，落地后恢复坐姿。不会因鼠标停在中途而长期叠着两幅图。当前过渡仍是两幅原画淡变，并非已绘制完整起身中间帧。
- 120Hz 固定步长，提供真实鼠标/触摸拖动、自动演示、三角色切换、惯性档位、网格查看、取消和复位。

## 验证

`scripts/verify-home-soft-drag.cjs` 检查三角色、三档惯性、抓取点、头部比例、所有可见网格无反转、停手收敛、落地回坐、真实鼠标拖动、取消和复位。实际网页截图与报告：`output/home-soft-drag-connected-v3/`。

视觉验收仍由用户完成。当前效果是完整原画的连续形变预览，不是生产可用的多关节骨骼资产；肘、膝尚无单独关节。此前 `layers-v2/`、`physics-v2.js`、`drag-v2.js` 及 V1 文件作为历史试验保留，本页不再加载。
