## 必须实现的效果

1. 风格圆润、柔软、手绘，以正式采用的浅青白水体、奶白高光、深蓝暗部制作短弧、圆头水瓣和饱满水滴。水花应与当前认可猫咪同屏协调；大鱼靠水体重量和回落节奏体现力量，不用霓虹、尖刺、照片水雾，不把每朵水花画成猫爪。
2. 仅实现 FX01 浮漂／饵入水、FX02 等待涟漪、FX03 咬钩波纹、FX04 挣扎扰水、FX05 发力中真实破水／拍水、FX08 撒饵落水、FX09 真实收杆触水。
3. **FX06/07继续撤销；咬钩／水下挣扎只出波纹。** 水花仅随实际出水、抛竿、撒饵、收杆触水产生。FX09依用户追加要求仅绑定 resolving/stopping 的 retrieve.contact（reel源0鱼线交点或reel_empty源0浮漂），每action一次，不得绑定retrieve.start或结果呈现；硬取消仍优先。其余结束阶段停止新发射并100ms收敛。
4. S/M/L/XL 每档至少两种水花和两种水纹，至少 8 种水花＋8 种水纹。轮廓、展开方向、拖尾、节奏均有区别，不能只放大同一张图片。体长初值分界 .30/.80/1.50m，详细尺寸和时长见 spec。
5. H/I 共用 waterSizeTier；只用允许展示的体长或可见鱼身尺寸，未知用 S，不提前暴露隐藏鱼种或尺寸。浮漂／窝料按落水物自身规格，不随未来鱼大小放大。角色槽位缩放、鱼档位和 DPI 分开计算。
6. 锚点复用 22B 实际浮漂／鱼触水点和裁剪，不以猫咪图片中心代替。不遮猫脸、鱼身、读条，不溢出岸线和邻座；不恢复状态栏、鱼获／脱钩弹窗。

## 实施顺序

1. 交付猫咪同屏四档预览：暂停、逐帧、明暗水面、角色槽位、标准／简化／关闭和多人对照；资源及 effects 配置版本化，注明来源与 hash。
2. 按共享契约核验并复用事件身份、源动画 marker、当前表现 owner、取消和去重。原生 Overlay 与 Unity 兜底只有一个 owner；WPF 实际帧发布后才消费 marker，不用插值帧、快照序号或固定延时制造事件。
3. 快照、重连、旧 epoch、取消、漏帧不能补播过时效果；同事件变体选择稳定。咬钩替换等待，强拍水替换普通扰水；FX04 最多每 700ms，FX08 每 720ms 循环最多一次，其他触发按 spec。
4. 池化 Image/Path 和效果组，共用时钟，不做每粒子定时器或每帧全场景布局。全局最多 24 实例／8 组，每角色最多 2 组，为自己保留 2 组／12 实例；优先级回收不排队补播。新增解码资源≤4MiB。
5. 装饰不参与 WPF 命中，也必须排除原生透明窗口的 alpha 命中检测。声音继续由 Unity 的 I 系统播放，H 不新增播放器；I 未完成时保留共享接口并明确联测待办。

## 专项验证

- 四档形态、未知尺寸、所有猫种 manifest、96/128/192 槽位、高 DPI、明暗水面、边缘座位、多人、简化／关闭与桌面点击穿透。
- 重复包、预测与权威合并、0/150/400ms 冷加载、取消、切塘、断线、后台恢复，无重复和迟到效果。
- Windows 同条件 A/B：20 角色、30 次进出塘和持续 10 分钟，检查稳定池容量、内存和线程；H/I 新增主线程目标 p95≤1ms、p99≤2ms。
- 与 I 联测至少 30 个事件，画声差目标≤80ms，超过 120ms 记录诊断。对照 H spec 逐条提供证据。
