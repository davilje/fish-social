## 1. 背景与目标

### 1.1 背景

10-25 到 10-26 的场景、特效和登录画面都是改仓库里的 Overlay 资源再随包发出。钓鱼公式在 `fishing_formula_constants.json`，要改系数就得发一版服务端。OPS-RELEASE-1 已经把「配置不停服」和「客户端整包」分开，但没有可用的替换通道。FEAT-05 的配置热更整包已废弃，不恢复那条。

### 1.2 目标

准备两条可回滚的热更，都不换 exe：

1. **数值**：服务端钓鱼公式常量和鱼塘文案可以换上一份已校验的数据包，进程不重启；失败时回到上一份。
2. **桌面资源**：Overlay 的鱼塘布局、场景图、钓鱼特效和音效可以换上一份带版本号的资源包，不重装客户端。

### 1.3 非目标

- 不热更 Unity 播放器或 Overlay 的 exe。
- 不做应用商店差量包，不做 Expo / CodePush。
- 不做多机滚动发布。
- 不在本项里改具体公式或世界观文案。那些走 FISH-ATTR-01 和 WORLD-CAT-01，本项只提供通道。
- 不恢复 FEAT-05。

## 2. 使用方式

| 谁 | 做什么 | 结果 |
|----|--------|------|
| 维护者 | 上传一份数值包或资源包，写明版本号 | 校验通过后成为当前版本；不通过则拒绝，旧版本继续生效 |
| 玩家 | 已打开的桌面客户端 | 下次进塘或重新打开 Overlay 时使用新资源；数值在下一次结算相关计算时使用新表 |
| 维护者 | 指定回滚到上一版本 | 数值和资源各自回滚，互不影响 |

版本对不上时，客户端显示明确的失败原因（包损坏、版本过旧、清单缺文件），不得静默用半套新图配旧布局。

## 3. 范围

### 3.1 数值包

包含公式常量和鱼塘玩家可见文案。加载前检查字段类型和必填键。与正在使用的表结构不一致则拒绝。`game_config` 里已有的开关继续走原路径，不并进这个包。

### 3.2 资源包

只含 Overlay 已在用的布局 json、塘场景图、特效清单和音效。清单列出相对路径和版本。缺文件或路径跑出资源目录则整包拒绝。Unity 主窗手账图片不在第一版。

### 3.3 权限

沿用现有管理入口的登录限制。没有第二人审批流程；OPS-RELEASE-1 里的双人批准不在本项补做。操作写入现有管理日志，至少留下版本号、时间和操作者。

## 4. 技术影响

- 服务端：数值包的存放、校验、切换和回滚。不新造一套与 `game_config` 平行的业务开关。
- 桌面：Overlay 从本地缓存读资源包；缓存无效时用安装包内的那份，并提示正在使用随包资源。
- 不改钓鱼公式本身，不改 `mobile/`。

### 回滚

数值、资源分别保留上一份成功版本。回滚只切指针。随包资源始终留在安装目录，缓存损坏时还能进塘。

## 5. 验收标准

- [ ] 替换一份公式常量后，不重启服务端，下一次相关计算用新值；把常量改成非法字段时整包拒绝，旧值仍在用。
- [ ] 替换一份鱼塘布局或场景图后，不重装客户端，重新进入该塘能看到新资源。
- [ ] 资源清单缺文件时不切换，并有可见的失败说明。
- [ ] 数值回滚和资源回滚可以单独做，exe 不需要更换。

## 6. 风险

| 风险 | 缓解 |
|------|------|
| 新旧客户端同时在线 | 资源包只增字段不删旧布局键；读不到新字段时用随包资源 |
| 和 FISH-ATTR-01 同时改步进 | 热更通道先验收；步进改动仍走正常发版，不借未验收的热更上线 |
