## 1. 背景

玩家侧的体长、体重变化太碎，和手账里「一条鱼长大一点」对不上。需要先判断现有概率和成长公式是否还适合，再只改已经结论明确的步进。

本项不是延迟或卡顿，不走 Overlay 时间戳链路。依据是 2026-10-26 源码里的常量和函数，不是手感猜测。

## 2. 当前口径

| 项 | 现在的值 | 出处 |
|----|----------|------|
| 体长最小单位 | 0.01 米（`round2`） | `shared/fishing.ts` |
| 体长下限 | 0.02 米 | `MIN_FISH_SIZE_M` |
| 体重 | 不入库。展示用 `12 × 体长³` 公斤 | `LENGTH_WEIGHT_A/B` |
| 成长 | 所有鱼共用 `L(t)=40×(1-(1-t/7)^1.8)` 米，品质只做上限 | `GROWTH_CURVE_*` |
| 脱钩即时成长 | 当前体长 × 1.02 | `ESCAPE_GROWTH_BONUS_RATIO` |
| 咬钩 | 全局缩放 0.05，体长系数 0.65，越大越好咬 | `BITE_BASE_SCALE`、`SIZE_BITE_K` |
| 脱钩曲线 | 0.02 米约 22%，0.35 米约 8%，40 米锚点 98.5%（减免前） | `ESCAPE_AT_*` |
| 出生近满尺寸 | 0.6% | `NEAR_MAX_SPAWN_CHANCE` |

体重例子：0.2 米约 0.1 公斤，1 米 12 公斤，2 米 96 公斤，40 米约 76.8 万公斤。体长每增加 0.01 米，大鱼的体重会跳一大截，小鱼几乎看不出。

## 3. 判断

**步进不合适。** 0.01 米对 0.02 米的幼鱼是一半身体，对按米长大的鱼又细到没有展示意义。体重没有步进，而且用三次方，大鱼数字不能当「单位重量」读。

**成长和脱钩曲线不适合当前尺度，本票不改系数。** 七天冲到 40 米、40 米脱钩 98.5%，是为巨物曲线写的，不是手账鱼塘里一条看得见长大的鱼。咬钩「越大越好咬」和脱钩「越大越难留」叠在一起，巨物几乎只作为脱钩事件存在。这些系数要改的话，会动卖价、经验和回鱼门槛，仍不放进本票。OPS-HOT-1 已废弃，之后若要改系数，随 Steam 整包发布，不依赖热更通道。

## 4. 本票要改的

- 体长的存储和展示步进从 0.01 米改为 **0.05 米**。出生、随时间成长、脱钩 ×1.02 之后，都按这个步进取整，且不低于 0.02 米，不超过该品质上限。
- 体重仍由原公式从体长算出，不入库。展示步进改为 **0.1 公斤**，不足一步就显示到这一步。
- 卖价、经验继续用取整后的体长，避免界面是 0.05 米、结算却用 0.01 米。

## 5. 非目标

- 不改 `GROWTH_CURVE_*`、`ESCAPE_AT_40M`、`BITE_BASE_SCALE`、`SIZE_BITE_K`、`NEAR_MAX_SPAWN_CHANCE`。
- 不改品质上限、鱼种表、回鱼的斤门槛。
- 不把体重写入背包或数据库。

## 6. 验收标准

- [ ] 新生成或新成长的体长都是 0.05 米的倍数（下限 0.02 米除外，0.02 保持为最小体长）。
- [ ] 同一条鱼脱钩前后的体长差至少为 0 或 0.05 米，不会再出现 0.01 米的变化。
- [ ] 界面体重按 0.1 公斤一档，和 `12 × 体长³` 取档后的值一致。
- [ ] 七天曲线、40 米脱钩锚点、咬钩缩放和近满尺寸概率与改前常量相同。
