本次交付为设计与开发交接，游戏功能尚未实现。目标是同一种鱼随实际体长变大而连续变大，同体长不同品质使用相同长度；从最小幼鱼到巨物都有明确视觉尺度，并在上钩、真实出水、收杆、持鱼之间保持一致。

## 1. 现行体长边界

`shared/fish.ts` 定义全局合法范围 **0.02–50.00m**。现行 `shared/generated/game-data/fish_quality_stats.json` 的品质成长上限为：

| 品质 | 灰 | 绿 | 蓝 | 紫 | 红 | 橙 | 金 |
|------|----|----|----|----|----|----|----|
| 当前成长上限（m） | 0.20 | 0.35 | 0.50 | 0.80 | 3.00 | 15.00 | 40.00 |

因此 **40m 是现行生态最大成长体长，50m 是全局兼容边界**，映射仍覆盖两者。鱼种 `typicalMinM/typicalMaxM` 只供图鉴参考，不能用于把每个鱼种的幼鱼都放大到同一视觉尺寸。FISH-ATTR-01 的 0.05m 步进仍待实现，本方案可接受现行 0.01m 和后续 0.05m 体长，不改成长、脱钩、经验、卖价或体重公式。

当前分层动作已有鱼图层和线末端位置；现行水下 `hooked/bite/effort` 隐藏鱼身。本项在真实允许显示鱼体时应用体长缩放；水下继续隐藏，不因为要展示尺寸而提前揭露鱼种或体长。

## 2. 映射口径与完整控制点

用**标准 128px 角色槽位下，鱼头到尾根的直线逻辑长度 B**表达尺寸，不计鱼鳍、尾鳍伸展、鱼钩及源图透明边。屏幕旋转后的包围盒宽度不是体长，横鱼与竖鱼必须一样长。以下为首版美术设计值，待统一预览确认：

| 实际体长 L（m） | 鱼身长度 B（标准逻辑 px） | 相对 128px 槽位 | 参考用途 |
|----------------|-------------------------|----------------|----------|
| 0.02 | 8 | 6.25% | 最小幼鱼，保留轮廓可读性 |
| 0.05 | 10 | 7.81% | 小幼鱼 |
| 0.10 | 14 | 10.94% | 小鱼 |
| 0.20 | 20 | 15.63% | 灰品当前上限 |
| 0.35 | 26 | 20.31% | 绿品当前上限 |
| 0.50 | 32 | 25.00% | 蓝品当前上限 |
| 0.80 | 40 | 31.25% | 紫品当前上限 |
| 1.00 | 46 | 35.94% | 一米鱼 |
| 1.50 | 56 | 43.75% | 中大型鱼 |
| 2.00 | 66 | 51.56% | 大型鱼 |
| 3.00 | 82 | 64.06% | 红品当前上限 |
| 5.00 | 102 | 79.69% | 巨物起段 |
| 10.00 | 128 | 100.00% | 鱼身达到一个槽位 |
| 15.00 | 146 | 114.06% | 橙品当前上限 |
| 20.00 | 160 | 125.00% | 大型巨物 |
| 30.00 | 178 | 139.06% | 更大巨物 |
| 40.00 | 192 | 150.00% | 金品当前成长上限 |
| 50.00 | 204 | 159.38% | 全局兼容边界 |

这是为屏幕可读性做的压缩映射，鱼获文案仍显示真实米数。最小到最大呈 25.5 倍视觉长度，避免将真实 2,500 倍比例直接画到桌面上。品质与鱼种可以改变造型、颜色和身体厚度，不能再额外乘一个“品质放大系数”。

### 2.1 控制点之间连续插值

```text
L = clamp(sizeMAtHook, 0.02, 50.00)
找到相邻控制点 (Li, Bi)、(Li+1, Bi+1)
t = ln(L / Li) / ln(Li+1 / Li)
B(L) = Bi + (Bi+1 - Bi) × t
```

端点直接使用首尾值。每段在对数体长上插值，端点连续、全范围单调递增，不按 S/M/L 档突然跳尺寸。中间值示例：0.30m → **24.35px**，1.20m → **50.50px**，4.00m → **93.26px**。内部保留浮点精度，只在调试界面显示到 0.01px，不能每帧取整造成抖动。

槽位 S、整体场景缩放 Z 和 DPI 的换算为：`Bscreen = B(L) × S/128 × Z × DPI`。引擎已应用过的 Canvas/Transform/DPI 不再重复相乘。例如 1m 鱼在 S=96/128/192、Z=1 时分别为 **34.5/46/69 逻辑 px**；40m 分别为 **144/192/288 逻辑 px**。这里的逻辑 px 与操作系统物理像素区分。

缺少、非有限或非正的体长按“未知”处理，不调用映射；无可见真实鱼时继续隐藏，旧数据已需显示鱼时使用标准 **32px** 中性回退并标记调试原因，不能把未知判成最大鱼。有限正数越界只在表现侧夹到端点，记录调试诊断，不回写服务器数据。

## 3. 动画锚点与缩放方式

### 3.1 先独立鱼层，再围绕接触点缩放

每条可显示鱼的资源需提供同一坐标系中的 `mouthAnchor`、`tailRootAnchor`、`holdAnchor`，以及完整鱼层尺寸。鱼身基准长度为头尾根间的距离 `Bnative`，等比缩放 `s = B(L)/Bnative`，同时作用于宽高与所有鱼体锚点。透明 PNG 的整张宽度不能代替 Bnative；不同体型各用自己的真实轮廓与锚点。

挂钩时，当前帧鱼嘴必须精确落在实际鱼钩/子线末端 H：

```text
Pscene = H + R(angle) × s × (Pfish - mouthAnchor)
```

上式在已归一到标准槽位的坐标中计算，外层槽位、场景和 DPI 变换只应用一次；需要翻转朝向时，鱼体及锚点使用同一个翻转矩阵。只缩鱼体，不缩整张角色、钓竿、鱼钩、浮漂或椅子；鱼线末端由 H 约束，竿尖端仍固定在当前竿尖。

现有源 rig 的 `lineEnd/fishAngle/fishHeld` 可作为转换依据；成功动作从 `fishHeld=true` 起不再总有 `lineEnd`，必须补明确的**持鱼接触点**，不能把握竿点当持鱼点。尾部摆动在局部坐标内叠加，鱼嘴接触误差在标准槽位下不超过 1px。

### 3.2 跨动作连续

- 当次鱼用上钩时锁定的 `sizeMAtHook`，真实出水、收杆、成功持鱼共用同一 B(L)。不能在上钩时一种尺寸、结果弹出时突然换另一种。
- 挂钩转持鱼时，在末段 **180ms** 内将接触约束从鱼嘴线端平滑过渡到角色持鱼接触点，保持鱼身长度；不缩成图标再放大。手账/背包卡片按各自容器缩略展示，不把其 fit-to-card 尺寸带回场景。
- 水下看不到鱼时不播放“鱼从零放大”的动画；第一帧真实出水已经是目标尺寸，水面裁剪自然揭示轮廓。
- 重连快照按当前进度恢复同一尺寸与姿态，不能重播出水或成长。脱钩后的生态成长不反过来改变当前逃鱼残影的体长。

## 4. 巨物、水面、碰撞与多人

10m 以上鱼身可能超过单个角色槽位，鱼层要进入允许溢出的场景表现容器，不能被原 128×128 图片矩形裁掉。渲染边界按完整鱼层变换后的包围盒计算，同时计入鱼鳍、尾鳍、旋转、阴影和摆幅；不能只按表中 B 当图片宽高。所有鱼体资源只从原素材采样，不能每条鱼每帧重建位图。

鱼嘴/持鱼接触点固定，巨物的移动路径优先朝本钓位水面侧展开；不通过任意缩小鱼来避让。水下 `hooked/bite/effort` 继续隐藏；出水/收杆/持鱼在**完整缩放、旋转、平移之后**应用场景水面的逆变换遮罩，不能缩放后露出本该在水下的像素。巨物局部出屏由场景窗口自然裁剪，不改变 B(L)；统一预览应提供完整动作视野以检查最大鱼。

鱼层不参与角色槽位重排、不阻挡鼠标、不改变脚底和座位锚点。按现有前后关系遮挡角色与椅子，不能将放大鱼整张强制置于所有玩家与 HUD 之上。多人同屏只使用同一尺寸规则，低特效模式可降低附带水花数量，不另把大鱼缩小；应复用网格/材质并按可见性渲染。

水花继续按现行“允许公开的体长/真实可见鱼身＋真实触水 marker”取档。本项不会把映射控制点同时当作水花 S/M/L/XL 阈值。隐藏鱼体的尺寸不能提前放大波纹、浪花或声音暴露未来鱼情。折断线、折断竿时参照 FISH-BREAK-01 保持同一个接触点和尺寸锁定。

## 5. 开发交接

一份版本化映射控制点配置作为权威源，Unity、WPF 和统一预览共用同一数据；各端只实现相同插值公式，不维护各自一张数值表。拟新增 `fish-body-size-map-v1` 配置（名称待实现时选定），包括体长单位、标准槽位、控制点和每种鱼资源的锚点数据。

预估接入文件：

- `desktop-overlay/OverlayPetActor.cs`、`OverlayFishWaterMask.cs`、`OverlayFishingWaterContact.cs`：鱼体矩阵、最终矩阵遮罩和触水点。
- `fish-social-unity/Assets/Scripts/Desktop/Pet/SpriteFramePetRenderer.cs`、`UnityFishingWaterMarkerBridge.cs`：Unity 同构缩放、布局与触水桥接。
- `scripts/export-fishing-motion.py` 及素材 manifest：头尾与持鱼锚点，不破坏原角色道具层。
- `shared/types.ts`、服务端当次咬钩上下文：复用现有 `sizeM`，若需独立字段则明确 `sizeMAtHook` 的序列化与公开时机，不向客户端暴露尚未允许公开的鱼情。

新增验证预览统一纳入根目录 `现行预览.html` 的钓鱼分类；包含体长滑杆、十八个控制点、一排同体长异品质对照、96/128/192 槽位和完整上钩→出水→持鱼动作。预览标注“设计试调”，采用前不宣称已入正式游戏。

## 6. 验收标准

- [ ] 18 个控制点逐一匹配，0.02m/40m/50m 明确；相邻控制点左右连续，全域单调不减。
- [ ] 0.30/1.20/4.00m 中间值与 §2.1 一致，非控制点不会吸附到某档。
- [ ] 同体长异品质使用相同鱼身长度；相同鱼种由小到大连续变化，身体比例不被横向拉扁。
- [ ] 源图透明边不同、朝向翻转、横鱼/竖鱼/旋转、十一角色及所有持鱼姿势的嘴/手接触误差≤1 标准 px。
- [ ] 槽位与 DPI 换算一次；96/128/192 槽位下 1m 和 40m 示例正确。
- [ ] 最小鱼仍可辨认，40/50m 鱼无槽位裁切、穿水、遮挡 HUD、阻止点击或推开邻座。
- [ ] 上钩、真实出水、收杆、持鱼长度一致；180ms 接触过渡不跳位置、快照不重播。
- [ ] 水下阶段持续隐藏；无真实触水不播水花，未知体长不会出现巨物提示。
- [ ] 缺值、NaN、Infinity、0、负数、有限越界、旧数据均按 §2.1 处理且不污染业务体长。
- [ ] 完成最小/最大鱼×断线/断竿/隐藏恢复/多人联测；统一预览与 Windows 实机完成视觉验收。
