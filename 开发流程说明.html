二、完整开发流程

① 提需求→
② @producer 写 spec→
③ 确认范围→
④ handoff→
⑤ @dev 实现→
⑥ verify→
⑦ accept→
⑧ @producer close

步骤详解

步骤角色操作
1 你（项目经理） 向 @producer 描述需求目标和验收标准
2 @producer 在 docs/planning/specs/ 撰写功能规格，包含背景、交互、API、验收标准、非目标
3 你（项目经理） 审核 spec 内容，确认范围和优先级，spec 状态标记为 已确认
4 @producer 运行 npm run planning:handoff -- vX.Y.Z → 自动生成分角色 prompt / 更新计划表 / 生成 handoff manifest
5 @frontend-dev / @backend-dev 按对应 prompt 实现代码，严格按 spec P0 范围，不自加功能
6 @frontend-dev / @backend-dev 运行 npm run planning:verify -- vX.Y.Z 执行自动化验收脚本
7 你（项目经理） 运行 npm run planning:accept -- vX.Y.Z → 标已实现 / 更新计划表 / 输出 CHANGELOG 草稿
8 @producer 运行 npm run planning:close -- vX.Y.Z → 更新 CHANGELOG / README / 全景文档

三、团队协作方式

桌面端（你当前的使用方式）

桌面 App 是单会话模式，你在聊天框中输入消息召唤角色。每次 @角色名 会启动一个子任务，执行完返回结果给你：

# 你写一条消息，@ 你要的角色 + 需求
@producer 写一个好友系统的功能规格，参考 docs/planning/specs/ 下的模板

# 策划执行完返回，你审核通过后继续
@backend-dev 按 docs/planning/handoffs/v0.5.3.json 实现后端

# 后端完成后
@frontend-dev 按 docs/planning/prompts/v0.5.3-frontend-dev.prompt.md 实现前端

核心逻辑：你始终在同一个对话里，按 策划 → 后端 → 前端 → 验收 → 结案 的顺序，依次 @角色名 交代工作。每个角色完成后退回控制权给你。

终端多角色（备选）

如果以后切换到终端使用，可以开多个窗口，每个 Tab 切换锁定一个角色：

# 终端 1：项目经理
opencode  →  Tab  build

# 终端 2：策划
opencode  →  Tab  @producer

# 终端 3：前端开发
opencode  →  Tab  @frontend-dev

# 终端 4：后端开发
opencode  →  Tab  @backend-dev

全流程编排（进阶）

一条指令让主 Agent 依次调度整个 pipeline，适合需求已确认的版本开发：

五、Spec 状态流转

草案→
评审中→
已确认→
已实现→

六、命令速查

命令执行者作用
npm run planning:handoff -- vX.Y.Z@producer登记计划表 + 生成分角色 prompt + 创建 manifest
npm run planning:status -- vX.Y.Z任何人查看版本开发状态
npm run planning:verify -- vX.Y.Z开发 Agent运行自动化验收脚本
npm run planning:accept -- vX.Y.Z项目经理标已实现 + 更新计划表 + 输出 CHANGELOG
npm run planning:close -- vX.Y.Z@producer策划结案，更新文档
npm run planning:export任何人仅重建 xlsx 计划表
npm run verify:a0开发 Agent执行具体功能验证（按 spec 选用）
npm run dev任何人启动完整开发环境（前端 + 后端）

七、版本发布流程

阶段负责产出
需求策划你 → @producerspecs/ 文档（已确认）
Handoff@producerhandoffs/vX.Y.Z.json + prompts/ + 计划表
开发实现@frontend-dev / @backend-dev源码变更
验证@frontend-dev / @backend-devverify 脚本通过
验收你（项目经理）accept → CHANGELOG 草稿
结案@producerCHANGELOG / README / 全景文档同步

也可将大版本拆成 后端专项 和 前端专项 两个独立 handoff，各自走完整流程。
